# EPUB 编辑与制作能力 · 可行性分析与实施计划

> 日期：2026-10-29 ｜ 状态：E1 已落地，E2–E5 待实施
> **2026-10-30 路线修订**：用户明确否决「独立编辑器主界面」，改为**阅读器内嵌侧滑编辑面板**，编辑能力由阅读器串联触发（详见 §4.3）。
> 关联：`../plans/00-项目计划书`、`../../memory/appendices/A01`（许可边界）、`A04`（功能范围）、`A07`（第 82–90 条 EPUB 合规经验）

## 0. 结论

**可行，且底座比预想的好。** 我们已经有 EPUB 写出、书库、封面、revisions 快照、第三方校验经验，缺的是「解包读取 + 结构编辑 + 双视图 + 内置校验」四块。

按 2026-10-29 拍板的三项要求（见 §0.1），路线调整为**阅读器内嵌编辑面板 + 分期补齐能力**，分五期落地：

| 期 | 目标 | 一句话验收 |
|---|---|---|
| **E1** | 打开书库/磁盘 EPUB → 解包 → 文件树 + 源码编辑 → 保存/另存 + 内置 epubcheck | 改一个 xhtml 导出后 `0 errors`，且只有目标条目字节变化 |
| **E2** | 元数据 / 封面 / 语言 / 贡献者角色表单化 | 改标题作者封面，第三方阅读器显示正确，`dcterms:modified` 自动更新 |
| **E3** | 目录树编辑（nav + ncx 双写）、章节增删改名排序、spine 同步 | 目录改完无 `NAV-011`，点击目录能跳到对应章节 |
| **E4** | 双视图：实时预览 + 块级所见即所得（含内联格式工具条） | 改 30 个段落，未触碰段落字节不变，导出 `0 errors`、预览与成品一致 |
| **E5** | 制作流水线：新建空白书 / TXT-MD-HTML 导入 / 样式预设 / 导出 | 从零做一本 3 章的书，全程不碰外部工具 |

**三个主要风险**：① 所见即所得的 XHTML 往返保真（用「块级回写」化解，见 §4.3.1）；② 内置 epubcheck 的 JRE 体积与分发（见 §4.6）；③ 编辑后 CFI 进度失效。

**许可红线**：Calibre、Sigil 均为 GPL，只能读交互与流程，**一行代码都不能复制**；5s6 那个「中文绿色版」来源与授权不明，只做功能参照，不下载、不打包、不逆向。EPUBCheck 本身是 **BSD-3**，可随包分发（已核对本地 `LICENSE.txt`）。

### 0.1 已拍板的决策（2026-10-29）

| 项 | 决策 | 对方案的影响 |
|---|---|---|
| 编辑形态 | **源码 + 所见即所得，两者都要** | 需要「块级结构化编辑 + 原文保真回写」，不能整篇重排 DOM（§4.3.1） |
| 校验 | **必须内置开箱即用的完整 epubcheck** | 随包分发 JRE + epubcheck，启动即用，不依赖本机 Java（§4.6） |
| 编辑范围 | **书库内 + 任意磁盘 EPUB** | 增加外部工程工作区、另存/入库两条路径（§4.1） |

## 1. 参考软件能力拆解

### 1.1 Calibre ——「编辑图书」（Edit book）

定位：把 EPUB 当**一个工程**来改，功能最全，也是最重的参考。

| 能力 | 说明 | 对我们的价值 |
|---|---|---|
| 文件浏览器 | 按 文本 / 样式 / 图片 / 字体 / 其他 分组，显示在 manifest 中的角色 | ★★★ 直接照抄信息架构（不是代码） |
| 代码编辑器 | 语法高亮、行号、自动补全、跨文件搜索替换（支持正则） | ★★★ 首期必须有 |
| 实时预览 | 分栏预览，编辑即刷新 | ★★★ 首期必须有 |
| 检查图书 | 内置检查 + 可选调用 epubcheck | ★★★ 见 §4.6 |
| 元数据编辑 | 标题/作者/系列/标签/语言/标识符/封面 | ★★★ E2 |
| 目录编辑 | 可视树形编辑，同时写 nav 与 NCX | ★★★ E3 |
| 报告 | 未使用文件、超大文件、断链、重复 id | ★★ E3 顺带做 |
| 插件/批量 | 大量转换与批处理 | ☆ 不做 |

结论：Calibre 的**信息架构**（文件树 + 编辑 + 预览 + 检查）就是我们要抄的"形"，实现全部自写。

### 1.2 Sigil（+ txt 导入插件）

定位：专注 EPUB 2/3 的**双模编辑器**，比 Calibre 轻、比中文小工具专业。

| 能力 | 说明 | 对我们的价值 |
|---|---|---|
| EPUB 2 / EPUB 3 双模 | 同一本书可在两种规范间切换 | ★★ 只支持 EPUB 3，EPUB 2 只做兼容读取 |
| Book View / Code View | 所见即所得 + 源码双视图 | ★★★ 首期两者都做，但 Book View 限定为块级（§4.3.1） |
| 目录编辑器 | 生成/编辑 TOC，自动同步 nav 与 ncx | ★★★ E3 |
| 元数据编辑器 | 含 contributor + role（`marc:relators`） | ★★★ E2（正好覆盖我们踩过的 `dc:translator` 坑） |
| 跨文件查找替换 | 正则、范围限定 | ★★★ E1 |
| 校验 | FlightCrew / epubcheck | ★★★ 直接内置 epubcheck（BSD-3，可分发） |
| 插件系统（含 txt import） | 插件可注册导入器、输出器、编辑操作 | ★ 我们不做插件运行时，改做"导入规则预设" |
| Clips / 拼写检查 | 片段库、拼写 | ☆ 不做 |

结论：Sigil 的**编辑手感**（Code View + 目录树 + 元数据表单）是目标形态；插件体系成本高、收益低，用"预设规则"替代。

### 1.3 「EPUB 电子书编辑器 v3.4.0 中文绿色版」

只能按公开页面描述做功能观察（来源不明，不下载）：

- 面向"做书"而非"改书"：封面/书名/作者/简介表单 → 章节列表（粘贴或导入 TXT）→ 一键生成。
- 强项是**中文用户的心智模型**：所有字段中文化、章节列表可视化、模板化。
- 弱项：无源码视图、无 manifest 级控制、无合规校验、无法处理已有 EPUB 的复杂结构；"绿色版"通常还带捆绑风险。

结论：**只借"做书向导"的产品语言**（E4 的中文化表单向导），不作为技术参照。

### 1.4 三者的共性 = 我们的功能基线

```
打开/新建 → 结构（manifest/spine）→ 内容（xhtml/css/图片）→ 元数据 → 目录 → 预览 → 校验 → 导出
```

任何一款都绕不开这条链；差别只在「哪些环节可视化」。我们按这条链拆期即可。

**关键缺口（代码层）**：

1. Rust 端**没有任何 ZIP 读取能力**，依赖里没有 `zip` crate → 无法解包。
2. 现有打包器**只能 store**（不压缩），做编辑器时若沿用，产物会比原书大 2–3 倍（合法但难看）。
3. `epub-writer.ts` 是**单向生成器**：硬编码 `OEBPS/` 布局、只认 title/author/language，不能读回、不能改任意路径。
4. 没有 XHTML/OPF 的**解析模型**，只有模板字符串拼接。
5. 没有"工作副本"概念，所有编辑都直接对着书库 `source.epub`。

## 4. 技术方案

### 4.1 数据模型：工作副本（edit workspace）

**书库内书籍**（可回写）：

```
library/<id>/
  meta.json          # 原有
  source.epub        # 原有（编辑前的原件保留）
  cover.jpg          # 原有
  edit/              # 新增：解包后的工作副本
    META-INF/
    OEBPS/...
    _index.json      # 条目清单：path / mediaType / id / role / size / crc
  revisions/         # 复用：每次保存前的 source.epub 快照
```

**任意磁盘 EPUB**（不自动污染书库）：

```
<应用数据>/edit-projects/<uuid>/
  origin.json        # 原始路径、大小、修改时间、只读标记
  edit/              # 同上解包结构
  revisions/         # 自己的快照
```

- 外部工程保存 = 写回**原路径**（先备份到 revisions）；也可「另存为」到任意目录，或「存入书库」走现有 `import_book`。
- 外部文件只读 / 无写权限时，自动降级为「只能另存为」，并给中文提示。
- 打开外部文件前做安全校验：拒绝 `META-INF/encryption.xml`（DRM）、拒绝路径穿越条目、限制条目数（≤20000）与解压总字节（≤2GB），防 ZIP 炸弹。

**通用规则**：

- **第一次进入编辑器**才解包，之后直接读 `edit/`，不反复解压。
- 保存 = 从 `edit/` 重新打包，**先写 `revisions/<时间戳>.source`**（复用现有快照机制），再原子替换。
- 放弃编辑 = 删工作副本，原件不动。
- 原件的未知条目（字体、加密清单、iTunes 元数据）**原样保留**，不重建 manifest。

### 4.2 ZIP 层（Rust）

- 依赖：`zip`（MIT）+ `quick-xml`（MIT）。
- 读：`ZipArchive::by_index` → 按 `_index.json` 顺序解包。
- 写：`mimetype` 首项 `Stored`，其余 `Deflated(6)`；保留 `last_modified_time` 与 `unix_mode`。
- 打包后自检：条目数、解压总字节、首项名与压缩方法，三项必须与工作副本一致（`A07` 第 88 条的做法）。

### 4.3 界面形态：阅读器内嵌侧滑编辑面板（2026-10-30 修订）

> 原方案是独立「编辑工作台」主界面，用户明确否决：**不从阅读器抽离出独立编辑器**。编辑必须由「已打开的阅读器」串联触发，保持"读书时随手改"的连续性；不再新增第三种主界面。

```
┌─────────────────────────────────┬──────────────────────────┐
│ 阅读器（原样保留，不被替换）     │ 编辑侧滑面板             │
│                                 │ ├ 文件树（可点、可滚）    │
│                                 │ ├ 编辑区（源码 / 后续预览）│
│                                 │ └ epubcheck 结果          │
└─────────────────────────────────┴──────────────────────────┘
```

- **入口三处，全部先打开书再展开面板**：阅读器顶栏 ✎、书架右键「编辑 EPUB」、书架悬浮按钮；不新开页面、不替换阅读器。
- 面板 `position:absolute` 从右侧滑出，宽度 `min(760px, 94%)`，关闭即回到阅读；阅读器仍在其后。
- 面板内部三段：文件树（按角色分组、可滚动、可点击选中）/ 编辑区（E1 为源码 textarea，E4 再加预览与可视）/ 检查结果（epubcheck，按需显示）。
- 工具条：写回当前文件（Ctrl+S）、保存并重打包（覆盖原件 + revision 快照）、**另存为**（默认落 `final export`，可另选任意磁盘位置）、epubcheck。
- 后续能力以「面板内标签页/分栏」扩展：E2 元数据、E3 目录、E4 源码+预览并排；样式文件与 OPF 只在源码视图编辑（避免可视化误伤 CSS/结构）。

### 4.3.1 块级所见即所得：原文保真回写（核心设计）

不做「整篇 DOM 重排」，而是把章节拆成**块**，只回写被改动的块：

1. **建立块坐标**：Rust 用 `quick-xml` 的 `buffer_position()` 扫描章节，产出每个块元素（`p` / `h1`–`h6` / `blockquote` / `li` / `figure` / `div.gallery-item`）的**字节区间 + 标签名 + 属性原文**，写入 `_blocks.json`。
2. **可视化渲染**：前端用 `DOMParser` 生成一份用于显示的 DOM，套上章节自身的 CSS，只给块元素加 `contenteditable`（不给 `body`），并记录块序号。
3. **只提交改动块**：保存时对比块文本/内联 HTML，只上传 `{块序号, 新 innerHTML}`。
4. **Rust 从后往前替换**：按字节区间倒序拼接，未改动块**逐字节保留**（属性、空行、自闭合写法、实体都不动）。
5. **内联白名单**：仅允许 `em/strong/i/b/a/span/br/img`，属性仅 `href/title/src/alt/class`；其余标签一律剥离并提示；`XMLSerializer` 输出后再做 XML 合法性校验（`&`、`<`、空元素自闭合）。
6. **保存前回归**：块回写后必须通过 L1/L2 检查；前端再 diff 一次，确认改动块数量与提交数一致。

**为什么这样能控制风险**：Sigil 的 Book View 之所以容易改坏书，是因为整篇序列化会丢未知属性；块级回写把风险限定在「用户真正动过的那几段」，其余 99% 内容不经过序列化。

**可视化视图的边界**（明确告知用户）：图片替换、样式表、manifest/spine、目录结构必须回源码视图或专用面板操作；可视视图只负责正文与标题的内联排版。

### 4.4 目录一致性（nav + NCX 双写）

- 单一数据源：内存中的树（`{label, href, children}`）。
- 保存时同时生成 `nav.xhtml` 的 `<ol>` 与 `toc.ncx` 的 `<navPoint>`，`playOrder` 按先序重排。
- 硬规则（`A07` 第 83/86/87 条）：
  - NCX 不带外部 DOCTYPE；
  - 目录顺序必须与 spine 一致，否则 `NAV-011`；
  - landmarks 不得指向非 spine 项（如 `nav.xhtml` 自身）。

### 4.5 预览

- 首选：复用 `foliate-view`，把**单个 xhtml** 作为"临时书"渲染（不重载整本）。
- 次选：`<iframe srcdoc>` + 注入 `<base href="file:///.../edit/">`，样式与图片相对路径自然生效。
- 编辑防抖 300ms 刷新；切换文件立即刷新。

### 4.6 校验（三层）

| 层 | 内容 | 依赖 |
|---|---|---|
| L1 结构自检 | mimetype 首项/STORED、container 指向存在、OPF 可解析、spine 引用都在 manifest | 内置，必过 |
| L2 规则检查 | 我们踩过的 10 类：OPF-073 / OPF-029 / PKG-021 / RSC-011 / RSC-005 / NAV-011 / 断链 / 未使用文件 / 重复 id / 非法控制字符 | 内置 |
| L3 完整校验 | epubcheck 4.2.6（内置，开箱即用） | 内置 JRE |

**内置方案（拍板：必须开箱即用）**

```
app/src-tauri/resources/epubcheck/
  epubcheck.jar          # 1.3 MB
  lib/                   # 依赖 jar 约 1.5 MB
  LICENSE.txt            # BSD-3（已核对）
  THIRD-PARTY.txt
  runtime/               # 精简 JRE（jlink 生成）
```

- **运行时**：用本机已装的 **Microsoft OpenJDK 21**（`D:\Program Files\jdk-21`，含 `jlink`）生成精简镜像，模块 `java.base, java.xml, java.desktop, java.logging, jdk.zipfs`（`java.desktop` 不能省，epubcheck 用 ImageIO 读图片尺寸）。**已实测**：解包 46.1 MB / 压缩 31.0 MB，epubcheck 在其上跑通（详见 `02-内置运行时与本地引擎-可行性分析.md` §1）。
- **分发**：JRE 与 jar 只在构建时从 `_tools/` 拷入 `resources/`，**不进 git**（`.gitignore`），由打包脚本保证存在；缺失时构建失败并给中文提示，避免出"假内置"包。
- **调用**：Rust `Command` 启 `runtime/bin/java.exe`，加 `CREATE_NO_WINDOW`（不闪黑框），带超时（60s）与取消；优先用 `--json` 拿结构化结果，不支持则解析输出文本，统一映射成中文条目。
- **回退链**：内置 runtime → 设置里配置的系统 Java 全路径 → L3 不可用（明确说明原因，不静默失败）。这条链也顺便绕开本机 Oracle java8path shim 崩溃（`A07` 第 82 条）。
- **许可**：OpenJDK/Temurin 为 GPLv2 + Classpath Exception，允许随包分发，需附 LICENSE/NOTICE；EPUBCheck 为 BSD-3，允许分发。两者都不影响本项目 MIT。
- **可升级**：日后如需 EPUB 3.3 支持，可换成 epubcheck 5.x（需 Java 11+，现有 runtime 已满足），只替换 jar 与 lib。

### 4.7 图片与媒体

- 写入前按**魔数**判定真实类型（`A07` 第 84 条），与扩展名/OPF 声明不一致时中文告警，并给「转换为 JPEG/PNG」按钮。
- 图片解码/转码用浏览器 Canvas（零依赖），不引入图像库。
- 封面替换沿用现有 `save_cover` 流程，但同步进 manifest + `properties="cover-image"`。

### 4.8 数据安全

- 写前快照（revisions），保留最近 N 份（默认 10）。
- 原子替换（临时文件 + 重命名），失败不破坏原件。
- 编辑期间禁止"删除书籍"。
- 保存后更新 `meta.json` 的 `byteLen`（`A07` 第 89 条），并提示"进度可能需重新定位"。

## 5. 分期计划与验收标准

### E1 · 打开、编辑与内置校验（核心闭环）

**做**：解包、`_index.json`、文件树（可点击/可滚动）、内嵌侧滑面板、源码编辑（E1 用 textarea；CodeMirror 语法高亮列为后续增强）、保存/另存（默认落 `final export`）/存入书库、**内置 epubcheck（L1–L3）**、revision 快照、外部磁盘 EPUB 工程、安全校验。

**当前进度（2026-10-30）**：
- 已上线：解包 / 文件树 / 源码编辑 / 写回当前文件 / 重打包（含 revision）/ 另存为 / epubcheck 入口 / 阅读器内嵌面板（三入口串联）。
- 待补：跨文件查找替换、CodeMirror 语法高亮、存入书库按钮、无 Java 干净环境实测、只读降级实测。

**验收**：
1. 书库 6 本 + 任意磁盘 EPUB 都能打开，文件树条目数与实际条目数一致（含图片/样式）。
2. 改任一 xhtml 的正文一段 → 保存 → **内置** epubcheck 输出 `0 fatals / 0 errors`。
3. 与原件逐条 diff：只有被编辑的条目字节变化，其余 CRC 不变（`mimetype` 仍首项 STORED）。
4. 在**没有安装 Java 的干净环境**（新建 Windows 用户或虚拟机）里，检查功能照常可用（证明 JRE 真的内置）。
5. 只读文件自动降级为「另存为」；DRM（`META-INF/encryption.xml`）、路径穿越、ZIP 炸弹被拒绝并给中文原因。
6. 关闭再打开，未保存改动有明确提示，不静默丢失。

### E2 · 元数据与封面

**做**：OPF 表单（标题/副标题/作者/译者/出版社/语言/日期/标识符/系列/标签/简介）、封面替换、`dcterms:modified` 自动更新、contributor role。

**验收**：
1. 改标题/作者/语言保存后，Thorium 与 Calibre 阅读器显示一致。
2. 填"译者"生成 `dc:contributor` + `role=trl`，检查报告不再出现 `RSC-005`。
3. 换封面后 OPF 的 `cover-image` 属性指向新文件，旧文件从 manifest 移除。
4. `dcterms:modified` 为 `YYYY-MM-DDTHH:MM:SSZ`（无毫秒）。

### E3 · 目录与章节结构

**做**：目录树编辑器（增删改/拖拽排序/嵌套）、章节重命名与移动、spine 同步、链接检查、未使用文件报告。

**验收**：
1. 目录增删后 nav 与 ncx 条目数量、层级、顺序完全一致。
2. 目录顺序与 spine 顺序一致，`NAV-011` 为 0。
3. 改章节文件名后，OPF、spine、nav、ncx、书内相对链接全部同步，无断链。
4. 扫描全书报告能列出未使用图片与重复 id。

### E4 · 双视图与块级所见即所得

**做**：当前文件即时预览、可视编辑（块级 `contenteditable`）、内联格式工具条（粗体/斜体/链接/标题级别）、块坐标与回写、未改动块逐字节保留。

**验收**：
1. 预览与导出成品一致（同章段落在同字号/缩进下断行位置一致，允许 ±1 行）。
2. 随机改 30 个段落（含中英混排、脚注链接段落）→ 保存 → 未触碰段落**逐字节一致**，导出 `0 errors`。
3. 从 Word 粘贴带内联样式的文本，白名单剥离后仍通过 XML 合法性检查。
4. 可视视图里删段落、改标题级别，源码视图立即同步正确；反向切换无丢失。
5. 可视视图不暴露 CSS/manifest 操作入口，避免误伤结构。

### E5 · 制作流水线（从零做书）

**做**："新建书"向导（书名/作者/语言/封面/样式预设）→ 章节导入（TXT 复用现有解析；MD/HTML 新解析）→ 章节列表编辑 → 生成 → 直接进入编辑器继续改 → 导出/存入书库。

**验收**：
1. 从空白新建 3 章书，全程不借助外部工具，产物 `epubcheck 0 errors`。
2. TXT 导入沿用现有章节识别，预览章节 = 产物章节（不二次解析）。
3. 样式预设至少 3 套（中文正文/英文小说/极简），可在编辑器里改。
4. 生成后自动进入 E1 工作台，改动可保存并另存到任意目录。

### 可选（不进本期）

- 外挂 Sigil / Calibre 打开（"用外部编辑器打开"菜单项，零成本，随时可加）。
- 批处理：批量改元数据、批量转封面。
- 字体嵌入与 CSS 变量面板。

## 7. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 原书结构不规范（手工生成、路径各异） | 编辑器打不开或预览错位 | 以 container.xml 为唯一入口；解包失败给中文诊断；先支持"能读就能编" |
| **WYSIWYG 破坏 XHTML** | 保存后排版崩、属性丢失 | **块级回写**（§4.3.1）：只替换用户改动块的字节区间，未改块逐字节保留；白名单过滤 + XML 合法性校验 |
| 可视视图与源码视图漂移 | 两处内容不一致 | 单一文档模型（源码为准），可视视图只做块内联编辑，切换时重新解析并比对 |
| 目录与 spine 不同步 | `NAV-011`、跳转错章 | 树形单一数据源，双写 + 保存前自检 |
| **内置 JRE 体积/启动成本** | 安装包 +30 MB，检查慢 1–2 秒 | jlink 只留必要模块（`java.base/java.xml/java.desktop/java.logging`）；检查异步 + 进度提示；允许设置里切换系统 Java |
| **jlink 模块缺漏** | 内置 runtime 一到图片校验就抛 `NoClassDefFoundError` | 用 3 本含图片的书做最小模块集回归；模块集写进构建脚本，不靠手工记忆 |
| 干净环境验证不足 | 本机有 Java，测不出"假内置" | E1 验收必须在新用户/虚拟机里跑一次（§5 E1-4） |
| 编辑导致进度失效 | 用户回到错页 | 按"章节路径 + 章内比例"重算；失败回退章首并提示 |
| 外部文件安全 | ZIP 炸弹、路径穿越、DRM | 条目数/总字节上限、拒绝 `..`、拒绝 encryption.xml、只读降级 |
| 内存/性能 | 大书卡顿 | 工作副本落盘，单文件按需读；打包在 Rust 端流式进行 |
| 许可污染 | MIT 项目被迫 GPL | 只读交互与流程；不复制任何 Calibre/Sigil 代码；第三方二进制只分发 BSD-3 的 epubcheck 与 GPLv2+CE 的 OpenJDK 运行时（附许可） |
