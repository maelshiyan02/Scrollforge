> 关联：[01-EPUB编辑与制作能力-可行性分析](./01-EPUB编辑与制作能力-可行性分析.md) ｜ `../../memory/appendices/A01`（许可边界）、`A02`（环境事实）、`A07`（第 82–93 条）

## 0. 结论

**三条都可行，但要分层，不能"一个包全塞进去"。**

| 能力 | 可行性 | 标配体积增量 | 许可 | 分期 |
|---|---|---|---|---|
| 内置 JRE（跑 epubcheck） | ✅ **已实测跑通** | **+46.1 MB 解包 / +31.0 MB 安装包** | GPLv2+CE，可分发 | T0 |
| 本地翻译 | ✅ 小模型可用；整本书用 LLM 偏慢 | Argos 级 +100 MB／LLM 级 +1.1 GB | 见 §3.2（有 NC 坑） | T2 |
| 本地朗读 | ✅ 但**不能依赖系统 TTS**（本机一台音色都没有） | Piper 中文音色 +63 MB | MIT | T1 |
| 小型 AI（改写/术语/摘要） | ✅ 本机可跑 1.5B–7B；弱机只能 0.5B | +400 MB 起 | Apache-2.0 / MIT | T3 |

**核心判断**：内置 JRE 是"正确但昂贵"的必选项；本地 AI 是"可选但值得"的增值项。建议做成**一个主安装包（阅读+编辑+内置校验）**加**多个可选模型包**，而不是发布一个 2 GB 的巨无霸——否则每一次小版本更新都要重下模型。

**本机硬件（实测）**：i5-14600KF（14C/20T）、31.8 GB RAM、RTX 5070（12 GB）、Win11 26100、D 盘剩 699 GB。这台机器能跑 7B，但**不能假设用户的电脑也这样**，所以基线必须按 4 核 / 8 GB / 无独显设计。

### 0.1 已拍板（2026-10-29）

| 项 | 决策 | 影响 |
|---|---|---|
| 安装包 | **统一主包**，不做 Lite | 用户零配置；下载从 8 MB 变大约 110 MB（见下方冲突说明） |
| 朗读 | **内置一个中文音色**（Piper `zh_CN-huayan-medium`，约 63 MB） | 开箱即读，不依赖系统 TTS |
| AI 模型 | **完全按需下载** | 主包不背 1 GB；弱机不被拖累；需做能力自检页 |
| 翻译语向 | **英→中 + 韩→中** | 两套模型约 220 MB（按需下载）；韩→中需单独验证质量 |

> **必须指出的体积冲突**：50 MB 是"JRE + epubcheck"的账，**不含音色**。内置音色后主包实际约 **110–125 MB**（程序 ~10 + runtime 31 + epubcheck ~11 + Piper ~5 + 音色 55–63）。如果 50 MB 是硬上限，音色就必须改成"首次朗读时下载"——两者不能同时成立。默认按"内置中文音色 → 主包约 110 MB"记录，等你确认。

## 1. 内置 JRE：从"计划"变成"已验证"

### 1.1 实测数据（今天刚跑）

```powershell
jlink --add-modules java.base,java.xml,java.desktop,java.logging,jdk.zipfs `
      --strip-debug --no-man-pages --no-header-files --compress=2 --output jre21-epubcheck
```

| 指标 | 实测值 |
|---|---|
| 裁剪耗时 | 3.7 秒 |
| 解包体积 | **46.1 MB** |
| 整目录 zip（Optimal） | **31.0 MB** ← 安装包的真实增量 |
| 启动验证 | `java -version` → OpenJDK 21.0.13 LTS |
| epubcheck 实跑 | 书库 4.6 MB 图文书 + 交付书各一遍：`No errors or warnings detected` |
| epubcheck 本体 | 12.85 MB（`epubcheck.jar` 1.3 MB + `lib/` 20 个 jar 共 11.55 MB） |

**合计：内置校验的总增量 ≈ 43 MB（压缩后）**，产物已在本机 `_tools/jre21-epubcheck/`，可直接复用。

### 1.2 模块集为什么是这五个

| 模块 | 为什么不能省 |
|---|---|
| `java.base` | 一切的基础（ZIP、IO、字符集） |
| `java.xml` | epubcheck 解析 OPF/XHTML/NCX（SAX/DOM、XPath） |
| `java.desktop` | **ImageIO 读图片尺寸**，检查"图片声明的宽高与真实不符"；漏了会在图片校验时 `NoClassDefFoundError` |
| `java.logging` | epubcheck 的日志框架依赖 |
| `jdk.zipfs` | 部分实现会走 `FileSystems.newFileSystem(zip)` |

> 实测警示：`--compress=2` 在 JDK 21 已标记为过时，会打印中文警告但**功能正常**；新脚本用 `--compress=zip-6`（等价），避免以后升级 JDK 时行为变化。

### 1.3 Tauri 集成方式

```jsonc
// tauri.conf.json
"bundle": {
  "resources": {
    "resources/epubcheck/": "epubcheck/",
    "resources/runtime/": "runtime/"
  }
}
```

- 运行时路径用 Tauri 的 `resource_dir()` 解析，**不写死安装路径**，也不依赖系统 `JAVA_HOME`/PATH。
- 调用：`Command::new(runtime/bin/java.exe)` + `.arg("-jar").arg(epubcheck.jar).arg(book)`，加 `CREATE_NO_WINDOW`（不闪黑框）+ 60s 超时 + 可取消。
- 输出解析：优先 `--json`，失败回落文本正则，统一映射成中文条目。
- **启动开销实测约 1–2 秒**（JVM 冷启动），检查必须异步 + 进度提示，不能卡界面。

### 1.4 许可与合规

- OpenJDK（Microsoft Build / Temurin）＝ **GPLv2 + Classpath Exception**，允许随商业/闭源程序分发；需附 `LICENSE` + `NOTICE`。
- EPUBCheck ＝ **BSD-3**（`LICENSE.txt` 已核对），允许分发；需保留版权声明。
- 两者都**不影响本项目 MIT**。
- 要写进 `THIRD-PARTY.md`，并在「关于」页列出。

### 1.5 需要注意的坑（都会在 E1 前遇到）

1. **杀软误报**：未签名的 `java.exe` + `jli.dll` 放进资源目录，容易被国产杀软拦；缓解＝安装包签名（哪怕自签名）+ 避免把 runtime 解到 `%TEMP%`。
2. **路径含空格/中文**：`Command` 参数必须逐个传，不能拼成一整条字符串。
3. **`%JAVA_HOME%` 残留依赖**：epubcheck 的 `epubcheck.jar` 启动脚本会读 `JAVA_HOME`，我们直接调 `java.exe -jar`，不经过脚本，因此安全。
4. **版本锁定**：runtime 与 epubcheck 版本必须配对记录（`runtime/build-info.txt`：JDK 版本、jlink 参数、模块集），否则以后排查"为什么别人的机器报错"会毫无线索。
5. **不能骗自己**：必须在一台**没装 Java 的机器/新用户**上验证一次，否则只是"本机假内置"（`A07` 第 82 条教训）。

### 1.6 体积换来的收益

- 用户零配置：不需要装 Java、不需要配 PATH、不受 Oracle shim 崩溃影响（`A07` 第 82 条）。
- 校验结果可复现：所有人跑同一版本 JDK + 同一版本 epubcheck，错误码一致。
- 代价：安装包 8 MB → 约 51 MB；每次升级 epubcheck 需重发安装包（可接受，校验器升级频率低）。

## 2. 本地引擎的通用原则

### 2.1 三类能力，三种引擎形态

| 形态 | 例子 | 体积 | 适用 |
|---|---|---|---|
| **系统能力** | Windows SAPI / OneCore TTS、WinRT | 0 | 有就用的兜底（**本机实测没有**，见 §4.1） |
| **专用小模型** | Piper（TTS）、Argos/CT2（翻译）、Whisper（识别） | 20–300 MB | 标配、离线、可预测 |
| **通用小 LLM** | Qwen2.5-1.5B/3B、Phi-4-mini | 0.4–2.4 GB | 可选增强、质量优先 |

### 2.2 三条硬原则

1. **引擎跑在 sidecar 子进程里**，不在 Rust 主进程内加载模型：模型崩了不拖垮阅读器，也便于单独限内存、单独杀进程。
2. **模型不进安装包，进"模型库"**：`models/<engine>/<name>/` + `manifest.json`（名称、体积、sha256、许可、来源、语言），支持联网下载与离线包导入，可单独卸载。
3. **能力必须能降级**：没模型 → 功能入口灰显并给中文原因（"未安装翻译模型，点击下载 110 MB"），绝不静默失败。

### 2.3 进程与接口

```
Rust 主进程
 ├─ 子进程: runtime/bin/java.exe  -jar epubcheck.jar      （校验，短任务）
 ├─ 子进程: engines/piper/piper.exe                        （TTS，流式 WAV）
 ├─ 子进程: engines/ct2/translate(.exe)                    （翻译，请求-响应）
 └─ 子进程: engines/llama/llama-server.exe                 （LLM，本地 HTTP + SSE 流式）
```

- 统一用 stdin/stdout JSON Lines 或本地回环 HTTP（仅 `127.0.0.1`，随机端口 + 一次性 token）。
- 长任务（整本翻译、整本朗读）走**队列 + 断点续做**，结果写缓存文件，关闭应用不丢进度。

## 3. 本地翻译

### 3.1 方案对比

| 方案 | 体积 | 质量（英→中） | CPU 速度 | 许可 | 结论 |
|---|---|---|---|---|---|
| **Argos Translate**（CTranslate2 + OPUS-MT） | ~100 MB/对 | 中（直译感强） | 很快（整本几分钟） | 代码 MIT；多数模型 CC-BY-4.0 | ✅ **首选标配** |
| **Bergamot / Marian**（Firefox 翻译） | ~20–40 MB/对 | 中上（欧洲语系强） | 极快 | MPL-2.0 | ⚠️ 中英方向覆盖有限，看模型再说 |
| **OPUS-MT 原始模型 + 自转 CT2** | 与 Argos 同源 | 同上 | 同 | CC-BY-4.0 | 作为补充语种来源 |
| **NLLB-200 distilled 600M** | ~600 MB–1.2 GB | 中上，200 语种 | 中等 | **CC-BY-NC-4.0（禁商用）** | ❌ 不内置，最多用户自装 |
| **Qwen2.5-1.5B-Instruct（Q4）** | ~1.1 GB | **好**（能保留语气/术语） | 慢（10–20 tok/s，整本 3–4 小时） | Apache-2.0 | ✅ **可选"精修"档** |
| **Qwen2.5-3B / Phi-4-mini** | 2.0–2.4 GB | 更好 | 更慢 | Apache-2.0 / MIT | 🟡 有独显再上 |
| 在线 API（DeepL/Google） | 0 | 最好 | 秒级 | 需联网 + 密钥 | ❌ 与"自带环境"目标冲突 |

### 3.2 许可坑（必须先排除）

- **NLLB-200 是 CC-BY-NC**：不能随包分发、不能商用。若用户自行导入不拦，但**绝不内置**。
- **XTTS-v2（Coqui）是 CPML**：非商用，不能内置。
- **Gemma 系列**用的是 Google 自定义条款（非 OSI），分发要额外合规审查 → 不首选。
- Argos 模型多为 CC-BY-4.0，需在「关于」页署名。

### 3.3 推荐路线（两档并存）

```
第一档（标配，离线）：Argos/CT2 英→中，逐段翻译，术语表强制替换
第二档（可选，质量）：Qwen2.5-1.5B-Instruct「译后精修」——只重写生硬段落，不整本重译
```

与现有能力打通（这是我们的独特优势）：

- `paragraphRanges` 已有**段落级绝对行号**，翻译可直接落到"某段 → 译文"，复用锻造台的写回与 revisions 快照（`A07` 第 45–50 条）。
- 译文可存为**双语对照层**（不覆盖原文），阅读器里可切换"原文 / 译文 / 对照"。
- 术语表：`glossary.json`（人名、地名、专有名词），先做**最长匹配强制替换**，成本极低、收益最直观。

### 3.4 速度量级（估算）

| 规模 | Argos/CT2（CPU） | 1.5B LLM（CPU） | 1.5B LLM（RTX 5070） |
|---|---|---|---|
| 单章（3 千字） | 数秒 | 1–2 分钟 | 10–20 秒 |
| 整本（10 万字 / 13 MB） | 3–10 分钟 | 3–4 小时 | 20–40 分钟 |

> 结论：**整本翻译默认走小模型**；LLM 只做"精修/术语统一/疑难句"，否则用户会等到放弃。

## 4. 本地朗读（TTS）

### 4.1 系统 TTS 实测：这台机器一个音色都没有

```
SAPI:    HKLM\SOFTWARE\Microsoft\Speech\Voices\Tokens        → 不存在
OneCore: HKLM\SOFTWARE\Microsoft\Speech_OneCore\Voices\Tokens → 不存在
System.Speech.GetInstalledVoices() → "系统上未安装语音"
```

Win11「专业版」默认不装语音包（需要在"设置 → 语音"里额外下载，且部分系统镜像永久没有）。**所以"零体积靠系统"这条路在移植场景下不可靠**，必须内置音色——这正是用户判断正确的证据。

### 4.2 方案对比

| 方案 | 中文音色体积 | 质量 | CPU 实时性 | 许可 | 结论 |
|---|---|---|---|---|---|
| **Piper**（ONNX，VITS） | 20–63 MB/音色（`zh_CN-huayan-medium` ≈ 63 MB） | 好（自然、稳定） | 10–20× 实时 | **MIT** | ✅ **标配内置 1 音色** |
| Kokoro-82M（ONNX） | 模型 ~90–330 MB + 音色包 | **很好** | 5–10× 实时 | Apache-2.0 | 🟡 可选高质量包 |
| XTTS-v2 | ~1.8 GB | 很好（可克隆音色） | 慢（需 GPU） | **CPML 非商用** | ❌ 不内置 |
| Edge TTS（在线） | 0 | 很好 | 快 | 非官方接口，ToS 灰色 | ❌ 不做默认 |
| Windows SAPI | 0 | 一般 | 即时 | 系统自带 | 🟡 有则作为兜底 |

### 4.3 推荐组合

```
默认：Piper 中文音色（内置，约 63 MB）→ 开箱即读
可选：Piper 英文音色（约 60 MB，英文书用）
可选：Kokoro 高质量包（含中英音色，约 300 MB）
兜底：检测到系统有 SAPI 音色时，允许用户切回系统音色（0 体积）
```

### 4.4 与阅读器结合的关键点

1. **跟读高亮**：朗读进度要能映射回**段落 / 句子**（现有的"按句定位 + rect 换算"逻辑可直接复用，`A07` 第 52–54 条）。
2. **分页联动**：读完当前页自动翻页；用户手动翻页则跳到该页首句继续。
3. **文本规范化**（朗读质量的关键，常被忽略）：数字、日期、英文缩写、多音字、脚注标记、破折号；需要一张可编辑的替换表 + 可选的 LLM 断句。
4. **长任务**：整本朗读生成音频文件（mp3/wav）要明确"是导出有声书还是仅即时朗读"，缓存与断点续做同 §2.3。
5. **资源占用**：Piper 单进程峰值内存约 200–400 MB，必须能在朗读时正常翻页与编辑。

## 5. 小型 AI（LLM）

### 5.1 运行时选择

| 运行时 | 许可 | 优点 | 缺点 |
|---|---|---|---|
| **llama.cpp**（`llama-server` sidecar 或 `llama-cpp-2` crate） | MIT | GGUF 生态最大、CPU/GPU 都能跑、可量化 | 需要自己管进程与端口 |
| **ONNX Runtime**（`ort` crate） | MIT | 与 Piper 共用一套运行时 | LLM 生态弱于 llama.cpp |
| **Ollama** | MIT | 安装简单 | **外部依赖，不能算"自带环境"** → 只作为"检测到就复用"的加分项 |

**推荐**：llama.cpp 作主运行时，`llama-server` 以 sidecar 启动（本机回环 HTTP + SSE 流式），前端按 token 流式渲染。这样"翻译精修 / 改写 / 摘要"共用同一进程，只切 prompt。

### 5.2 模型候选

| 模型 | 量化后体积 | 中文 | 许可 | 适用档位 |
|---|---|---|---|---|
| Qwen2.5-0.5B-Instruct | ~400 MB | 中 | Apache-2.0 | **弱机基线**（4C/8G 可跑） |
| Qwen2.5-1.5B-Instruct | ~1.1 GB | 好 | Apache-2.0 | **推荐主力** |
| Qwen2.5-3B-Instruct | ~2.0 GB | 更好 | Apache-2.0 | 有独显 |
| Qwen3-1.7B | ~1.2 GB | 好（带思考模式） | Apache-2.0 | 可选替代 |
| Phi-4-mini（3.8B） | ~2.4 GB | 中 | MIT | 英文改写强 |
| Gemma 3 1B | ~0.8 GB | 中 | **Gemma 自定义条款** | 需额外合规审查，不首选 |

### 5.3 用途（全部落在已有能力上）

| 用途 | 说明 | 与现有代码的关系 |
|---|---|---|
| 段落改写/润色 | 锻造台"改写"从手工输入变成 AI 建议 | 复用 `applyRewrites` 的行范围写回 |
| 术语统一 | 扫描全书，找同一人名的不同译法 | 复用 `paragraphRanges` |
| 摘要/章节简介 | 生成目录摘要、书籍简介 | 写入 `meta.json` 或 info 页 |
| 翻译精修 | 只重译"低置信度"段落 | 与 §3.3 第二档同一入口 |
| 朗读规范化 | 给 TTS 生成更好的断句与读音提示 | 与 §4.4 第 3 点共用替换表 |
| 编辑辅助 | 检查错别字、标点、重复段 | 编辑器侧栏 |

### 5.4 硬件档位

| 档位 | 代表机器 | 能跑什么 |
|---|---|---|
| 基线 | 4C / 8 GB / 无独显 | Piper TTS、Argos 翻译、0.5B LLM（7–10 tok/s） |
| 主流 | 8C / 16 GB / 核显 | Piper、Argos、1.5B LLM（15–20 tok/s） |
| 本机 | 14C / 32 GB / RTX 5070 12 GB | 7B 级 LLM（GPU 加速 60+ tok/s）、Kokoro、整本精修 |

> 必须给用户一个**「本机能力自检」**页面：检测 CPU 核数、内存、是否有 CUDA/DirectML，推荐"能跑什么档"，避免装了大模型才发现卡死。

## 6. 统一资源架构

```
<安装目录>/
  Scrollforge.exe
  resources/
    runtime/            # jlink JRE（46 MB，随包）
    epubcheck/          # jar + lib（12.85 MB，随包）
    engines/
      piper/            # piper.exe + dll（约 5 MB）
      ct2/              # 翻译引擎（约 10 MB）
      llama/            # llama-server.exe（约 10–30 MB）
  models/               # 可选，独立卸载
    tts/zh_CN-huayan-medium/   63 MB
    translate/en-zh/          110 MB
    llm/qwen2.5-1.5b-instruct-q4/  1.1 GB
  models-manifest.json
```

- 所有可执行文件与模型都带 `sha256`，启动时校验，防止被替换或下坏。
- `models/` 支持"导入离线包"（zip），适配内网/无网用户。
- 卸载：提供"移除模型（保留阅读器）"与"完全卸载"两种。

## 7. 安装包分级（按实测推算，已按拍板调整）

| 包 | 内容 | 体积（估算） |
|---|---|---|
| **主包（已拍板）** | 程序 + jlink runtime + epubcheck + Piper + **1 中文音色** | **约 110–125 MB** |
| 翻译包（按需下载） | Argos 英→中 + 韩→中 | 约 220 MB |
| 朗读增强（按需下载） | 英文音色 / Kokoro 高质量包 | 60 MB / 300 MB |
| AI 精修（按需下载） | Qwen2.5-0.5B / 1.5B / 3B | 400 MB / 1.1 GB / 2.0 GB |
| Lite（备用，不发布） | 无 JRE、无音色（仅规则校验） | 约 15 MB |

> 决策后果：主包从"50 MB 级"变成"110 MB 级"，换来"装上就能读、就能校验"的真·自带环境。翻译与 LLM 全部走应用内下载或离线包，小版本更新只重下主包。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 安装包 +43 MB 被用户抱怨 | 下载/安装意愿下降 | 提供 Lite 档；校验失败时才提示"安装运行时"；说明可离线 |
| 杀软误报内置 java.exe | 安装失败 | 签名安装包；runtime 放安装目录而非临时目录；在白名单文档里说明 |
| 模型许可踩坑（NLLB NC / XTTS CPML / Gemma 条款） | 法律风险 | 只内置 Apache-2.0/MIT/CC-BY；其余仅支持用户自导入并提示 |
| 弱机装大模型卡死 | 体验崩坏 | 能力自检 + 分档推荐 + 内存上限保护 + 可随时终止 |
| LLM 翻译幻觉/漏译 | 内容错误 | 默认不对整本做 LLM 翻译；精修必须"逐段对齐 + 可 diff 回滚" |
| TTS 与分页错位 | 跟读高亮乱跳 | 以"句子"为最小朗读单元，朗读结束再翻页；手动翻页立即重定位 |
| sidecar 端口冲突/僵尸进程 | 功能失效、进程残留 | 随机端口 + token；退出时按 PID 树清理；崩溃自动重启一次 |
| 中文多音字/数字读错 | 听感差 | 可编辑规范化替换表 + 可选 LLM 断句 |
| 模型下载中断/损坏 | 无法使用 | sha256 校验 + 断点续传 + 离线包导入 |

## 10. 已拍板与本轮唯一遗留

**已定**（2026-10-29）：统一主包（不做 Lite）、内置一个中文音色、AI 模型全部按需下载、翻译首批 **英→中 + 韩→中**。

**唯一遗留**：主包体积因内置音色涨到约 110–125 MB（超出原设想的 50 MB）。三种处理方式，等你一句话：

1. 接受 110 MB（推荐：真·开箱即读，用户不用再下第二次）。← 当前默认
2. 主包回到 ~50 MB，音色改为「首次点朗读时下载 63 MB」。
3. 主包 ~50 MB，另发一个「朗读增强版」安装包。

**下一步（等你发话再动手）**：T0 只需把 `_tools/jre21-epubcheck/` 与 `epubcheck-4.2.6/` 接进 Tauri `bundle.resources`，加一个只读的「检查图书」命令 + 中文结果面板——不涉及编辑器主体，风险最低，可以先验证"真内置"在另一台机器上成立。
