# 03 · 护眼三档主题需求调研与色板

> 上级：`../plans/02-护眼三档主题开发计划-20261107.md` ｜ 结论回写：`../../memory/appendices/W00-工作日志索引.md`（W28）
> 调研日期：2026-11-07 ｜ 状态：已定稿（待用户确认后进入实现）

## 0. 结论先行

1. **护眼模式不等于「绿色背景」**，但也并非必须复刻系统的「降蓝光」。业界事实上的做法分两层：
   - **屏幕层**：降色温 / 降蓝光（Windows 夜间模式 2700–4000K、f.lux；macOS Night Shift；显示器低蓝光档位）。这一层属于系统/硬件，软件只能模拟。
   - **内容层**：换一套低亮度、低饱和、低对比的**暖色/绿色纸面 + 深灰（非纯黑）文字**，配合图片降亮。阅读类软件（Kindle、Apple Books、微信读书）都只做内容层。
2. **本项目的护眼档 = 内容层绿色纸面方案**：整窗偏绿、降低明度与饱和度、正文对比度维持在 **WCAG AA（≥4.5:1）**，不把对比度压到看不清；不额外叠加 CSS 全局滤镜（会导致图片与图标失真）。
3. **夜间档不采用纯黑**（`#000` 会在暗环境产生光晕/halation，且和周围黑边形成强边缘），采用「深灰纸面 + 87% 灰白文字」，对比度 ≈10:1，既清晰又不刺眼。
4. **日间档保持现有外观不变**（`#faf9f6` 纸色 + `#2f2b26` 墨色），避免升级后"看起来变了"。
5. 图片与封面：**三档都不反色**；夜间统一轻微降亮（`brightness(.86)`），护眼与日间保持原样。理由见 §3.4。
6. 档位切换：**手动三档 + 持久化**，本轮**不做**跟随系统、定时切换（见 §5 非目标）。

## 1. 调研证据

### 1.1 系统层：夜间模式本质是「色温」而不是「绿色」

- Windows 夜间模式官方说明：减少蓝光，让屏幕呈暖色调，用于夜间助眠。
- 多方资料给出夜间最佳色温 **2700K–4000K**（白天基准 6500K）。蓝光 ≈400–490nm，抑制褪黑素。
- 结论：系统层做的是**黄/暖**，不含绿；并且它作用于整个屏幕（含所有应用），软件无法也不该重复实现。

### 1.2 中文「护眼绿」的实际取值

- Office / Word 自定义页面色的流行做法：豆沙绿 **RGB(199,237,204) = #C7EDCC**（也写作 #CCE8CF），另有一组常见护眼底色：杏仁黄 #FAF9DE、秋叶褐 #FFF2E2、青草绿 #E3EDCD、海天蓝 #DCE2F1、极光灰。
- 这些值共同特征：**明度很高（L≈90%）、饱和度低–中（S≈20–35%）**，因此整屏使用不刺眼；直接把 #C7EDCC 铺满整个软件会偏艳，故本项目在豆沙绿基础上再降饱和、降明度一点，取 **#E8F0E4** 作为纸面，另配 #DCE8D8 外壳 / #F2F7F0 卡片。

### 1.3 阅读类软件的「纸色」方案

| 软件 | 方案 | 取值 |
|---|---|---|
| Kindle | 白 / 羊皮纸(sepia) / 夜间 | sepia 底 `#FDF0D6`~`#E9D8BA`，字 `#634A2E`（暖棕，非纯黑） |
| Apple Books | White / Sepia / Grey / Night | 四档纸色，夜间同样不用纯黑 |
| 微信读书 | 阅读背景 + 夜间模式（多皮肤） | 背景与字体分开设置，夜间为深灰底 |
| Adobe Acrobat | 辅助工具「替换文档颜色」 | 可自选高对比前景/背景组合（含深色组合） |

共性：**纸色是"低饱和暖/中性色"，文字是深灰或暖棕，不追求高对比**；并且**纸色与软件外壳分两套**（书页可换，外壳跟随主题）。

### 1.4 深色模式的工程共识（Material Design）

- 深色主题**不要用纯黑**，基础表面 `#121212` 一类深灰；层级越高表面越亮（elevation overlay）。
- 正文与表面至少 15.8:1 才保证"最高层级表面"上仍满足 AA 4.5:1。
- 强调色在深色下需**降饱和**，保证与正文并排时仍 ≥4.5:1。

### 1.5 对比度标准

- WCAG 2.1 AA：正文 ≥**4.5:1**，大字号 ≥3:1，图标/边框等非文本 ≥3:1；AAA 为 7:1。
- 护眼不等于低对比：新华网等科普明确「护眼模式治标不治本」，黑暗环境下高对比仍会加重调节负担；蓝光滤镜对眼疲劳的证据等级较低（Cochrane 综述：短期几乎无差异）。
- 结论：**护眼档保持 AA 可读，靠降色温、降明度、降纯黑对比来减负，而不是把字变浅**。

### 1.6 图片处理

- Kindle / Apple Books 夜间**不反色图片**，页面整体压暗。
- 浏览器插件 Dark Reader 的反色滤镜模式被官方定位为「兜底方案」，主要问题正是图片与已深色内容被反色；`Inkflip` 进一步说明「照片保持原样、只修白底图表」。
- 结论：阅读器正文图片与封面**三档都不反色**；夜间仅轻微降亮（0.86），避免全屏白图刺眼。

## 2. 三档定义与色板（定稿）

### 2.1 语义分层（CSS 变量）

## 4. 明确不做（避免过度设计）

1. **不做跟随系统 / 定时切换 / 日出日落**：本轮只做手动三档 + 持久化；系统层降蓝光由 Windows 夜间模式负责。
2. **不做全局 CSS 反色/滤镜**（`invert`/`hue-rotate`）：会使图片、图标、语法色失真，且 GPU 开销大。
3. **不反色书内图片与封面**，只做夜间轻微降亮。
4. **不改书籍自身的排版/字体/字号体系**，仅在正文注入颜色与图片降亮。
5. **不做 PDF/CBZ 页面内容反色**（固定版式按原样渲染），仅把周围舞台变暗。
6. **不做高亮/标注 6 色的换色**（用户已选定颜色，保持语义一致）。

## 5. 风险与已知边界

| 风险 | 处置 |
|---|---|
| 532 处硬编码色值 + 125 处 rgba 漏改，出现局部白底 | 按"高频色→令牌"映射批量替换 + 逐区域截图核查清单 |
| foliate 分页器背景取自 iframe 文档背景 | 通过注入 `html/body` 背景，分页器 `#background` 会自动跟随（已在 `paginator.js#getBackground` 确认） |
| 自定义颜色的 EPUB（书内自带背景/文字色） | 注入时用 `!important` 覆盖 html/body；书内元素自带色不强改 |
| 图片、图表在夜间过亮 | 夜间统一 `img{filter:brightness(.86)}`，可选关闭（不纳入本轮） |
| 固定版式 PDF/CBZ 白页 | 属内容层，保持原样；仅舞台变暗，验收时确认"不刺眼即可" |
| EPUB 编辑页由"常驻深色"变"随主题" | 需单独一套 `--ed-*` 令牌，逐档截图核对 |
| 原生控件（滚动条、下拉、checkbox）在夜间仍为浅色 | 夜间加 `color-scheme: dark` |
