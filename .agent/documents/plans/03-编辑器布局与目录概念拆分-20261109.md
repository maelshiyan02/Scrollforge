## 一、实机复现结果（CDP 后台点击 + 截图，正式包临时开 9222）

复现用书：《轮回第7次的反派千金 第1卷》；窗口 1024×698，`.stage` 高度 720px。

| 现象 | 实测数据 | 结论 |
| --- | --- | --- |
| 阅读→编辑后面板只占上半，下方露出阅读页 | `.edit-panel` 计算样式 `position: relative`，高度 **250.65px / 486px**；`.stage` 720px | 面板没有铺满舞台 |
| 只有「源码视图 + 展开文件树」显示正常 | 源码视图面板高度 **1064px > 720px**，超出部分被 `.app{overflow:hidden}` 裁掉，视觉上铺满 | 巧合，不是正确布局 |
| 文件树无滚动条 | 展开树后面板高度变成 486px（由内容撑开），树 `clientHeight = scrollHeight = 486`，`overflow:auto` 永不触发 | 不是缺滚动条样式，是没有高度约束 |
| 收起「正文」分组后下方显示失效 | 折叠 `<details>` 后，面板高度 **486px → 271.25px**，阅读页重新露出 | 同上，面板高度由内容决定 |
| 目录视图滚轮无效 | `.toc-tree` 为 `clientHeight 403 / scrollHeight 427`（仅溢出 24px）；条目一多，树被内容撑到全高，面板超出舞台，滚轮无处可滚 | 同上 |
| 阅读模式「展开目录」混入前置页 | 条目为：彩页 1 / 彩页 2 / 彩页 3 / 第一章 … / 后记 | 与「章节列表」定位不符 |
| 文件树只有文件名 | `title.xhtml / color01.xhtml / ch_115048.xhtml …` | 看不懂，需要标题映射 |

运行时把 `.edit-panel` 临时改成 `position:absolute; inset:0` 后复测：

- 面板高度 720px = 舞台高度，阅读页不再露出；
- 视口压到 420px 高时，树 `clientHeight 320 / scrollHeight 486`，滚轮可滚到 `scrollTop 166`；
- 目录视图的树恢复为可滚动容器。

→ **四个现象同一个根因**，不是四个独立 bug。

## 二、根因

### 根因 1：`.edit-panel` 的全屏定位被后面的重复规则覆盖

- [styles.css 2430](../../app/src/styles.css#L2430) 定义 `.edit-panel { position: absolute; inset: 0; ... }`（正确定位，和 `.forge-panel` 一致）。
- [styles.css 5102](../../app/src/styles.css#L5102) 又写了一条 `.edit-panel { position: relative; }`（D 阶段补丁，同一选择器、同权重、位置更靠后）。

结果 `inset:0` 失效，面板回到普通文档流：

1. 高度改由内容决定（250 / 486 / 502 / 1064px 都是被内容撑出来的高度），铺不满舞台 → 现象 2；
2. `edit-panel__body` 的 `flex:1; min-height:0` 拿不到确定高度，向下传递后
   - `.edit-panel__tree` 的 `overflow:auto` 永不生效 → 现象 3；
   - `.toc-tree`、`.block-canvas` 同理，长内容不滚动 → 现象 5；
3. 折叠分组改变内容高度，面板跟着缩 → 现象 3 的后半段。

### 根因 2：底栏是舞台的兄弟节点，编辑档也一直显示阅读底栏

[Reader.tsx 1765](../../app/src/components/Reader.tsx#L1765) 的 `.read-bottom` 在 `main.stage` 之外。即使面板修好，编辑/锻造档下方仍留一条阅读专用底栏（翻页、章节跳转按钮全禁用），是"三档没统一"的视觉残渣。

### 根因 3：概念混用（不是 bug，是模型没分层）

现在叫「目录」的东西其实是三样：

| 概念 | 现状入口 | 本质 |
| --- | --- | --- |
| A 章节列表 | 阅读模式「展开目录」抽屉 | 按正文标题跳章，不该含彩页/封面/nav |
| B 文件标题清单 | 无（只有文件树 `0001.html`） | 全部正文文件的可读标题清单，按 spine 排序 |
| C 目录页 / 目录结构 | 编辑「目录」切面 | nav.xhtml / toc.ncx / spine 的结构与链接配对编辑 |

文件树（D）是第四样：真实文件系统清单，服务于结构操作（重命名/删除/manifest）。A 与 B 功能重叠、C 与 D 部分重叠，正是用户说的"一体两面"。

## 三、实施计划（分阶段，每阶段可单独验收）

### S1（P0，3 行内修复，先止血）

1. 删除 [styles.css 5102](../../app/src/styles.css#L5102) 的 `.edit-panel { position: relative; }`；
2. 确认 `.edit-panel` 与 `.forge-panel` 同为 `position:absolute; inset:0; z-index`，`edit-panel__body / __content / __tree` 高度链条完整；
3. 底栏按档位渲染：
   - 阅读：现状（章节前进/后退、进度、百分比）；
   - 编辑：显示当前文件、字数/块数、"有未保存改动"、写回/保存按钮状态；
   - 锻造：当前段/总段、写回状态；
   - 或最小方案：编辑/锻造时隐藏阅读专用控件，仅保留当前文件名与保存提示。

验收：阅读→编辑→阅读→锻造来回切 6 次，任何档位面板都 100% 铺满舞台，无阅读页残露；窗口拉伸到 820×560 与最大化都正常。

### S2 文件树改为浮层抽屉（不占编辑器宽度）

- `.edit-panel__tree` 改 `position:absolute; left:0; top:0; bottom:0; width:260px; z-index:20;` + 阴影 + 半透明遮罩；
- 内容区不再被挤压，任何切面（段落/源码/元数据/目录）宽度恒定；
- 独立滚动：显式滚动条样式（复用 `.toc-tree` 的 12px 滚动条），`overscroll-behavior: contain`；
- 关闭方式：顶栏按钮、遮罩点击、Esc；
- 树内容分两段：
  1. **正文章节**：主标题 = TOC 可读标题（第一章 / 后记…），副标题 = 文件名；按 spine 排序；
  2. **结构文件**：封面/彩页/样式/图片/字体/manifest，保留原文件名。
- 标题来源：`edit_read_toc` 的 `tree` 里 `href → label` 映射；缺失时用文件首个 `h1/h2` 文本；再缺省用文件名。

验收：15 条目与 100+ 条目两种书，树都能滚到底；展开树时编辑区宽度不变；收起正文章节不影响面板高度。

### S3 目录概念三分

1. 阅读模式按钮改名/改义：「展开目录」→「章节列表」，tooltip 明确"仅正文章节"；
   过滤规则：排除 `FRONT_PAGE_RE`（cover/titlepage/intro/nav/toc/contents）与彩页（`color/plate/illustration` 命名），只保留 spine 中的正文 text 项；过滤后条目数显示在抽屉头部。
2. 编辑档新增「文件标题清单」入口（可并入 S2 抽屉的"正文章节"段，不新增第五个按钮）；
   点击 = 打开该文件并定位到对应标题块（复用 `initialHref`/`initialBlock`）。
3. 编辑「目录」切面保留（工具栏与链接配对 UI 是它独有的），但重命名为「目录结构」，tab tooltip 写清"编辑 nav.xhtml / toc.ncx / spine 顺序"；
   在目录结构里选中条目时，提供"打开对应文件"动作，形成 C↔B 的桥。

验收：同一本书
- 阅读「章节列表」只剩第一章…后记（无彩页）；
- 编辑抽屉里每个正文文件都显示"第一章 / ch_115048.xhtml"两行；
- 目录结构切面仍能拖拽、批量上下移、设置目标、重命名目标文件（现有功能不回退）。

### S4 三档统一框架（为后续铺路）

统一为：`顶栏（唯一）→ 舞台（stage）→ 底栏（按档位）`；所有浮层（章节列表、文件树、脚注、彩页、设置面板）一律 `absolute` 定位于 stage 内，互不挤压。沉淀一份"滚动容器契约"：

```
父容器: display:flex; flex-direction:column; min-height:0
滚动子容器: flex:1; min-height:0; overflow-y:auto; overscroll-behavior:contain; scrollbar-gutter:stable
```

后续「文件级新建/重命名/删除/移动（同步 OPF manifest 与 spine）」直接挂在 S2 抽屉的树上；「阅读层划词草稿撤销栈」挂在阅读档的写入路径上，与布局解耦。

## 四、风险与回归清单

- `.edit-panel` 的 CSS 重复规则说明历史补丁可能还有同类覆盖；实施前全局搜一遍同名选择器重复声明。
- `embedded` 模式下编辑面板没有自带头部/标签，高度依赖 stage，修复后要检查段落视图横向工具栏（`block-bar`）在窄窗口是否换行挤压。
- 目录结构切面的拖拽、批量移动依赖 `.toc-tree` 高度与命中区域，S1 后要重测拖拽。
- 文件树改浮层后，`handleSelect` 里的自动定位（`treeRef.scrollTop`）需确认在遮罩下仍生效。
- 保存/打包路径不受布局影响，但切档时的 dirty 确认逻辑要复测。
