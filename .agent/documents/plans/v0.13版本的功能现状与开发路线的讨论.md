## 2. 已上线的功能

### 2.1 书架

- **11 种格式导入**：EPUB / MOBI / AZW / AZW3 / FB2 / CBZ / ZIP / PDF / TXT / MD / HTML。
- **三种视图**：网格、列表、仿轻小说文库的轴测 3D 书架（书脊 / 书页顶面 / 退封面三面投影，按视口高度自适应）。
- **组织能力**：分组、排序、批量删除；所有导入入口（按钮 / 拖拽 / 启动参数）统一走同一入库流程。
- **封面**：EPUB 自动抽取并缓存到 `covers/`；缺失时回源实时提取，不因字段为空放弃加载。
- **两种存储模式**：归档模式（复制进固定书库、保留用户自定义文件名）/ 历史模式（只登记原文件路径 + 阅读进度）。

### 2.2 阅读器

- **排版保真**：直接渲染原书 CSS 与插图，不做二次重排。
- **阅读方式**：分页 / 滚动；单页 / 双页 / 竖排；Ctrl + 滚轮缩放字号（屏幕适配优先）。
- **导航**：目录树跳转、上一章 / 下一章、可点击拖拽的底部进度条。
- **辅助阅读**：脚注气泡、插图点击放大 + 全屏画廊翻页（缩放 / 拖拽 / 左右切换 / Esc 退出）。
- **标注**：6 色高亮、笔记（小字常驻原文旁，可拖动，记忆相对位置，单条上限 500 字，预览 30–50 字）、删除与复原。
- **划词翻译（通道 2）**：译文贴边展示、字号随原文、随页面翻动、以草稿形式存在（关软件即消失，不污染正文）。

### 2.3 编辑器（E6 编辑深水区）

- **五种视图**：文件树 / 源码 / 元数据 / 目录 / 段落块。
- **块级可视编辑**：段落、标题、删除标记；只提交 dirty 块，未改段落逐字节保留。
- **内联格式**：粗体 / 斜体 / 链接 / 标题级别；Word 粘贴白名单过滤，非法标签自动剔除。
- **段落翻译（通道 3）**：逐块一键翻译并**正式写回**工作副本，写回前过 XML 合法性校验。
- **修订与回滚**：修订列表、快照、单条回滚。
- **校验**：epubcheck 内嵌运行，结果按错误级别着色；成功提示面板带关闭按钮。
- **位置连续性**：阅读 ↔ 编辑切换自动对齐当前阅读段落，不出现空白等待。
- **目录编辑**：`nav.xhtml` 与 `toc.ncx` 同步写回；章节重命名联动 OPF / spine / 内部引用；同层拖拽排序、升降级、批量勾选、全书扫描（未使用图片 / 孤儿文件 / 重复 id / 断链 / 目录与 spine 不一致五类）。

### 2.4 锻造器（ForgePanel，通道 1）

- 逐段改写 / 翻译 / 注释，支持整章批量。
- **双书源**：TXT 走 `forge.json` 覆盖层；EPUB 直接写回工作副本并即时重打包。
- 术语表 + 翻译记忆参与翻译，一致性由专名掩码机制保证。
- 版本快照与回滚；行级 diff 对照。

### 2.5 翻译体系（三通道全闭环）

| 通道 | 入口 | 写回 | 上下文 |
|---|---|---|---|
| 1 锻造 | ForgePanel 逐段 / 整章 | EPUB 写回工作副本；TXT 写覆盖层 | 术语表 + 翻译记忆 |
| 2 划词 | 阅读器工具栏 | `sessionStorage` 草稿 | 轻量 |
| 3 段落 | 编辑器块按钮 | 正式写回工作副本 | 轻量 |

- **双引擎**：在线（任意 OpenAI 兼容接口）/ 本地（Ollama、LM Studio）；断网自动回落本地。
- **术语表**：CSV 2–4 列（原文 / 译文 / 类型 / 备注），类型分 person / place / org / term，跨书共用，可导入导出。
- **翻译记忆**：命中即复用；用户手工修订覆盖旧值。
- **后处理**：`【Tn】` 占位还原标准译名 → 繁转简（OpenCC t2cn）→ XML 合法性校验。

### 2.6 从零做书与格式转换

- **两步向导**：基础信息（书名 / 作者 / 语言 / 封面 / 3 套样式预设）→ 三层树形结构（正文 / 分卷 / 章），支持同层拖拽、升降级、合并拆分、插图、番外与后记。
- **章节导入**：TXT / MD / HTML，预览与最终生成同源逻辑。
- **生成**：`buildEpub` 自动产出 OPF / nav / NCX，正文页按段落直落 `body`（与编辑器块序号严格对齐）。
- **转换**：TXT / MD / HTML / FB2 / CBZ / ZIP / PDF → EPUB；EPUB → TXT / MD / HTML 导出。
- **质量**：R3 起产物均可通过 epubcheck 零错误零警告；已修复 NCX DOCTYPE（OPF-073）与 playOrder 重复（RSC-005）等历史隐患。

### 2.7 设置与说明书

- 设置页由**功能注册表**驱动：8 张功能卡、20 个设置项，修改即时生效并持久化。
- 面板可拖动、可缩放、位置尺寸记忆，只认关闭按钮。
- **F1 说明书与注册表同源生成**，不会与界面漂移；书架与阅读页均可唤起。
- 关于页版本号动态读取 `tauri.conf.json`，不再硬编码。

## 4. 能力边界（诚实清单）

- **编辑只对 EPUB 成立**；其它格式进入编辑器前会转成工作副本，不写回原格式。
- **PDF 只读渲染 + 文字层提取**；扫描件无文字层时无法转出正文。
- **无在线内容抓取**（漫画 / 小说），CBZ / ZIP 只支持本地导入。
- **翻译不自带模型**；必须用户自配在线 API 或本地端点，Key 明文存于本机 localStorage。
- **仅桌面端**；Windows 已打包验收，Mac / Linux 未验证。
- **TTS（朗读）未上线**，按既定计划延后。
- **大书性能未系统压测**（数百章、超大单页、海量插图场景缺少基准数据）。
- **自动化测试覆盖仍薄**：现有 Rust 单测集中在 E6 块级写回（含真实书端到端用例），其余模块主要靠手工 + Playwright 脚本验收；CI 尚未建立。

## 5. 可深化方向（候选池）

> 说明：以下不是需求清单，而是「真实使用后可能想做的事」。建议按下表先记录痛点，再决定取舍。
> 改动范围：局部 = 单文件/单组件；跨模块 = 前后端联动；结构性 = 涉及数据模型或架构。

### A. 阅读体验（最高频，最容易被真实使用暴露）

| 候选 | 能解决什么 | 改动范围 | 风险 / 代价 |
|---|---|---|---|
| 全局搜索（书内关键词 + 结果列表跳转） | 长篇找不到人名/设定 | 跨模块（foliate search + UI） | 大书搜索耗时，需要异步与进度提示 |
| 书签与「稍后读」 | 高亮/笔记之外的轻量标记 | 局部 + 存储 | 需要与进度模型共存 |
| 快捷键体系（翻页、缩放、全屏、F1） | 目前以鼠标为主，重度用户效率低 | 局部 | 与输入框编辑冲突需隔离 |
| 阅读统计（时长、速度、章节完成度） | 了解自己的阅读节奏 | 跨模块 | 数据只应本机，避免隐私争议 |
| 双页模式下的 gutter / 页边距微调 | 大屏阅读观感 | 局部 | 与字号缩放联动 |
| 沉浸式全屏 + 隐藏工具栏 | 长时间阅读干扰少 | 局部 | 与悬浮提示层级冲突 |

### B. 书架与书库管理

| 候选 | 能解决什么 | 改动范围 | 风险 / 代价 |
|---|---|---|---|
| 搜索 / 按格式 / 按进度筛选 | 书多了以后翻找成本高 | 跨模块 | 需统一列表与 3D 视图的筛选语义 |
| 批量导入去重（同名 / 同内容哈希） | 重复入库 | 跨模块 | 历史模式与归档模式规则不同 |
| 3D 书架交互打磨（抽出动画、悬停预览、横向惯性滚动） | 目前的亮点但操作成本仍偏高 | 局部 | 动画性能在低端机上需降级 |
| 书库健康检查（缺失源文件、封面损坏、进度越界） | 历史模式链接失效无提示 | 跨模块 | 只读检查，不能自动删书 |

### C. 编辑器深化

## 6. 下一阶段的建议做法

1. **先建痛点台账（轻量）**：在 `.agent/memory/2026-11.md` 里按「日期 / 场景 / 卡在哪 / 期望」记流水，不写方案。用两周真实使用积累 20–30 条，再聚类。
2. **按「频次 × 痛感 × 改动成本」排序**：高频低成本的先做（快捷键、书内搜索、书架筛选）；低频高成本的（表格编辑、批量翻译队列）等证据充分再立项。
3. **每轮只做 1 个主目标 + 2 个体验补强**：沿用 R 系列节奏（一项能力 + 若干 UX 补丁），避免并行铺开导致回归失控。
4. **验收标准不变**：构建通过 + 后台截图/DOM 实测 + epubcheck 回归（涉及 EPUB 产物时），未实测不交付。

### 建议的三个候选包（供讨论）

| 包 | 内容 | 适合的前提 |
|---|---|---|
| 包 1「读得顺」 | 书内搜索 + 快捷键体系 + 全屏沉浸 + 书架筛选 | 日常以阅读为主，编辑为辅 |
| 包 2「改得稳」 | 块级撤销/重做 + 修订对比视图 + 图片替换 + 脚注编辑 | 常做 EPUB 修书/合章 |
| 包 3「译得快」 | 全书批量队列 + 原文/译文对照 + 术语冲突检测 + 成本面板 | 主要用途是长篇翻译 |

## 7. 需要拍板的决策点

1. **主用途排序**：阅读 ＞ 编辑 ＞ 翻译，还是翻译优先？三者的打磨顺序直接决定包 1/2/3 的优先级。
2. **大书规模上限**：目标支持多少章、多大单文件？这决定是否值得做性能结构性改造。
3. **翻译成本容忍度**：全书批量是否需要「先估价再执行」？是否允许并发请求。
4. **分发形态**：继续绿色 exe，还是做安装器 + 自动更新？影响资源包与签名方案。
5. **跨设备移植**：暂缓期间，仓库只保留核心代码；恢复时是否需要一并解决资源包与首次启动引导。
