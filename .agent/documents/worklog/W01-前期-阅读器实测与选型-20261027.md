# W01 · 前期 · 阅读器横向实测与选型（2026-10-27）

> 阶段：开工前调研（Phase 0 之前）｜产出：`../analysis/00-开源阅读器横向对比与骨架选型分析.md`（v1.3）与五项拍板

## 1. 目标

回答三个问题：**界面抄哪个、骨架用哪个、功能整合哪些**，并且必须建立在实测证据上，不允许凭印象下结论。

## 2. 做了什么

1. 隔离落盘：全部阅读器安装包/发行版放进 `_reference_apps/`，源码放 `_reference_src/`，`.gitignore` 排除，避免污染仓库。
2. 五款成品软件人工试用 + 截图：Readest、ReadAware、Koodo Reader、Thorium、Wenku8_Flutter（Android，仅源码与官方截图）。
3. 五个源码库浅克隆作为参考代码库：Readest（AGPL-3.0）、ReadAware（AGPL-3.0）、Wenku8_Flutter（GPL-2.0）、foliate-js（MIT）、readium/css（BSD-3）。
4. 统一测样：`_testdata/` 放入《红楼梦》《西游记》TXT、10MB 长文本、自制带脚注中文 EPUB、英文 XHTML 样本。
5. 算法复现：把两家的中文 TXT 章节识别算法分别跑在《红楼梦》《西游记》上，统计章节数。
6. B 站教程视频 `BV1znhR6KEX5`（TTS）取 `view_points` 官方章节 + 关键帧，无字幕（`need_login_subtitle`）如实记录。

## 3. 关键证据

| 项目 | 结论 | 依据 |
|---|---|---|
| TXT 章节识别 | Readest 的"先切段再匹配"在《红楼梦》全废；ReadAware "逐行分类 + 数字可信度校验" 得 123/123 | 两套算法实跑对照表（分析报告 §10） |
| 硬换行 | 中文公版 TXT 一句一行，两家都未做熔接 → 差异化点 | 实测排版观感 |
| 许可证 | Readest / ReadAware / Koodo 均 AGPL-3.0；Wenku8 GPL-2.0 → MIT 路线下零复制 | 仓库 LICENSE 文件 |
| 界面 | ReadAware 信息密度低、图标按钮无中文名、悬停无提示；Wenku8 全中文 + 编号分节 + 命名色卡 | 用户在 Windows 上实际使用反馈 + 官方截图 |
| 骨架 | foliate-js（MIT）渲染能力最完整，Tauri 2 体积最小 | 体积/许可证/API 面 |

## 4. 结论（用户五项拍板）

1. 自建 MIT（不 fork 任何 AGPL 项目）。
2. 界面双模式切换（阅读模式 / 编辑模式）。
3. TXT 转换用**独立转换向导**，不做无提示的隐式转换。
4. 编辑写回源文件，但保存必须留可回滚空间。
5. TTS 默认用系统语音（组合方案），可升级外部引擎。

## 5. 偏差与未决

- ReadAware 目录面板条目数、Readest 脚注弹窗行为未人工确认（UIA 点击在 WebView2 子文档内不稳定）。
- Koodo 启动白屏，`PrintWindow` 抓不到画面 → 未纳入视觉基线（不影响"不作骨架"的结论）。
- Wenku8 无法在 Windows 编译（Flutter/Android），只作界面参考。
