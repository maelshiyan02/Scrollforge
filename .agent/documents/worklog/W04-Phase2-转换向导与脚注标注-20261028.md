## 1. 本轮目标

把"只读 TXT"补成"能把 TXT 锻成标准 EPUB3"，并让阅读页具备注释能力：转换向导、脚注气泡、划词标注。验收的硬门槛是**第三方阅读器能正确打开产物**，不能只在自己程序里能看。

## 2. 实际改动

### 2.1 自写 EPUB 写出（零新依赖）

| 文件 | 职责 |

## 4. 关键问题与修正

1. **脚注点了不弹**：起初把 `FootnoteHandler` 给的临时 `foliate-view` 在 `setState` 之后才插入文档，且气泡用条件渲染 → 插入时容器宽高为 0，分页器算不出栏宽，`render` 事件内容为空。改为「气泡常驻 + `visibility` 隐藏」保留真实尺寸，并在 `before-render` 事件里**先挂载再渲染**，气泡正常。
2. **iframe 里的 Esc 收不到**：正文在 `iframe` 中，按键不冒泡到顶层 `window`。改为每个 `load` 到的文档各挂一份 `keydown`，转发给同一个处理函数，脚注/设置/目录/返回的逐级关闭才生效。
3. **CDP 拖选选不中**：`Input.dispatchMouseEvent` 拖拽必须带 `buttons:1` 且分多步 `mouseMoved`，否则 WebView2 不认为在拖选。
4. **临时远程调试端口**：`tauri.conf.json` 的 `additionalBrowserArgs` 加 `--remote-debugging-port=9333` 才能连 CDP；**交付前已回滚并重构建**，最终 exe 无 9333 端口（实测 `CDP-OFF`）。
5. **系统保存框不可直接驱动**：`SetWindowText` 写入完整路径不进入外壳模型，OK 被视为空名。可行做法是保留应用默认文件名，直接按「保存(&S)」。

## 5. 后台自动化（本轮确立）

- 启动：WMI `Invoke-CimMethod Win32_Process Create`，脱离 shell 任务树，跨命令存活。
- 交互：CDP over WebSocket（Node 24 内置 `WebSocket`）——`Runtime.evaluate` / `Page.captureScreenshot` / `Input.dispatchMouseEvent` / `Input.dispatchKeyEvent`。
- 全程**在进程内注入**，不移动真实鼠标、不发系统按键、不抢前台窗口；交付 exe 抓图用 `PrintWindow`。
- 注意：`window.__TAURI_INTERNALS__.invoke` 是 `writable:false`，无法拦截 dialog IPC，别在这上面浪费时间。
