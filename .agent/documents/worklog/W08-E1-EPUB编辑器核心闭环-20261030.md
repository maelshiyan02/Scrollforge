# W08 — E1 阶段：EPUB 编辑器核心闭环

**日期**：2026-10-30  
**范围**：Scrollforge v0.6.1 → v0.7.0（E1 核心）  
**前置**：可行性分析 `01-EPUB编辑与制作能力-可行性分析.md` §5 E1 验收标准  
**验收标准**（6 条）：

> 1. 书库 6 本 + 任意磁盘 EPUB 都能打开，文件树条目数与实际一致  
> 2. 改任一 xhtml → 保存 → 内置 epubcheck 输出 0 fatals / 0 errors  
> 3. diff：只有被编辑的条目字节变化，其余 CRC 不变（mimetype 仍首项 STORED）  
> 4. 没有 Java 的干净环境里，检查功能照常可用（JRE 真内置）  
> 5. 只读文件自动降级为"另存为"；DRM/路径穿越/ZIP炸弹被拒绝  
> 6. 关闭再打开，未保存改动有提示

**8 个数据结构**：
| 结构体 | 用途 |

| `run_epubcheck()` | 三层回退链：内置 runtime/java → 系统 java → 开发态 resources/epubcheck.jar |
| `infer_mime_str()` / `infer_role_str()` | 公开 MIME / 角色推断 |

## 三、踩坑记录（追加 A07）

### K107 — Rust 工具链损坏（2026-10-30）
**现象**：`rustup.exe` 文件丢失，settings.toml 拒绝访问，`cargo` 报 "missing manifest in toolchain"
**根因**：上次 `rustup default stable` 更新时被超时中断，toolchain 下载不完整
**解决**：直接删 `D:\dev\rust` 全目录（先 `StopCommand` 停掉后台 rustup 进程），然后：
```powershell
Invoke-WebRequest -Uri "https://win.rustup.rs/x86_64" -OutFile "rustup-init.exe"
& rustup-init.exe -y --default-toolchain stable --profile default --no-modify-path
```
**教训**：不要让 rustup 更新在后台 timeout 被移走——它可能还在运行锁文件。遇到工具链坏了最稳的办法就是 `rustup-init.exe` 全新装。

### K108 — zip 2.x `CompressionMethod::Deflated` 不是函数
**现象**：`CompressionMethod::Deflated(6)` 编译报 E0618 expected function
**根因**：zip 2.x 枚举变了——`Deflated` 是 unit variant（无参数），不是 tuple variant
**解决**：直接 `CompressionMethod::Deflated`，压缩级别由底层 flate2 默认处理
**教训**：依赖升级必查文档，`cargo doc --package zip` 生成本地文档最准

### K109 — zip 2.x `SimpleFileOptions` 不存在
**现象**：`cannot find SimpleFileOptions in zip`
**根因**：zip 2.x API 改名了，且 `FileOptions` 是泛型结构体
**解决**：`FileOptions::<()>::default().compression_method(CompressionMethod::Deflated)`
**教训**：泛型类型推断失败时显式指定 `::<ConcreteType>`

### K110 — quick-xml 0.31 `LocalName` 不是 `&[u8]`
**现象**：`expected LocalName<'_>, found &[u8; 8]`
**根因**：quick-xml 0.31 的 `LocalName` 是新类型包装器，实现了 `Deref<Target = [u8]>` 但 Rust 不自动解引用比较
**解决**：用 `.as_ref()` 拿到底层 `&[u8]` 再比较：`local.as_ref() == b"manifest"`
**教训**：新版本库的零拷贝类型（Cow、LocalName 等）总是要加 `.as_ref()` 或 `&*`

### K111 — `Command::creation_flags` 需要 trait
**现象**：`no method named creation_flags found for Command`
**根因**：Windows 专用 trait `std::os::windows::process::CommandExt` 没导入
**解决**：加 `use std::os::windows::process::CommandExt;`

### K112 — container.xml 不用 quick-xml serde::from_str
**现象**：`Container { rootfile: String }` 带 `#[serde(rename = "rootfile@full-path")]` 反序列化失败
**根因**：quick-xml 0.31 的 serde 集成对嵌套属性标记不稳（container.xml 只有 rootfile 一个元素，用属性 `full-path`）
**解决**：直接正则提取 `full-path="xxx"`，10 行代码搞定
**教训**：别硬套 serde::from_str 给小 XML，手写提取函数更可控

### K113 — zip 2.x `crc32()` 直接返回 u32
**现象**：`no method named unwrap_or found for u32`
**根因**：旧版 zip 的 crc32() 返回 Option<u32>，2.x 直接返回 u32
**解决**：`file.crc32()` 直接用

### K114 — UNIX_EPOCH 必须显式导入
**现象**：`cannot find value UNIX_EPOCH in this scope`
**根因**：不在 prelude 里
**解决**：`use std::time::UNIX_EPOCH;`

## 六、补记：工具栏 tooltip + 3D 书架重做（同日）

### 1. 工具栏悬浮说明被遮挡

- 根因：`.shelf-subbar` 曾是 `overflow: hidden`，把向下浮出的 `[data-tip]::after` 裁掉；且靠右按钮的说明横向超出窗口右缘。
- 修法：`.shelf-subbar { overflow: visible; position: relative; z-index: 12 }`；`.subbar-tools / .rack-head` 内 `[data-tip]::after` 改右对齐（`left:auto; right:0`）。
- 实测：`hover .subbar-tools button:nth-of-type(4)` → 说明"刷新书架（重新扫描本地书库与阅读历史）"完整显示在书架之上（`shots/cdp-tip-refresh2.png`，`::after` opacity=1 / z-index=95）。

### 2. 3D 书架改为 wenku8 式轴测投影

- 弃用 CSS `perspective`（整排透视有鱼眼，书脊+90°封面两片拼接不协调）。
- 每本书改成三个共享顶点的面：书脊面 + 书页顶面 + 斜退封面面，全部用 2D 仿射矩阵（`matrix(1,.05,0,1,0,0)` / `matrix(1,.05,.55,-.12,0,0)` / `matrix(.55,-.12,0,1,0,0)`），参考 `archive_wave.dart` 的 `ArchiveBoxDepthRender`。
- 默认行距 = 书脊宽 + 6px，封面被后面的书遮挡 → 只看到一排书脊；`看封面` 档把行距放大到 `0.34 × 封面宽`，斜着看过去每本封面都露出。
- 书高按书散列取 93%–99.8%，一排高低错落；`ResizeObserver` 量视口，`bookH = max(160, 视口高×0.8)`；`justify-content: flex-start` 从左侧起排。
- 悬浮：整本左移上抬 + 抬高 z-index，斜退封面盖到邻书之上；相邻书按 `min(3,d)²*0.8` 轻微下沉（波浪感）。
- 修 bug：`.rack-viewport` 在 pointerdown 就 `setPointerCapture` 会吞掉按钮 click（点书没反应）→ 改为拖动超过 8px 才捕获。
