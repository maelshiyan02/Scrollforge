## 一、完成的工作

### 1. 后端（`app/src-tauri/src/epub_edit.rs`）

纯文本/字节级 XML 改写，**不引入 regex**（项目依赖里没有）：

| 函数 | 说明 |
|---|---|
| `escape_xml_text` | `&` `<` `>` 转义 |
| `find_start_tag` | 按 `:` 之后的 local name 匹配开始标签，兼容 `<dc:title>` 与 `<title>` |
| `attr_value` | 取属性值；要求属性名前一个字节是空格，避免误命中 `xml:id` / 属性值里的 `id` |
| `block_range` | 取 `<metadata>` / `<manifest>` 的区间 |
| `set_dc_field` | 有元素 → 只换内容（自闭合则展开）；没有 → 在 `</metadata>` 前补（有 `xmlns:dc` 才带前缀） |
| `cover_item` | 先找 `properties="cover-image"`（EPUB3），再回落 `<meta name="cover">` 指到的 manifest 项（EPUB2） |
| `insert_manifest_item` / `ensure_meta_cover` | 原书无封面时补条目（EPUB3 才加 `properties="cover-image"`） |
| `apply_metadata` | 对外入口：封面文件替换 → `dc:title/creator/language` → 写回 OPF → 重新解析并回填 `cover_image` |

**本轮修正两处**

1. `OpfMetadata` 补 `#[serde(rename_all = "camelCase")]`。此前前端读 `metadata.coverImage` 恒为 `undefined`，书明明有封面却显示「暂无封面」。
2. 封面替换改为**覆盖原封面文件字节、不动 manifest**（删掉随之无用的 `replace_item_attrs` / `replace_attr_in_tag`）。原设计换格式时会改 href 为 `cover.<ext>`，但 `cover.xhtml` 里 `<img src="cover.jpg">` 会失效，旧图还会变成包里没人引用的孤儿。

### 2. 后端命令（`app/src-tauri/src/main.rs`）

- `preview_image(path)` → `FileContent`（base64 + 真实 mime），选封面后即时预览。
- `edit_update_metadata(edit_dir, opf_path, title, creator, language, cover_path)` → `OpfMetadata`，只改工作副本；真正进包仍走 `edit_save`。

### 3. 前端

- `EpubEditPanel.tsx`：面板内新增「源码 / 元数据」两个标签页；元数据页 = 封面预览 + 「选择图片…」+ 书名/作者/语言（语言带 datalist）+ 只读标识符 + 「写回元数据」「保存并重打包」+ 说明文案。标题栏脏点合并 `dirty || metaDirty`。
- `styles.css`：`.edit-panel__tabs` / `.edit-tab` / `.meta-form` / `.meta-cover` / `.meta-row` / `.meta-actions` / `.meta-note`（2067–2144 行一带）。
- `Reader.tsx`：`onCommitted` 里先 `forgetCover(source.meta.id)` 再刷新阅读器 —— 否则回书架还是旧封面。

## 三、踩坑（已写入 A07 §19）

- `OpfMetadata` 少一个 `serde(rename_all="camelCase")` → 前端字段静默为空。
- 换封面别改 manifest href（书内封面页引用会断），覆盖原文件即可。
- 书架封面有内存缓存，编辑提交后必须 `forgetCover`。
- `toast` 只有 2.8s，验收要 400ms 轮询。
- 构建要显式给 `PATH / CARGO_HOME / RUSTUP_HOME`（`D:\dev\rust`）。
- 验收会真改书库原文件，必须先备份 + 事后字节还原并核对 SHA256。

## 四、已知边界

- 封面若换了格式（如原 `.jpg`、新选 PNG），文件名与 media-type 保持原样、内容为新格式；epubcheck 0 error、本应用正常显示，但极严格的外部阅读器理论上可能按扩展名解码失败。若要彻底对齐，需引入图片转码依赖（当前未引入）。
- 元数据只覆盖 `dc:title` / `dc:creator` / `dc:language` 第一项；`description` / `publisher` / `subject` 等仍走源码页编辑（E3/E4 再收）。
- 书架显示的书名来自文件名，改 `dc:title` 不会改名书架条目（表单下方已注明）。
