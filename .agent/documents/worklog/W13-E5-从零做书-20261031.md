# W13 · E5：从零做书（新建工程 → 章节 → 打包）

- 日期：2026-10-31
- 阶段：E5（制作流水线，复用 E1 打包链路）
- 产物：`build/Scrollforge.exe`（4,276,224 字节 / 2026-10-31 13:09:59）

## 一、目标

按可行性分析 §E5 的四条验收：

1. 从空白新建 3 章书，全程不借助外部工具，产物 `epubcheck 0 errors`。
2. TXT 导入沿用现有章节识别，预览章节 = 产物章节（不二次解析）。
3. 样式预设至少 3 套（中文正文 / 英文小说 / 极简），可在编辑器里改。
4. 生成后自动进入 E1 工作台，改动可保存并另存到任意目录。

## 二、实现

### 1. 产物生成：`lib/epub-writer.ts`

- 新增 `EpubStylePreset = 'zh-serif' | 'en-serif' | 'minimal'` 与 `EpubCover` / `EpubMeta` 扩展。
- `styleFlags()`：`indent`（首行缩进两字）与 `centerHeading`（标题居中）默认只对 `zh-serif` 打开，可被显式覆盖。
- `buildStyle()` 三套预设：

| 预设 | 字体栈 | 行高 | 对齐 | 其他 |
|---|---|---|---|---|
| `zh-serif` 中文正文 | Source Han Serif SC / Noto Serif CJK SC / Songti SC / SimSun | 1.85 | justify | 首行缩进 + 标题居中 |
| `en-serif` 英文小说 | Georgia / Times New Roman / Nimbus Roman | 1.65 | justify | `hyphens: auto` |
| `minimal` 极简 | PingFang SC / Microsoft YaHei / Helvetica Neue / Arial | 1.75 | left | 段距 0.75em、无缩进 |

- 封面：`images/cover.<ext>` + `cover.xhtml`，OPF 增加 `properties="cover-image"` 与 `<meta name="cover">`，spine 封面页置顶；未选封面时不生成任何封面条目。
- 修正历史隐患：`toc.ncx` 的 `<!DOCTYPE ncx PUBLIC ...>` 在 EPUB 3.2 下触发 `OPF-073`，删掉后三套预设产物全部 `0 errors`（ConvertWizard 的旧产物一并受益）。

### 2. 章节导入：`lib/draft-import.ts`（新建）

- `draftFormatOf(fileName)` 按扩展名分 `txt / md / html`。
- `parseDraft()` 输出与 `analyzeTxt()` 相同的 `TxtChapter[]`：
  - TXT：直接 `tidyChapters(analyzeTxt(text).chapters)`，沿用既有章节识别，不二次解析。
  - MD：`#{1,4}` 切章，连续非空行合并成段，`stripInline` 去掉链接 / 强调 / 代码 / 引用 / 列表标记。
  - HTML：`DOMParser` + `body.children`，`h1/h2/h3` 切章，`p/li/blockquote` 取段落；无块级元素时整元素取文字。
- 解析失败或空结果一律退回「整篇一章」，保证向导永远有可编辑内容。

### 3. 新建书向导：`components/NewBookWizard.tsx`（新建）

- 两步：① 书籍信息（书名 / 作者 / 语言 / 封面 / 样式预设）；② 章节（添加 / 导入 TXT·MD·HTML / 改标题与正文 / 上下移 / 删除）。
- 封面选择走 `open` → `read_book` 返 `ArrayBuffer` → `Uint8Array`；预览用 `Blob` + `URL.createObjectURL`，切换时 revoke。
- 导入有多章时若非首章已有正文则追加，否则替换草稿；章节正文按「每行一段」拆分后过滤空行。
- 生成：`buildEpub()` → `save()` 原生对话框（默认落 `final export`）→ `save_epub()` → `onOpenSaved(path)`。

### 4. 串联入口：`App.tsx` / `Shelf.tsx` / `styles.css`

- 书架顶栏新增「新建书」图标按钮（`note_add`），tooltip「从零新建一本书（书名 / 章节 / 样式）」。
- `openExternal(path, { edit })` 支持生成后直接打开编辑层；`openSavedEpub(path, true)` 生成后自动进入 E1 工作台。
- 新增 E5 向导样式块（`.nb-*`），沿用现有纸张 / 强调色的视觉语言。

## 三、验证（全部实测）

### 1. 从空白建 3 章书

- 向导 step1 选「极简」预设，填书名《风从窗缝里来》，step2 手写 3 章（`3 章有正文 · 133 字`）→ 生成。
- 原生保存框确认后产出 `final export/风从窗缝里来.epub`（6,485 字节）。
- `epubcheck`：`0 fatals / 0 errors / 0 warnings / 0 infos`。
- 解包核对：`OEBPS/text/ch0001.xhtml` 648 B、`ch0002.xhtml` 601 B、`ch0003.xhtml` 571 B，恰好 3 章。
- 成品 `style.css` 的字体栈为 `PingFang SC ... sans-serif`、`line-height: 1.75`，确认走的是所选「极简」预设。

### 2. TXT 导入沿用旧识别

- `parseDraft()` 的 TXT 分支直接调用 `analyzeTxt()`，与转换向导共用同一份章节结果，预览即产物。
- 用 3 个 `第X章` 标题的样本文本实测：解析结果 3 章、标题完整（`第一章 起风 / 第二章 山雨 / 第三章 归途`），硬换行按既有逻辑熔接成段。

### 3. 三套预设差异

用 `.agent/e5_build.ts` 脱离 UI 生成三本同内容样书，解包比对 `style.css`：

```
book-zh  => font-family: "Source Han Serif SC", "Noto Serif CJK SC", "Songti SC", "SimSun", serif;
book-en  => font-family: Georgia, "Times New Roman", "Nimbus Roman", "Source Han Serif SC", serif;
book-min => font-family: "PingFang SC", "Microsoft YaHei", "Helvetica Neue", Arial, sans-serif;
```

三本均 `epubcheck 0 errors / 0 warnings`（6,496 / 7,421 / 6,485 字节，其中 en 版含 1×1 PNG 封面）。

### 4. 生成后进工作台 + 改动可保存 / 另存任意目录

- 生成后自动打开阅读器并进入编辑层，标题「编辑 EPUB」，文件树含 `ch0001~ch0003.xhtml`。
- 打开 `OEBPS/text/ch0001.xhtml` → 段落视图改末段为「她决定今天就走。【E5闭环验证】」→「应用到源码」右侧 textarea 同步 →「写回当前文件」`dirty` 清空。
- 「另存为」：原生对话框 `AppActivate('另存为 EPUB')` + `SendKeys` 输入完整路径 `...\.agent\tmp-e5\saved-as-test.epub` → 落盘 4,160 字节。
- 解包核对：3 章齐全，`ch0001.xhtml` 内确有【E5闭环验证】；`epubcheck 0 errors / 0 warnings`。

> 尺寸差（6,485 → 4,160）来自 `edit_save` 重打包时使用 deflate，而前端 `buildEpub` 是 store 不压缩；两者结构一致，均合法。

## 四、踩坑（已写进 A07 §23）

1. `toc.ncx` 写 DOCTYPE 会在 EPUB 3.2 触发 `OPF-073`，NCX 不需要 DOCTYPE。
2. 原生「另存为」对话框 CDP 点不到，必须 `WScript.Shell.AppActivate(标题)` 后 `SendKeys`；SendKeys 里中文文件名不可靠，验收用 ASCII 文件名。
3. 手动 `dispatchEvent(new InputEvent('input'))` 后 React 状态不是同步可见，要等一帧（约 300ms）再断言按钮 `disabled`。
4. `buildEpub` 把整章包在单个 `<section>` 里，编辑器段落视图因此只有 1 个块；章节内段落编辑仍可用，但块级定位粒度是「章」。
5. 前端 store 写入与 Rust 重打包的 deflate 压缩会造成「同一本书两种体积」，验收比结构不比字节。
