# W20 · R7 · 翻译（反馈 ⑧⑪）

> 上级索引：`../../memory/appendices/W00-工作日志索引.md`

## 一、目标

按计划书 §0.10.3「R7 · 翻译」：

1. **双模式**：本地引擎优先、在线引擎可选；设置里可切换引擎、配 API Key、导入离线模型包。
2. **流水线**：分段 → 术语/人名地名组织名表 → 翻译 → 文学化后处理 → 一致性检查 → 人工校对 → 写入翻译记忆。
3. **韩译中**：专名以简体中文为准，可编辑对照表；繁→简 normalize（OpenCC）优先级高于模型输出；用户可逐条纠正并回灌。
4. **英译中**：风格指南（成语/谚语/书面语/避免直译腔）+ few-shot + 术语表；在线负责高质量，本地负责离线可用。
5. **本地引擎自我迭代**：术语表 + 翻译记忆 + 用户修订 + 风格规则持续积累，不重训练模型；模型包与运行时分开。

验收：
- 同一段落离线/在线各译一次，术语表命中 100%，专名全部简体；
- 韩文样章对照表可导入导出，抽查 30 条全部简体且一致；
- 断网时本地引擎可完成整章翻译；在线失败自动回退并提示。

## 二、做了什么

### 1. Rust 后端（`src-tauri/src/main.rs`）

- `translate_text`：OpenAI 兼容 `/chat/completions` 调用（在线与本地 Ollama/LM Studio 同协议），`ureq` + `json`，支持 baseUrl/model/apiKey/temperature/timeout，返回译文与耗时。
- 术语表读写 `read_glossary` / `write_glossary`；翻译记忆读写 `read_translation_memory` / `write_translation_memory`；文本文件导入导出 `read_text_file` / `write_text_file`。
- 数据落 `app_data/translate/glossary.json` 与 `memory.json`，跨书共用；所有命令注册进 `invoke_handler`。
- `Cargo.toml` 增 `ureq = { version = "2", features = ["json"] }`。

### 2. 前端基础库

- **`lib/glossary.ts`（新建）**：`GlossaryEntry`（source/target/kind/note）、JSON/CSV 双向解析与序列化（表头 `source,target,kind,note`，容忍引号与逗号）、合并去重、繁→简批量简化。
- **`lib/translate.ts`（新建）**：`detectLanguage`（韩/英/中/未知）、`glossaryHits`、`systemPrompt`（文学化/忠实/口语化三种风格 + few-shot + 术语对照 + 占位符保留规则）、`maskProperNouns`（人名/地名/组织名替换为 `【Tn】`）、`restoreMasks`（按编号 Map 还原为术语表简体译名）、`cleanTranslation`（含 `toSimplifiedZh`，OpenCC `opencc-js/t2cn` 繁→简）、`translateOne`（翻译记忆命中 → 掩码 → 引擎 → normalize → 还原）、`probeEngine`、`tmKey/parseMemory/serializeMemory/rememberTranslation/memoryCount`、`translateConfigFromPrefs`。
- **`lib/prefs.ts`**：新增 `TranslateMode`（auto/local/online）与 `TranslateStyle`（literary/faithful/colloquial），默认值补齐 8 个翻译偏好。
- **`lib/features.ts`**：翻译卡片由「规划中」改「已上线」，`kind:'text'` 支持 API Key/模型名，`action: storage | glossary | translateTest`，共 10 个设置项。

### 3. 界面

- **`GlossaryDialog.tsx`（新建）**：术语表增删改、搜索与类型过滤、批量「全部转简体」、粘贴/文件导入、CSV/JSON 导出与预览、条数统计（总数 + 人名/地名/组织/术语分项）。
- **`SettingsDialog.tsx`**：文本设置项输入类名改 `feature-input`（`.feature-text` 已是功能卡容器，冲突会让输入框布局错乱）；翻译动作接入「打开术语表 / 测试连接」，连接测试 Toast 显示引擎与耗时；末尾挂载 `GlossaryDialog`。
- **`ForgePanel.tsx`**：新增「译本段 / 译本章」、进度与停止、跳过已有译文、术语命中标签、引擎徽标（本地/在线/翻译记忆）、回落提示；保存 `commit()` 后把用户校对过的译文写回翻译记忆（仅 dirty translate），文件头注释补 `translateConfigFromPrefs`。
- **`styles.css`**：追加 R7 段（`.forge-translate*`、`.forge-term-hits`、`.feature-input`、`.glossary-*`），未改旧样式。

### 4. 版本与构建

- `tauri.conf.json` / `package.json` / `Cargo.toml` 三处同步 **0.12.0**；新增依赖 `opencc-js`（MIT AND Apache-2.0）。

## 四、偏差与原因

- **本地引擎不做内置推理运行时**：按可行性分析，本地模式走 Ollama / LM Studio 的 OpenAI 兼容接口，软件只负责协议与提示词，不打包模型权重；「导入离线模型包」在设置里留入口与说明，不在本轮内置 GGUF 加载器。
- **掩码方案而非直接依赖模型一致**：专名先替换 `【Tn】` 并要求原样保留，译后按编号还原术语表简体译名；实测一次 0/5 的 bug 是 `masks` 只 push 命中项导致编号与下标错位，改为 `MaskInfo.no` + `Map` 后修复；「专名 6/5」是同一专名重复出现的计数假象，改为去重统计。
- **OpenCC 只做繁→简**：新增 `opencc-js`（MIT AND Apache-2.0），不引入 GPL 词典与转换引擎；转换在模型输出之后、掩码还原之前执行，保证「繁→简优先级高于模型输出」。
- **翻译记忆以用户校对为准**：自动译文不写记忆，只有保存时 dirty 的译文段落回灌；避免把低质量机翻固化。
- **测试书登记为本地书库**：history 模式书没有 `source.txt`，`commit_forge` 拒绝写回；测试书临时登记为 library 书（`source.txt` + `meta.json`），验收后删除。
- **另一处实测坑**：`meta.json` 用 PowerShell `Set-Content -Encoding UTF8` 写入带 BOM，Rust `serde_json` 解析失败导致书库扫描不到；改用无 BOM 写入。
