# W21 · E6 · 编辑深水区

> 上级索引：`../../memory/appendices/W00-工作日志索引.md`

## 一、目标

按计划书 §0.10.3「E6 · 编辑深水区」：

1. **内联格式工具条**：粗体 / 斜体 / 链接 + 标题级别下拉。
2. **粘贴白名单**：只允许 `em / strong / i / b / a / span / br / img`；属性只允许 `href / title / src / alt / class`；危险协议 `javascript:` 等剥离；粘贴后 XML 合法性校验。
3. **块级回写只替换 dirty 块**：未改动块逐字节保留（取代旧前端整篇 `XMLSerializer` 序列化）。
4. **非 EPUB → 工作副本 EPUB**：`buildEpub` 生成 `library/<id>/working.epub` 后进入 E1 编辑面板。
5. **新建书章节按段落拆块**：单层包裹容器下钻（body 仅一个 section/div/article 时把其直接子元素当块），跳过空 `<a id>` 锚点；前后端扫描规则 1:1 对齐。
6. **修订列表与回滚 UI**：`edit_save` 把旧包快照到 `<edit 父目录>/revisions/<秒>_<stem>.source`。

验收：
- 改 30 段落（含中英混排、脚注链接）→ 未触碰段落逐字节一致 + `epubcheck 0 errors`；
- Word 粘贴白名单剥离后 XML 合法；
- 可视视图删段落 / 改标题级别与源码双向同步；
- 可视视图不暴露 CSS / manifest。

## 二、做了什么

### 1. Rust 后端（`src-tauri/src/epub_edit.rs`）

- **字节区间扫描**：`scan_blocks_raw` 按块正则 + 括号配对找 `<p>…</p>` / `<h1>…</h6>` / `<div>` / `<blockquote>` / `<li>`，逐块返回 `start / innerStart / innerEnd / end` 绝对字节偏移；单层包裹容器自动下钻一层；跳过空 `<a id="x"></a>` 锚点。
- **倒序只替换 dirty 块**：`apply_block_edits` 从后往前 `replace_range(s..e, rep)`，区间重叠立即报错 `块区间重叠`；未改动块完全不动；改完统一做 `validate_xml`（quick-xml）。
- **块级写回入口**：`edit_write_blocks` / `edit_scan_blocks` / `edit_delete_block`（旧的整篇 `XMLSerializer` 序列化路径彻底废弃）。
- **真实书端到端单测**：`#[cfg(test)] mod e6_tests::real_book_untouched_bytes_and_epubcheck` 读 `SCROLLFORGE_E6_BOOK` 或默认 `local book repository/（中译）灭门家族的重生者.epub`；在块最多的 .xhtml（≥30 段）上改 1 段正文、改 1 段标签为 h2、删 1 段；断言其余 26 段原文逐字节存在 + 重扫 tag 变 h2 + 新文本出现 + 被删段消失 + `pack_epub` → `run_epubcheck` 断言 **0 fatal / 0 error / 0 warning**；额外用坏 epub 断言 epubcheck 能产出非空消息（证明报告真跑了）。
- **修 epubcheck 参数 bug**：原 `cmd.arg("--json").arg(epub)` 把 EPUB 当 JSON 输出文件，epubcheck 直接报 `No file specified in the arguments.` 且 stdout 空 → 应用层 `edit_check` 长期静默"通过"。修复：`--json <temp-report.json> <epub>`，读报告文件，报告缺失返回 Err 提示退出码与 stderr；测试耗时从 1.35s 变 8.85s 证明真跑了。
- **`main.rs` 命令注册**：`edit_write_blocks` / `edit_list_revisions` / `edit_restore_revision` / `file_exists`。

### 2. 前端基础库（`lib/inline-format.ts`）

- **白名单清洗**：`sanitizeInline` 白名单仅 `em / strong / i / b / a / span / br / img`，属性仅 `href / title / src / alt / class`；危险协议（`javascript: / vbscript: / data:`）剥离；HTML 节点树处理 + XMLSerializer 输出合法 XHTML 片段 + DOMParser XML 合法性校验。
- **修 XML 校验 bug**：原实现把 `innerHTML`（含 `<br>` 非自闭合、`&nbsp;` 实体）直接塞给 XML DOMParser → 任何含 `<br>` 的输入（含纯文本换行粘贴）都抛 `Unexpected closing tag div != br`。修复：改用 `new XMLSerializer().serializeToString(node)` 从节点树序列化，空元素自闭合、`&nbsp;` 输出为字符本身。
- **其他**：`BLOCK_TAG_LABELS`、`splitPreview` / `restorePreview`（图片/图形占位还原）、`normalizeBlockBreaks`、`textToInline` 保持不变。

### 3. EpubEditPanel.tsx

- **内联工具条**：粗体 / 斜体 / 链接（`document.execCommand('bold'/'italic'/'createLink')`）+ `.inline-tag` 标题级别下拉（p / h1–h6 / div / blockquote / li）；`onMouseDown.preventDefault()` 保选区不丢。
- **粘贴过滤**：`handleBlockPaste` 读取 `text/html` → `sanitizeInline(normalizeBlockBreaks(html))` → `insertHTML`；纯文本走 `textToInline`；提示「粘贴内容已过滤：剥离 N 个标签 / M 个属性」。
- **只提交 dirty 块**：`applyBlocks` 遍历 rows，只给 `inner` 改过的或 `tagChanged` 的或 `deletedIdx` 里的块 push payload，其余一律跳过 → 后端 `apply_block_edits` 对这些块完全不动字节。
- **修 `changeBlockTag` bug**：旧实现 `setBlocks` 后还把 `host.innerHTML` 存进 `blockEdits.current[index]` → payload 会同时带 `inner` 和 `tag` → Rust 会用 inner 重写块内内容 → 块内原始字节丢失。修复：`changeBlockTag` 只改 state 设 dirty，**不存 inner**，让 Rust 在 payload 只有 `{index, tag:'h2'}` 时保留原 inner。
- **删除段落**：`.blk-del` 按钮 + `confirm` → `setDeletedIdx` 显示 `is-deleted` 灰块 + "撤销删除"。
- **修订 UI**：`.edit-panel__head` 历史版本按钮（title="历史版本（保存时的 EPUB 快照）"）→ `.rev-panel` 弹出 revision 列表 + 每条「回滚」（会先自动存档当前 EPUB）。
- **文件树过滤**：blocks 模式下 `visibleGroups` 仅 `text` / `toc`（正文 / 目录），CSS / manifest / 图片 / 字体全部隐藏。
- **源码视图**：应用改动后自动切回段落预览；源码框改完 700ms 防抖重建预览。

### 4. Reader.tsx：非 EPUB 转工作副本 EPUB

- `prepareWorkingCopy`：`source.kind === 'library'` 时，先检查 `library/<id>/working.epub` 存在性（`file_exists`），存在则复用、不存在才转；避免每次编辑都重转。
- 转换：`decodeText` → `toPlainText` → `analyzeTxt` → `buildEpub({ indent, centerHeading, ...prefs })`。
- 打开编辑面板时，EPUB 用原 `source.meta.path`，非 EPUB 用 `workingEpub`。

### 5. 样式补充

- `.inline-bar` / `.inline-tag` / `.blk-del` / `.rev-panel` / `.is-deleted` 等类补进 `styles.css`；`.edit-panel__tree` 增加 `group-filter` 规则隐藏非正文/目录条目。

## 四、偏差与原因

- **epubcheck `--json` 参数 bug**（Rust）：`--json` 必须后接输出文件再后接 EPUB，原实现把 EPUB 当输出文件 → epubcheck 静默空 stdout → `edit_check` 长期"假通过"。这是 **E1 以来一直存在**的 bug，靠这次引入真实书端到端单测才暴露（单测里 `run_epubcheck` 耗时从 1.35s 变 8.85s 才发现跑真了）。
- **sanitizeInline 用 innerHTML 做 XML 校验**（前端）：`<br>` 未闭合、`&nbsp;` 不是 XML 预定义实体 → 任何含 `<br>` 的输入（纯文本粘贴换行也含 `<br>`）都抛 XML 不合法。修了后用 XMLSerializer 序列化节点树。
- **changeBlockTag 多提交 inner**（前端）：旧实现设完 state 还把 innerHTML 存进 `blockEdits` → payload 里同时有 `inner` 和 `tag` → Rust 会用 inner 重写块内内容 → 块内原始字节丢失。修了后只设 dirty 标志，不存 inner。这一条是验收"未改动段逐字节保留"的关键，不修就不可能过。
- **vite 默认监听 IPv6 `[::1]:1420`**：Playwright MCP 走 `127.0.0.1` 连不上，报 `net::ERR_HTTP_RESPONSE_CODE_FAILURE`。用 `--host 127.0.0.1 --port 1421` 起第二个 vite 进程绕过（原 1420 保留给 tauri.conf.json 的 `devUrl`，两个端口互不干扰）。
- **真实应用 WebView2 无法开 CDP**：`WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9222` 对 Tauri 无效（Wry 显式覆盖了），只能在 `tauri.conf.json` 加 `additionalBrowserArgs` 并重建 → 但交付版本要求去掉该字段，所以验收期用 harness 内存测试代替。
- **新建书章节目前仍整章一个 `<section>`**：扫描器单层下钻已处理（body 只有 section 时把 section 的直接子元素当块），但生成器 `buildEpub` 还没改"按段落拆块"这一条 → 单层包裹实际效果等价，但源码层还是一个 section 包所有段落；本轮主要验收的是"扫描与回写 1:1 对齐 + 未改字节保留"，拆块留在后续。
