# W24 · E6-UX · 编辑器段落翻译（通道 3）

> 上级索引：`../../memory/appendices/W00-工作日志索引.md`
> 分类：E6 编辑器 UX 迭代（翻译三通道之通道 3）

## 一、改动原因

翻译三通道方案的最后一环——**编辑器内直接翻译段落块**。通道 1（ForgePanel 整章）和通道 2（Reader 划词实时贴边）都已落地，现在差通道 3：用户在 EpubEditPanel 的段落预览里点一下就把这段翻译成中文，结果直接替换块内正文，用户可以继续在段落预览里手工润色，点「应用改动」正式写回 EPUB。

核心诉求（来自 translate-pipeline SKILL.md §四）：
1. 每个段落块右下角 blk-del（删除）按钮旁边加一个小的蓝底翻译按钮。
2. 调 translateOne 拿译文 → sanitizeInline 白名单 + XML 校验 → 塞 blockEdits.current[i] + setBlocks 更新预览。
3. 译文标记 dirty，走已有 edit_write_blocks 写回链路——**正式内容**，不是草稿（区别于通道 2 的 sessionStorage 草稿）。
4. 用 translate-pipeline skill 的标准接法：glossary 传空数组，不传 memory。

## 二、改了什么

### 1. EpubEditPanel.tsx

- **import 加两行**：
  - `import { translateOne, translateConfigFromPrefs } from '../lib/translate'`
  - `import { DEFAULT_PREFS, type Prefs } from '../lib/prefs'`
  - sanitizeInline 已在 inline-format import 里（line 11），不用重复。

- **Props 类型**：加 `prefs?: Prefs` + 注释说明是翻译三通道通道 3 用的。

- **函数解构**：加 `prefs = DEFAULT_PREFS`（不传时用默认 prefs，保证 standalone 场景下也能跑）。

- **新 state**：`translatingBlock: number | null`（当前正在翻译的块序号，单块粒度 loading）。

- **块渲染（blocks.map）**：
  - 原来 `{!isDeleted && <button className="blk-del">...}` 单条件块，改成 `{!isDeleted && (<><button className="blk-translate">...<button className="blk-del">...</></>)}`。
  - blk-translate 按钮完整 onClick 链路：
    1. 防重入：`if (translatingBlock === i) return`
    2. `setTranslatingBlock(i)` 进入 loading 态
    3. 从 `b.html` 抽纯文本：`b.html.replace(/<[^>]+>/g, ' ').replace(/\s+/g, ' ').trim()`
    4. 空文本兜底：toast「这段没有可翻译的文字」→ 退出
    5. 调 `translateOne({ config: translateConfigFromPrefs(prefs), source: sourceText, glossary: [] })` —— 不传 memory（通道 3 轻量链路）
    6. `sanitizeInline(outcome.text)` 白名单 + XML 校验 → 拿 `.xml` 字符串
    7. `blockEdits.current[i] = sanitized.xml`（写回链路核心：edit_write_blocks 用这个）
    8. `setBlocks(prev => prev ? prev.map((r,j) => j===i ? {...r, html: sanitized.xml} : r) : prev)` —— null 安全
    9. `if (!blockDirty) setBlockDirty(true)` —— 标记有未保存改动
    10. toast 显示引擎名（在线/本地/记忆命中）+ 耗时 ms + 「可继续在段落里改」
    11. finally `setTranslatingBlock(null)` 复位
  - Icon：`translatingBlock === i ? 'hourglass_top' : 'translate'`（和通道 2 一致）。

### 2. Reader.tsx

- `<EpubEditPanel ... />` 调用加 `prefs={prefs}` —— Reader 已有 `const prefs = loadPrefs()` 变量，直接透传。

### 3. styles.css

- `.blk-translate`：和 `.blk-del` 同样尺寸 22×22、同样圆角 5px、同样 `place-items:center`。
- 颜色偏蓝（区别于 .blk-del 的红色系）：`#c6d2e2` 边框、`#f2f7fc` 背景、`#5a7ea0` 文字；hover 加深到 `#2a5690` / `#e4eef9`。
- 位置：`right: 28px`（.blk-del 是 right: 2px，错开 26px 避免重叠），top 同样 6px。
- 显示策略和 .blk-del 一致：`.blk:hover .blk-translate:not(:disabled) { display: grid }` —— hover 块才显现，disabled（翻译中）直接 `display: grid; opacity: 0.55` 强制可见 + 半透明，表示「正在翻译这一块」。

## 三、验收

- `npm run build`：tsc --noEmit + vite 96 modules 通过（exit code 0），CSS 87.19 kB（+0.41 kB），JS 663.85 kB（+0.90 kB）。
- 打开 EPUB 进 EpubEditPanel 段落预览 → 鼠标 hover 任意段落块右上角 → 出现两个小按钮（左侧蓝底 translate、右侧红底 delete）→ 点 translate → 按钮图标变 hourglass_top + 半透明 → 约 1-5 秒后 toast「已翻译（在线/本地 · Xms），可继续在段落里改」→ 段落正文变成中文译文 → block 顶部出现黄边（dirty 高亮）→ 可以在段落里继续编辑 → 点「应用改动」→ edit_write_blocks 写回 working.epub。
- 翻译失败（引擎不通）→ toast「翻译失败：...」+ 按钮复位，块不被改坏。

## 四、踩坑

1. **React Fragment 短语法 `<>...</>` 不需要显式 import**：当前项目是 Vite + React 17+ 自动 JSX 转换配置，TSX 文件里直接用 Fragment 短语法没问题，import 列表里不用加 `Fragment`。如果换到 JSX 运行时禁用的老配置会炸。

2. **blocks 是 BlockRow[] | null**：setBlocks 的 prev 必须判 null，translateOne 返回后如果 prev 为 null（极端时序）就返回 prev 不更新。已用三元表达式保护。

3. **sanitizeInline 会把译文里的特殊字符（如 & < >）序列化为 XML 合法形式**：translateOne 返回的纯文本可能直接含 `<`（比如引擎输出了一段带尖括号的内容），sanitizeInline 用 XMLSerializer + DOMParser 双重校验保证塞回 inner 合法。如果 translateOne 输出纯文本（通常情况），sanitizeInline 就只是空走一遍白名单（没有危险标签），xml === textContent 转义后结果。
