# W27 · 使用痛点修复：锻造 EPUB 可用 + 书架封面自检（2026-11-05）

> 回指：`.agent/memory/appendices/W00-工作日志索引.md` ｜ 上次阶段：W26 buildEpub 拆块

## 1. 目标

在进入 v0.13 功能现状与开发路线二次讨论前，先解决两个实际使用痛点：

1. **EPUB 进入阅读器后「锻造」按钮灰化**，无法做任何翻译测试。
2. **直接复制进书库的 6 卷《轮回第7次的反派千金》没有封面**；磁盘 `covers/` 里是 6 个 `.xhtml` 空文件 + 1 个多余 `cover.jpg`。要求：
   - 刷新书架按钮自带「书 + 封面」检测；
   - 软件每次启动自动做同一套防御性自检；
   - 封面要有「记录表」式的比对，不能缺关键文件，也不能留冗余文件。

## 2. 做了什么

### 2.1 锻造不可用（`app/src-tauri/src/epub_edit.rs`）

- `parse_opf_manifest` / `parse_opf_spine` 原来只匹配 `Event::Start`；外部 EPUB 的 `<item …/>`、`<itemref …/>` 是自闭合标签，走 `Event::Empty`，导致 manifest/spine 全空。两个解析器改为 **Start | Empty 同时处理**。
- `unpack_epub` 在循环结束后按 `opf_path` **从已解压文件补解析一次 manifest**：OPF 在 ZIP 中排在 `container.xml` 之前时，循环里的顺序匹配会漏。
- 验证时额外发现 `extract_plain_text` 用 `bytes[i] as char` 逐字节推进，中文被拆成 latin-1 乱码（`è½®å›ž…`）；改为 `chars().next() + len_utf8()` 按 UTF-8 字符推进。修复后正文长度 650,819 → 329,697（此前每个汉字被算成 3 个字符）。

### 2.2 封面缺失与封面目录卫生（`app/src-tauri/src/main.rs`）

- 重写 `extract_epub_cover`：
  - 解析 manifest 的 `id/href/media-type/properties`，支持自闭合 `<item/>`；
  - 优先级：`properties="cover-image"` → EPUB2 `<meta name="cover">` → id 含 cover 的图片 → 若命中项是 XHTML，下钻其 `<img src>` / `<image href>`；
  - 所有候选都用 **魔数嗅探**（JPEG/PNG/GIF/WEBP/BMP）确认，绝不把 xhtml 当封面。
- 新增封面记录表辅助：`valid_cover_file` / `find_cached_cover` / `ensure_flat_cover`；扁平书库统一用 `sanitize(title).<真实扩展名>` 命名，已有有效文件复用，缺失/损坏才重新提取。
- `read_cover`：登记文件必须通过魔数校验，xhtml/损坏文件直接忽略并从 EPUB 实时提取；`save_cover`：先嗅探真实图片类型，扁平书库写「书名.ext」且不再写固定 `cover.jpg`。
- 新增命令 **`shelf_health`**（启动与刷新共用）：
  1. 每本书校验封面，坏了/缺了就重建；
  2. `covers/` 里非图片文件、以及不属于任何书目的冗余文件直接删除；
  3. 正文文件缺失只在报告里列出（绝不删书）；
  4. 返回 `scanned / coversRepaired / coversRemoved / repairedTitles / removedFiles / missingSources / uncoveredTitles`。

### 2.3 前端（`cover.ts` / `App.tsx` / `Reader.tsx`）

- `cover.ts`：新增 `sniffMime`（按魔数选 MIME，旧缓存是 xhtml 也不会渲染错）与 `clearCoverCache()`。
- `App.tsx`：`refreshLibrary` 先 `invoke('shelf_health')` 再 `list_books`；有修复/清理/缺失时清封面缓存并 toast 汇总。启动挂载与「刷新书架」按钮走同一条路径。
- `Reader.tsx`：锻造提示从「只支持 TXT」改为「逐段改写、翻译、注释，写回 EPUB / TXT 源文件（可回滚）」。

### 2.4 测试（替换临时探针）

- `epub_edit::forge_epub_tests::forge_index_parses_spine_and_manifest`：真实 EPUB 必须解析出章节/正文块，中文书额外断言无 latin-1 乱码。
- `main::tests::extract_epub_cover_handles_external_opf_books`：遍历书库中 6 卷《轮回第7次的反派千金》，每本都必须抽到 >1KB 的真实图片。

## 4. 偏差与原因

- 原计划只修「锻造灰化 + 封面提取」，验证锻造面板时发现中文乱码，属于同一链路的解码 bug，遂在同一轮修复并加回归断言。
- 原计划直接复用 `save_cover` 的 `cover.jpg` 命名；实际扁平书库没有 `meta.json`，`write_cover_meta` 必然失败并留下孤儿文件，改为按书名推导命名 + `shelf_health` 兜底清理。
