## 一、反馈与实测结论

用户提出 5 点：目录切面与文件树重叠；阅读→编辑后编辑面板只占上半、下方露出阅读页且「只有源码视图+展开文件树才正常」；文件树没有滚动条、收起章节后显示失效；文件树应是不占编辑器空间的侧栏；目录视图滚轮失效且目录概念混用。

CDP 后台点击 + 截图复现（《轮回第7次的反派千金 第1卷》，`.stage` 高 720px）：

| 现象 | 实测 | 结论 |
| --- | --- | --- |
| 面板只占上半 | `.edit-panel` 计算 `position: relative`，高 250.65 / 486px | 面板没有铺满舞台 |
| 「源码+树」才正常 | 源码视图面板高 1064px > 720px，超出被 `.app{overflow:hidden}` 裁掉 | 巧合，不是正确布局 |
| 树无滚动条 | 树 `clientHeight = scrollHeight = 486`，`overflow:auto` 不触发 | 缺高度约束，不是缺滚动条 |
| 收起「正文」失效 | 折叠 `<details>` 后 486 → **271.25px**，阅读页露出 | 同上 |
| 目录滚轮失效 | `.toc-tree` 403/427（仅溢出 24px），条目一多就撑满 | 同上 |

运行时把 `.edit-panel` 临时设为 `position:absolute; inset:0` 后：面板 720px=舞台、树 320/486 可滚到 `scrollTop 166`、目录树恢复滚动。**四个现象同一根因。**

## 二、根因

`styles.css` 2430 行 `.edit-panel { position:absolute; inset:0; }` 被 5102 行遗留补丁 `.edit-panel { position: relative; }`（同选择器、同权重、位置更靠后）覆盖。`inset:0` 失效后：

1. 面板高度改由内容决定，铺不满舞台；
2. `edit-panel__body` 的 `flex:1; min-height:0` 拿不到确定高度，向下传递后树/目录树/块画布的 `overflow:auto` 永不生效；
3. 折叠分组改变内容高度，面板跟着缩。

次因：`.read-bottom` 是 `main.stage` 的兄弟节点，编辑/锻造档也显示阅读翻页栏。

## 三、S1 改动（2 个文件）

1. `app/src/styles.css`：删除 5102 行 `.edit-panel { position: relative; }`，恢复 2430 行的全屏定位（与 `.forge-panel` 一致）。`.img-picker` 等 absolute 子元素仍以 `.edit-panel` 为包含块，不受影响。
2. `app/src/components/Reader.tsx`：底栏按档位渲染。
   - 阅读档：原样（上一章/上一页、进度条、百分比、章节名、下一页/下一章）；移除重复的 `mode !== 'read'` 禁用判断（该分支只在阅读档出现）。
   - 编辑档：`编辑中` 徽章 + 章节名 + 当前切面名 + `已同步` / `● 有未保存改动` + 保存/检查中的状态。
   - 锻造档：`锻造中` 徽章 + 章节名 + `逐段改写 · 写回可回滚`。
3. `styles.css` 新增 `.read-bottom.is-mode`、`.mode-badge(.edit/.forge)`、`.mode-tab`、`.mode-state(.dirty)`。

## 六、坑

CSS 同一选择器在文件后段重复声明会整体覆盖前段，且不会报错；这类「历史补丁叠在最终规则之后」的覆盖很难靠读组件发现，必须用 CDP 读 `getComputedStyle` 的 `position/height` 反查。详见 A07 §39。
