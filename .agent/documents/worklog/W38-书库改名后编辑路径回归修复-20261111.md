# W38 — 书库改名后编辑 / 锻造路径回归修复与防御

日期：2026-11-11
状态：已完成并出包
关联计划：`../plans/04-三档数据分层与双文档架构-20261111.md`（S5 回归修复）

## 一、问题

S5 把书库目录从 `<书库根>/<书 id>/` 改成 `<书名>__<短编号>/` 后，打开书籍「编辑」标签报：

```
打开失败：源文件不存在: <书库根>/flat_5847312308328060354/source.epub
```

`flat_5847312308328060354` 是迁移前的旧目录名，迁移后真实路径是
`轮回第7次的反派千金 第3卷__10e8d9/source.epub`。

## 二、根因

1. 前端 `Reader.tsx` 用 `source.meta.path || \`${libraryDir}/${source.meta.id}/source.epub\`` 自己拼路径；
   迁移后 `meta.path` 为 `null`，于是拼出旧式 `<书库根>/<id>/source.epub`。
2. 同类问题还在 `prepareWorkingCopy()`：它把非 EPUB 的工作副本写到
   `<书库根>/<id>/working.epub`，会在书库里**重新造出** `flat_<id>` 目录。
3. 改名是数据层行为，但路径拼接分散在 UI 层，二者没有契约——这是结构性隐患，不是单点笔误。

## 三、修复

### 后端（`main.rs`）

- 新增 `book_paths(id)` 命令，返回 `{ source, dir }`：书目录与正文路径的唯一来源。
- 新增 `resolve_existing_source(raw)`：任何命令收到旧路径时按「父目录名当书 id → 书名/sourceName」自愈。
- `edit_open_epub` / `forge_epub_index` 改为接收 `AppHandle` 并先自愈路径，防任何旧调用方。
- 新增 `resolve_library_write_path(raw)` 并接入 `save_epub`：写入侧若按旧习惯落在
  `<书库根>/<id>/`，自动改指向这本书的真实目录，避免再次生成 `flat_<id>`。
- 迁移新增步骤 ②b：收养「无 `meta.json`、但直接放 `source.<ext>`」的旧式目录；
  若该 id 已有正规书目录，则并入而不是另建副本。
- `library_check` 报告新增 `legacyDirs`，设置页自检会显示「旧式目录」异常项。

### 前端（`Reader.tsx` / `App.tsx`）

- 新增 `bookPaths` 状态与 `ensureBookPaths()`，所有书目录/正文路径一次性向后端解析。
- 编辑入口、锻造索引、EPUB 编辑面板、工作副本全部改用后端路径；
  删除 `libraryDir` 拼接逻辑（`Reader` 不再接收该 prop）。
- 进入编辑前先 `await ensureBookPaths()`，避免面板拿到空路径静默不渲染。

## 五、防御结论

改名类改动的安全边界从「UI 记得改」变成三层兜底：

1. **路径唯一来源**：前端只能问 `book_paths`，禁止拼「根 + id」；
2. **读写双向自愈**：读命令 `resolve_existing_source`、写命令 `resolve_library_write_path`；
3. **迁移自动收养 + 自检暴露**：启动时收养旧式目录，`library_check` 用 `legacyDirs` 长期盯着。
