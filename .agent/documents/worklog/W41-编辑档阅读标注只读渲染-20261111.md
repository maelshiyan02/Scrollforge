## 一、目标

S8 分两块：三态视图（W36 已完成）与「阅读标注在编辑档渲染」。本轮补后者：

1. 富文本视图显示阅读层的高亮与笔记（只读），正文仍可正常编辑；
2. 源码视图不显示任何标注；
3. 删掉被标注的文字后，标注随之消失（不残留错位高亮）；
4. 分屏对照的富文本侧同样可见标注。

划词译文不需要新渲染：W24/W25 已把阅读草稿铺进对应段落，编辑档里可直接改，属「可见且可编辑」。

## 二、实现

新增 `app/src/lib/annotation-marks.ts`：

- `sameChapterHref`：`anchor.href` 是包内相对路径（如 `EPUB/ch_0053.xhtml`），`currentFile.relPath` 是 ZIP 内完整路径，按后缀对齐，忽略大小写、反斜杠与 URL 转义。
- `collectChars`：`TreeWalker` 按文本节点收集可见字符，跳过 `.blk-img`（`［图片］` / `［图形］` 占位 span），否则图片之后的字符区间整体偏移。
- `buildRange`：把 `anchor.range`（归一化区间）经 `normalizedWithMap` 的 map 还原成原始下标，再生成 DOM `Range`。
- `collectChapterMarks`：按 `blockIndex` 分组；只有当前块文本 hash 与 `anchor.textHash` 一致才画，`partial` / `orphan` 交给阅读端待复核，避免错位高亮。
- `applyChapterMarks` / `clearChapterMarks`：用 CSS Custom Highlight API 注册
  `sf-ann-<色值>`（高亮底色）与 `sf-ann-note`（笔记下划线），样式注入 `#sf-ann-highlight-style`。
  **不往 contentEditable 里插 DOM**，所以高亮不会被 `innerHTML` 带回章节 XHTML。

`app/src/lib/annotations.ts`：

- `normalizedWithMap` 由内部函数改为导出，编辑器复用同一套归一化口径。

`app/src/components/EpubEditPanel.tsx`：

- 新增 `annotations` 状态，进面板与换章时 `loadBookAnnotations(bookId)` 读一次（只读，不写壳）。
- 新增渲染 effect：`view !== 'source'` 且块已渲染时，在 `requestAnimationFrame` 里从 `.block-canvas` 收集并注册；源码视图与卸载时清空。
- 依赖 `[view, blocks, annotations, currentFile?.relPath]`：翻译、应用改动、撤销等导致块重建后会重画。

release 构建 + `--remote-debugging-port=9222`：

   `anchor{blockIndex:77, href:'EPUB/ch_0053.xhtml', range:{0,18}, textHash:'f406f9f4', state:'ok'}`（s8-04）。
2. 进编辑档默认富文本：`CSS.highlights` 注册 `sf-ann-f2cf66`，`::highlight` 样式为
   `background-color:#f2cf66`，84 个块，截图高亮位置与阅读端一致（s8-05）。
3. 切源码视图：注册表 `sf-ann-*` 为 0，`.blk-body` 为 0（s8-06）。
4. 切回富文本：高亮恢复。
5. 源码视图删掉该句并等 700ms 自动重建 → 回富文本 `keys=[]`，块 77 文本已不含该句，
   即「删文字连带标注消失」（s8-07）。该改动只走 dirty 通道，未点保存，磁盘字节未变。
6. 结束进程重开、再进编辑档：高亮仍在（读盘生效）。
7. 分屏对照：左侧富文本黄底、右侧源码无高亮（s8-08、s8-09）。

## 四、偏差与注意

- 只画 hash 完全一致的标注；`partial` 不在编辑档画（阅读端已标「部分失效」），避免误导。
- CSS Custom Highlight API 需要 WebView2 对应 Chromium 105+；不支持时静默不画，编辑功能不受影响。
- 源码视图的删除要等「保存」才落盘；「应用改动」只提交富文本 `blockEdits`，源码改动时该按钮不可用。
- 切到源码视图只清注册表与样式，不删 `#sf-ann-highlight-style` 节点。
