## 一、目标

编辑器从「改段落 / 改目录」扩展到「改文件」：新建章节、重命名、删除、移动，并保证 EPUB 结构自洽——同步 OPF manifest / spine、nav.xhtml、toc.ncx 与书内相对链接；操作前先显示影响面。

验收：新建章节能出现在目录结构与阅读章节列表；重命名后无断链；删除后 `edit_validate` 通过；每次操作后保存产生 revision。

## 二、实现

### Rust `app/src-tauri/src/epub_edit.rs`

新增 `FileImpact` / `FileOpResult` 与「文件级操作」小节：

- `file_impact(edit_dir, opf_rel, rel_path)`：判断 manifest / spine / toc 是否引用，并统计其他文本文件中 `href/src` 解析后命中该文件的次数与文件列表。
- `create_chapter(edit_dir, opf_rel, rel_path, title)`：
  - 校验路径与扩展名，生成 XHTML 模板（XML 声明 + `<html xmlns:epub>` + `<h1>`；若 manifest 有 CSS，按新文件目录写入相对 `<link>`）；
  - 生成唯一 manifest id（`ch_<stem>`，冲突追加序号），在 `</manifest>` 前插 `<item>`、`</spine>` 前插 `<itemref>`；
  - `read_toc` 根级追加节点 → `write_toc(..., true)` 同步 nav/ncx 与 spine 顺序；
  - `rebuild_index` 重建 `_index.json`。
- `delete_file(edit_dir, opf_rel, rel_path)`：
  - 保护 `mimetype`、`META-INF/*`、OPF、nav、ncx；
  - 先删目录项并 `write_toc(..., false)`（此时 manifest 仍完整，nav/ncx 能找到）；
  - 再删 manifest 命中项并按其 id 删 spine `itemref`；
  - 删除磁盘文件后，遍历其他文本文件，整段移除指向它的 `href/src` 属性；
  - `rebuild_index`。
- `rebase_links(raw, old_dir, new_dir)`：**移动文件自身**跨目录时，把它的 CSS/图片/锚点相对链接按新目录重算（原来只改写「指向被移动文件的链接」，会漏掉文件内部的相对链接）。
- 移动不新增命令，复用 `rename_file`（传跨目录 `to_path`）。

### Rust `app/src-tauri/src/main.rs`

新增并注册：`edit_file_impact`、`edit_create_chapter`、`edit_delete_file`。

### 前端 `app/src/components/EpubEditPanel.tsx`

- 文件树头部新增四个按钮：新建章节、重命名、移动、删除；目标为当前打开文件。
- 新建默认落在当前文件所在目录（`<dir>/chapter-new.xhtml`），可改标题。
- 重命名 / 移动 / 删除执行前先调 `edit_file_impact`，弹出影响面面板：manifest、spine、目录、书内链接 N 处（列出前 4 个文件），确认后才执行。
- `refreshFiles(focus?)` 并行刷新文件列表与目录；新建/移动后重开目标文件，删除后清空当前文件。
- 当前文件有未保存改动（`dirty || blockDirty`）时拒绝文件级操作，提示先保存。

`app/src/styles.css`：新增 `.edit-panel__tree-tools`、`.file-op-form`、`.file-op-impact*`。

## 四、偏差与注意

- 文件操作只改工作副本 `edit/`，不立即写母本；revision 由随后的「保存并重打包」产生，不是每次点击自动快照。
- 模板里的 CSS 链接使用 `opf_items` 已解析的包内路径，不要再 `resolve_href` 二次拼接（否则会出现 `EPUB/EPUB/...` 断链）。
- 删除按「目录 → manifest/spine → 文件 → 其他文本链接」的顺序执行；顺序反了会让 `read_toc` 找不到 nav/ncx。
- 不删除 `mimetype`、`META-INF/*`、OPF、nav、ncx；这类文件前端仍显示，但删除会被后端拒绝。
