## 一、目标

在 S10「只写译文工程」的基础上，把锻造的「整章对照」从单滚动的成对行升级为真正的左右分屏：

- 左右两栏各自滚动，可按段落序号（blockIndex）互相定位，滚动联动误差 ≤ 1 段。
- 切换章节时两侧同步回到同一章、同一段。
- 未译段落可一键定位；母本被编辑后产生错位的段落标「漂移」。

验收：滚动联动误差 ≤ 1 段；切换章节两侧同步；未译段落可一键定位。

## 二、实现

### `app/src/components/ForgePanel.tsx`

- 整章视图由 `.forge-pairs`（单一滚动容器、逐行成对）改为 `.forge-split`：左「原文」、右「译文」两个独立滚动面板，每段一个 `data-block-index` 块。
- 新增按段联动：
  - `blockOffset(el, pane)`：块顶边换算成滚动偏移。
  - `topBlockIndex(blocks, pane)`：找当前贴顶的段落序号（按段，不做高度比例换算）。
  - `syncChapterScroll(from)`：一侧滚动时把另一侧滚到同一段的偏移；触顶/触底直接对齐端点，避免两侧内容高度不同在尾部差出多段。`syncingRef` + `requestAnimationFrame` 防回声。
- 新增「滚动联动」开关：关闭后两栏完全独立滚动（`aria-label="滚动联动开关"`）。
- 新增「定位下一处未译」按钮：从当前段往后找、绕回开头，跳不过就提示「本章没有未译段落」。
- 新增定位 effect：依赖 `[chapterView, chapterIndex, locateToken]`，切章 / 切整章视图 / 点未译清单 / 点段落列表时，两栏一起滚到目标段；输入时不抢滚动。
- 切章时两栏一起回到章首并清空块引用表。
- 漂移标记：把 `forge-draft.json` 里的 `source` 镜像与当前母本段落逐段比对；不一致即漂移。面板头显示「漂移 N 段」，译文侧对应块标「漂移」徽标。
- 未译标记：译文侧每块标「译 / 待译」，章节头显示「已译 X / Y 段」。

### `app/src/styles.css`

- 删除 `.forge-pairs` / `.forge-pair*`，新增 `.forge-split*`（两栏 grid、`56vh` 独立滚动区、当前段高亮、空段占位）、`.badge-missing` / `.badge-drift`、`.forge-drift`。

## 四、双文档渲染评估

本轮只做段对双栏增强，不引入「母本 foliate 实例 + 译文 foliate 实例」的双文档渲染，原因：

- 现有分屏已能让原文与译文逐段同屏、双向定位，翻译工作流不缺能力；双 foliate 实例会多一份整书解包、渲染与内存占用（本书 435 章、3.9 MB，长书更明显）。
- 两套渲染的 CFI 不同源，仍要回落到 `href + blockIndex` 对齐，定位逻辑与当前按段对齐等价，收益主要是排版保真。
- 译文工程的每章 XHTML 已保留母本 head/CSS/图片，后续若需要在译文侧看真实排版，可先在分屏右侧切「译文预览」，再考虑整页双文档。

结论：S11 以段对双栏收口，双文档渲染留到有明确排版校对需求时再做。

## 五、偏差与注意

- 源文栏在短章节（内容不足一屏）时不产生滚动，此时「顶段」恒为 0 属于正常现象，不代表联动失败；验收需选长章节。
- 漂移检测依赖 `forge-draft.json` 的 `source` 镜像。若用户删除该文件，首次进入会按当前母本重建，漂移归零（属预期）。
- 漂移只提示不改数据；是否按新母本重排草稿留给后续「重新对齐」功能。
