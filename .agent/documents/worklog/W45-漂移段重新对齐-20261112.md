## 一、目标

母本被编辑过之后，`forge-draft.json` 里记录的旧原文与当前母本对不上（W44 的「漂移」）。本轮把已有译文按**当前段落结构**重新落位：

- 先给出差异预览（不变 / 位移 / 改写 / 新增 / 删除 / 孤儿译文），用户确认后才应用。
- 应用只写草稿层与译文工程，**母本一个字节都不动**。
- 原文一致的段落译文原样跟随（含位移）；被改写的段落保留译文并标「需校」；被删除段落的译文可选择保留到草稿孤儿区。
- 不引入 LCS 以外的依赖，不改变 `translation_save` 的落盘格式。

## 二、实现

### `app/src/lib/realign-drafts.ts`（新增）

- `buildRealignPlan({ mirror, chapters, edits })`：只读生成计划，不落盘。
  - 章节配对：标题一致优先 → 唯一标题兜底 → 同下标兜底；找不到则整章按「新增」处理。
  - 段落比对复用 `forge.ts` 的 `myers`（改为导出）；差异过大（超过 1500 编辑距离）时退化为按下标配对，保证仍能给出映射。
  - 同一段差异块内，旧段与新增段按顺序配对：相似度 ≥ 0.4 判为 `modified`，否则拆成一删一增。
  - 相似度：≤300 字的段落用 Levenshtein（`1 - 距离/最长长度`），长段落用字符二元组 Dice，避免中文长段的 O(n²)。
  - `moved`：原文一致但段落位置变化的数量；`changed = modified + added + removed + moved`。
  - 孤儿译文：被删段落且仍有译文/注释的条数。
- `finalizeRealign(plan, keepOrphans)`：
  - 新草稿：所有当前段落（含空段）按新下标重建 `source/kind`，带过来的 `target`；`modified` 且原本有译文的块加 `stale: true`。
  - 新覆盖层：译文/注释按新下标写回；`removed` 段落不再占位。
  - `keepOrphans=true` 时把被删段落的译文/注释写入 `doc.orphans`（仅草稿孤儿区，不写 `forge.json`）。

### `app/src/lib/forge-drafts.ts`

- `ForgeBlockDraft` 新增可选 `stale`（母本这段被改写过，译文需对校）；`ForgeDraftDoc` 新增可选 `orphans`。
- 导出 `forgeBlockKind(text)`，建草稿与重新对齐共用同一套标题/空段判定。
- `setForgeTarget` 在写入新译文时自动清除 `stale`——重新翻译/输入即视为已对校。

### `app/src/components/ForgePanel.tsx`

- 漂移计算从「当前章」升级为 `driftByChapter`（全书按章 `Map<index, Set<index>>`），派生 `driftTotal` 供入口使用；当前章徽标语义不变。
- 面板头在「漂移 N 段」旁新增「重新对齐 {driftTotal}」按钮；有孤儿时显示「孤儿译文 N」徽标（tooltip 预览前 8 条）。
- `saveDraft(source)`：把原 `commit` 里的 `translation_save + write_forge_state + setEdits` 抽成共用函数，普通保存与重新对齐复用同一落盘通道。
- `applyRealign(keepOrphans)`：写 `forge-draft.json` → 更新内存 `mirror` → `saveDraft(nextEdits)` 写译文工程与 `forge.json` → 关闭弹层并提示计数。
- Esc：弹层打开时优先关弹层（应用进行中不响应），不再直接关面板。
- 段落列表与整章分屏译文侧新增「需校」徽标（`stale`），与「译/待译」「漂移」并存。

### `app/src/components/RealignDialog.tsx`（新增）与 `styles.css`

- 摘要 chip：不变 / 位移 / 改写 / 新增 / 删除 / 孤儿译文。
- 按章折叠，默认展开第一个有改动的章节；行内显示状态、`#旧 → #新`、旧/新原文摘要、带过来的译文摘要；改写行显示相似度；每章最多渲染 200 行。
- 「保留被删除段落的译文（N 条，存入草稿孤儿区备查）」勾选，默认保留。
- 底部「取消 / 应用对齐」，应用期间显示「正在写入译文工程…」并禁用按钮。
- 新增 `.realign-*`、`.badge-stale`、`.forge-stale` 样式。

## 四、偏差与注意

- **应用即写译文工程**：只改草稿会让 `forge.json` / `forge-draft.json` / `译文/` 三方错位（关掉再开可能重新漂移）。本轮选择「应用 = 对齐草稿 + 立即保存译文工程」，仍然不碰母本；普通保存通道不变。
- **孤儿译文只进草稿**：`forge.json` 不保留已删除段落的键，避免下次保存又把它们当成当前段落；需要找回时看 `forge-draft.json → orphans` 或面板头 tooltip。
- **改写段落的译文可能过期**：`modified` 只保证位置与段落归属，语义是否仍成立要人工看「需校」；用户重新输入译文后 `stale` 自动清除。
- **阈值是启发式**：相似度 < 0.4 的改写会被拆成「删除 + 新增」，译文进入孤儿区而不是硬套到新段落；这是有意的保守策略。
- **章节级变动**：只按标题/下标配对；整章被删除时其译文不会迁移到别的章（会作为未配对旧章忽略），整章新增时全部按「新增」处理。
- **TXT 母本未实测**：书库仍只有 EPUB 书；逻辑只依赖 `analysis.chapters`，与格式无关。
