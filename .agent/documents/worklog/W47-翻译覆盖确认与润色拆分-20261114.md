## 一、目标

1. **翻译覆盖确认**：已有译文时不再静默覆盖，一个批次只问一次。
2. **润色拆两个按钮**：`润色所选` 只处理选区里有译文的段落，新增 `润色本章`；两者共用进度、取消、撤销与失败统计。

## 二、实现

- 判定口径：`draft[editKey(chapterIndex, index)]?.translate?.trim()` 非空即「已有译文」，以草稿为唯一真相。
- `ForgePanel`：`译所选` / `译本章` 先算 targets，再统计其中已有译文条数；0 条直接翻译，否则把 scope、章号、targets、translated 存入 `overwriteAsk`。
- 新组件 `app/src/components/TranslateConfirmDialog.tsx`：沿用 `modal-mask` + `check-head` + `modal-actions`，三个动作「全部重译并覆盖 / 跳过已有只译未译 N 段 / 取消」；Esc 与点遮罩关闭；全部已译时跳过按钮禁用。
- `resolveOverwrite(mode)` 过滤 targets 后仍走原 `translateMany`；百度两档继续走 `translateBaiduBlocks`，整章一次批量请求。
- `polishSelected` 的循环抽成 `polishMany(targets, label)`，进度 / 取消 / `applyTranslation` 撤销 / 失败计数共用；`polishSelected` 与 `polishChapter` 只是目标集合不同。
- 无目标时分别提示「所选段落还没有译文…」「本章还没有译文…」；`translating` / `polishing` 期间四个按钮互斥禁用；`polishOne` 的中文错误拼进完成提示，不吞掉。
- 样式：新增 `.forge-overwrite { width: 470px; overflow-x: hidden }`，仍放在 `.realign-modal` 之前。
- 实测发现并修：`.forge-confirm` 与既有「未保存改动确认条」类名冲突 → 改名 `.forge-overwrite`；弹层横向滚动条；提示里的 `Error:` 前缀与 0 成功仍提示 Ctrl+Z。
