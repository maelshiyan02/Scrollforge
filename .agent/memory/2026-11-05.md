# 2026-11-05

## FIX：两个使用痛点（锻造 EPUB 可用 + 书架封面自检）

- 现象：
  - EPUB 进阅读器后「锻造」按钮灰化，翻译链路无法测试。
  - 直接复制进书库的 6 卷《轮回第7次的反派千金》全是灰封面；`covers/` 里是 6 个 362B 的 `.xhtml` + 1 个多余 `cover.jpg`。
- 根因：
  - `parse_opf_spine` / `parse_opf_manifest` 只匹配 `Event::Start`，外部 EPUB 的自闭合 `<itemref/>`、`<item/>` 是 `Event::Empty` → spine/manifest 为空；另外 OPF 排在 `container.xml` 之前时顺序匹配漏解析。
  - 旧封面提取用字符串位置猜 `href`，命中的是 `id="cover-image"` 前面那个 item 的 `text/cover.xhtml`；扁平书库没有 `meta.json`，`save_cover` 还会写死 `cover.jpg` 并报错，留下孤儿。
  - 验证锻造面板时发现 `extract_plain_text` 用 `bytes[i] as char`，中文被拆成 latin-1 乱码。
- 修复：
  - 两个 OPF 解析器同时处理 `Start | Empty`；`unpack_epub` 解包后按 `opf_path` 补解析 manifest。
  - `extract_plain_text` 改为 `chars().next()` + `len_utf8()` 推进。
  - `extract_epub_cover` 重写：manifest 属性解析 + EPUB2 meta cover + XHTML `<img src>` 下钻 + 魔数嗅探。
  - 封面记录表：`valid_cover_file` / `find_cached_cover` / `ensure_flat_cover`，扁平书库统一 `sanitize(title).<ext>`。
  - `read_cover` 拒绝非图片字节；`save_cover` 只认真实图片且扁平书库不再写 `cover.jpg`。
  - 新增 `shelf_health`：启动 + 刷新书架共用，修封面 / 删非图片与无主文件 / 报告正文缺失。
  - 前端 `clearCoverCache` + `sniffMime`；`refreshLibrary` 先自检再列书架并 toast；锻造提示改 EPUB/TXT。
- 验收：`cargo check` / `npm run build` / `npm run tauri build` 全部通过；`cargo test`（forge 索引 chapters=10 blocks=4258 text_len=329697；6 卷封面全部 jpg）；CDP `forge.disabled=false`，锻造面板中文正常；书架 17/17 封面有图；`covers/` 只剩 6 个 jpg。
