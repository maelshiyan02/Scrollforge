# A07 · 踩坑与规则

> 上级索引：`../MEMORY.md` §0 底线 4/5 ｜ 相关：A02 环境、A06 构建
> 规则：只写**已复现或已解决**的坑，一句一条，格式「现象 → 根因 → 正确做法」。

**触发时机**：遇到怪现象、准备重复某个曾失败的操作、或自动化操作 GUI 之前。

## 1. 平台与环境

1. `cargo` / `rustc` 命令不存在 → 本机 Rust 装在 `D:\dev\rust`，不在 PATH → 每次构建前设 `CARGO_HOME`、`RUSTUP_HOME` 并把 `D:\dev\rust\cargo\bin` 加进 PATH。
2. 环境里没有 pnpm → 别写 pnpm 命令 → 一律用 `npm`。
3. PowerShell 5 不支持 `&&` / `||` → 用 `;` 或分步执行。
4. npm / git 把正常输出写到 stderr，PowerShell 会抛 `NativeCommandError` → 看到该类报错先看退出码与实际结果，不要当失败重试。

## 2. GUI 自动化（🔴 用户要求：不许抢前台）

5. `Start-Process` 启动的 Tauri/Electron 应用会随 shell job 被回收，进程消失 → 用 WMI 脱离：`Invoke-CimMethod -ClassName Win32_Process -MethodName Create`。
6. `SetForegroundWindow` 常无效，屏幕截图会抓到别的窗口 → 用 `PrintWindow(hwnd, hdc, 2)` 直接抓窗口内容。
7. Electron 应用（如 Koodo）`PrintWindow` 抓到全白 → GPU 合成导致，不要用它做视觉评估 → 改用官方截图或 UI 自动化树。
8. `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=<port>` 对 Tauri 无效：Wry 在创建 WebView2 环境时**显式设置了** additional browser args，环境变量被覆盖 → 要 CDP 只能在 `tauri.conf.json` 的 `app.windows[0]` 写 `additionalBrowserArgs`，然后重新构建；交付前删掉并重建（A06 §5）。
9. UIA 对 WebView2 iframe 子文档内的合成点击常不生效（脚注链接点了不弹窗） → 不要用 UIA 判功能缺失；改用 CDP `Input.dispatchMouseEvent` 在页面坐标系点击（见 §7）。
10. PowerShell 进程默认**非 DPI 感知**，本机 125% 缩放：`GetWindowRect` 返回缩小后的 1214×858，而 `PrintWindow` 实际只画了左上 ~80% → 看起来"右边书名没了、底部状态条没渲染"，纯属截图裁切假象 → 抓图脚本第一行 `SetProcessDPIAware()`，再看 `window=1518x1072 / client=1500x1025` 才是真尺寸。
11. WebView2/Chromium 的 UIA 树**懒建**：刚打开时 `FindFirst(Descendants, Name=...)` 返回 null，过一会儿或先遍历一次树就能找到 → 先遍历/重试再 `InvokePattern`；`InvokePattern.Invoke()` 可在后台点按钮，不需要前台焦点。
12. `tauri build` 期间若目标 exe 正在运行，`Copy-Item` 覆盖 `build/Scrollforge.exe` 会报"文件正由另一进程使用" → 先 `Stop-Process -Name scrollforge`，再复制；复制后用文件大小与时间戳确认确实换了新包。

## 3. 阅读器算法

13. TXT 章节"先按连续空行切段、再逐段匹配"的算法在中文公版书上不可靠：《红楼梦》章间正好 8 个空行 → 切成 123 段、每段仅 1 个标题 → 全部判废 → 退化成数字分块 → **必须逐行分类**（不做切段），并对纯数字标题做递增可信度校验。
14. 中文 TXT 常见硬换行（Gutenberg 等），若"每个非空行 = 一段"会排成碎片 → 必须做段落重排（按句读熔接 + 保留首行缩进）。
15. 竖排不是只改 CSS：`writing-mode` 一改，双页顺序、进度条方向、左右键语义、目录缩进都要一起反转，否则"看着别扭"。
16. foliate 的 `relocate.detail.fraction` 是**全书比例**（`SectionProgress` 按各节字节权重算），不是"当前页在章节内的位置"；测试书首屏显示 65%、第二章 100% 属于正常（ch1 占全书 65% 字节），不要当 bug 修。

## 4. 工程

17. 引入 foliate-js 必须保留其 LICENSE（MIT），并在 `src/vendor/foliate-js/` 内集中放置，便于日后整体替换。
18. 版本号必须在 `package.json` / `tauri.conf.json` / `Cargo.toml` 三处一致，否则 exe 属性与实际版本不符。
19. 删 foliate 的某个模块（如 `pdf.js`）会导致 `view.js` 里 `await import('./pdf.js')` 在 Vite 构建时报 `Could not resolve` → 必须留同路径占位文件（导出一个抛错函数），不能只删文件。
20. React 里 `useEffect(..., [])` 注册的事件回调拿到的是**首次渲染时的闭包**：进度保存这类依赖后续 state（书名）的逻辑必须走 `useRef`，否则条件永远不成立、静默失效（本次"进度记忆不生效"就是这么来的）。
21. 恢复进度的顺序：先读存档 → `init({lastLocation})` → **再**开启保存开关，否则恢复过程本身会立刻把旧进度覆盖成第一页。
22. 第三方库的英文报错（如 `File type not supported`）会直接透到界面 → 在 catch 里做中文映射，满足"界面全中文"的硬约束。

## 5. TXT 解析（Phase 1 新增）

23. 用"原始 `第X回` 行数"当验收基线会错：《hongloumeng.txt》原始像标题的行有 123 行，但其中 2 行是正文（`第四回中既將…`、`第二回了．你怎么…`）、1 行是重复标题，真实是 **120 回本** → 验收必须按解析出的回号序列查 1–N 无缺号，不要拿 grep 行数对账。
24. 公版书会把回目拆两行：`第三回` 一行、分隔线一行、`賈雨村夤緣复舊職　林黛玉拋父進京都` 一行 → 不合并就会出现一堆只有"第X回"的目录项；合并后正文起点要后移到回目之后。
25. 重复标题行（同一回标题紧挨着出现两次）被去重后，第二份标题会落进正文开头 → 建正文时要剥掉开头的空行、分隔线、与标题相同的行。
26. 纯数字标题做递增校验时，混合写法（`第一章` + `第1章`）会因重复值被判废 → 标记型标题（带章/回/卷）不走数字校验，只有裸数字标题才走。

## 6. Tauri / 自动化（Phase 1 新增）

27. 接 `tauri-plugin-dialog` 需要三处同改：`Cargo.toml` 加 `tauri-plugin-dialog = "2"`、`main.rs` 里 `.plugin(tauri_plugin_dialog::init())`、`capabilities/default.json` 加 `dialog:default`；少一处就报权限错误。
28. Windows 原生文件对话框在 UIA 里只暴露成 `Pane`（文件名框 id `1148` class `ComboBoxEx32`），没有 Value/Invoke 模式 → 自动化要用 Win32：给 `GetDlgItem(dlg,1148)` 发 `WM_SETTEXT`，再给 `GetDlgItem(dlg,1)` 发 `WM_COMMAND`（只设置内部 Edit 子窗口会被判空而取消）。**保存框例外**：`SetWindowText` 塞完整路径不会进入外壳模型，OK 仍被判空 → 保留应用给的默认文件名，直接点「保存(&S)」才生成文件。
29. PowerShell 里 `[IntPtr]$string` 会抛类型转换异常 → 用 `[IntPtr][long]$text`；进程重启后主窗口句柄会变，必须重新取，别缓存。
30. WebView2 的目录项同时存在 `ListItem`（只有 ScrollItem）和 `Button`（有 Invoke）两个 UIA 元素，按名字找会先命中 ListItem 导致"Unsupported Pattern" → 按 ControlType.Button 过滤再 Invoke；右键菜单没有可编程入口，只能人工点检。
31. 用内存 EPUB 渲染 TXT 时，`view.goTo()` 的 href 必须是资源表里的完整路径（`OEBPS/text/chNNNN.xhtml`），传 `text/chNNNN.xhtml` 会解析成 null，且 foliate 内部 catch 掉错误 → 表现为"点了目录没反应但不报错"。
32. 书架的视图状态类名不要用 `.grid` / `.list` 这种通用词，容易和布局类互相覆盖 → 统一 `view-grid` / `view-list` 前缀。

## 7. CDP 后台自动化与 EPUB 写出（Phase 2 新增）

33. Tauri 的远程调试只能靠配置开：`tauri.conf.json` → `app.windows[0].additionalBrowserArgs` 追加 `--remote-debugging-port=9333`，重新 `npm run tauri build` 后 `http://127.0.0.1:9333/json/list` 才有目标（环境变量无效，见第 8 条）。
34. 用 CDP 拖选文字：`Input.dispatchMouseEvent` 必须在 `mousePressed` 与每一步 `mouseMoved` 带 `buttons:1`，且分成多步移动，只在终点跳一次选区不会生成 → 封装成 `drag(from, to)` 复用。
35. CDP 点击 iframe 内的元素：坐标要用 `iframe.getBoundingClientRect() + 元素范围.getBoundingClientRect()` 换算到页面坐标；`document.elementFromPoint()` 命中 `FOLIATE-VIEW` 属正常（iframe 不可穿透），不代表点错。
36. 页面里 `window.__TAURI_INTERNALS__.invoke / ipc / postMessage` 都是 `writable:false, configurable:false` → 无法 monkey-patch 拦截 `plugin:dialog|open/save`；不要在这上面耗时，改用「书架 fixture + 默认文件名保存」。
37. Node 脚本里连了 WebSocket 后必须 `close()` 再 `process.exit(0)`，否则报 "unsettled top-level await" 并挂住（退出码 13）。
38. PowerShell 5 读无 BOM 的 UTF-8 脚本会按 ANSI 解码，中文按钮名变乱码、`FindButton` 全部找不到 → 保存脚本时用 `[IO.File]::WriteAllText($p, $t, (New-Object Text.UTF8Encoding($true)))` 写 BOM。
39. foliate 的临时 `foliate-view`（脚注）脱离文档时宽高为 0，分页器算不出栏宽、`load` 不触发 → 必须先在 `before-render` 阶段把它塞进有真实尺寸的容器；气泡用 `visibility:hidden` 保留尺寸，不要用条件渲染卸载。
40. 书籍正文在 iframe 里，`keydown` **不会**冒泡到顶层 `window` → 每个 `load` 到的 `doc` 各挂一份监听并转发给同一个处理函数，否则 Esc 在正文里失效。
41. 几 MB 的二进制别用 `Vec<u8>` 走 IPC（会被编成 JSON 数字数组膨胀数倍）→ 前端分块 `btoa` 转 base64，Rust 用 `base64` crate 解码；`btoa` 要按 0x8000 分块，避免参数上限。
42. EPUB 的 `mimetype` 必须是 ZIP **第一个**本地条目、`method=0`（store）、无 extra field，否则第三方阅读器直接判非法；`dcterms:modified` 必须 `YYYY-MM-DDTHH:MM:SSZ`（不带毫秒）。
43. 验收"产物合规"不能只看自家阅读器：用 Node 解 ZIP 自查结构，再用第三方（Thorium）实际打开，两者都过才算过。

## 8. 锻造写回与版本（Phase 3 新增）

44. 手工伪造书库测试数据时，`meta.json` 必须用 **camelCase**（`byteLen` / `importedAt` / `sourceName`），因为 `BookMeta` 带 `serde(rename_all = "camelCase")`；写成 snake_case 会让 `list_books` 整批反序列化失败，表现为书架空白且无报错。
45. 写回源文件的行号必须是**原文件绝对行号**：`stripGutenberg()` 裁掉头尾后要返回 `offset`，熔接段落时把 offset 加到每一行；漏加会让整章正文整体上移/下移，改写落到标题或邻段。
46. 保存后 Reader 会重载并统一提示"已回到上次位置"，正好覆盖"已写回源文件"提示 → 只在首次加载（`reloadToken === 0`）提示位置，重载路径保持静默。
47. 锻造台拿到新的 `analysis` 后如果再次执行"定位当前章节"，保存刷新会把用户拉回第一章 → 用一次性 `locatedRef`，定位只做一次。
48. 大文本 diff 不要直接对全量行跑 Myers：先裁掉公共前后缀，再对中段设编辑距离上限（1500），超限降级为整块删除/新增，否则几万行的书会卡住 UI。
49. 版本快照要存**保存前**的字节，不是保存后：`commit_forge` 先写 `revisions/<id>.source` 再覆盖 `source.txt`；回滚同样先给当前状态自动存档，回滚本身才可撤销。
50. 写回是"一段换一段"：段落行范围重叠时必须跳过并计数，宁可少改也不能写错位；改完用磁盘文件哈希与原始 fixture 对账，比只看界面更可靠。
51. WebView2 交付 exe 的后台抓图：WMI 启动 → 等 5 秒 → `GetWindowRect` + `PrintWindow(hwnd, hdc, 2)` 直接得书架画面（约 63 KB PNG），全程不抢前台；`Test-NetConnection 127.0.0.1 -Port 9333` 返回 `False` 才算调试端口已关闭。

## 9. 图标按钮与笔记常驻小字（2026-10-28 追加）

52. 分页模式下 iframe 的 `innerWidth` 是**整章宽**（实测 5760），`frameElement.getBoundingClientRect().left` 为负（实测 -480）；`range.getClientRects()` 的 left 是相对 iframe 视口 → 判断"这句是否在本页"必须换算成屏幕坐标再与 `window.innerWidth` 比，`rect.left < 0` 这种判断毫无意义。
53. 拿整段 `getClientRects()` 判可见性会误判跨页段落（左半屏在上一页，可见 200 多像素）→ 先在前 16 个字符里按文本节点精确定位**句子**，取该句 rect；可见宽度 `< min(rect.width, 240) × 0.5` 或句首屏幕 left < -8 就当作不在本页，不铺小字（翻过去再出现）。
54. 字体加载与分栏在 `load` 之后还会再变一次，`relocate` 不一定触发 → `load` 后补 500ms / 1400ms 两次重排，否则小字停在旧坐标（实测偏差 95px）。
55. 图标按钮化：`material-icons/iconfont/filled.css` + `.mi` 连字 + `Icon` 组件；按钮中文一律进 `data-tip`，同时必须给 `aria-label`——CDP 自动化只能靠 `aria-label` 点按钮，缺了就点不到。
56. 二级弹窗拖拽：PointerEvent + `transform: translate()` 累加位移，`pointermove`/`pointerup` 必须挂 `window`，挂在卡片上鼠标一移出就断；标题栏 `cursor: grab` 让用户知道能拖。

## 10. 3D 书架与 EPUB 封面（2026-10-28 追加）

57. CSS 3D 书脊"点不到"的根因是父容器 `transform-style: preserve-3d`：命中测试只返回容器本身，`elementFromPoint` / CDP hover 全部落到 `.rack-books`。去掉 `preserve-3d`（保持 `flat`），把 `perspective` 直接写在**书脊的直接父级**上，子元素才既能有透视形变、又能正常命中。
58. `perspective` 放在更外层容器（如 `.shelf3d`）不生效：书脊是孙元素且父级是 `flat`，不构成 3D 渲染上下文，视觉上就是平面矩形。判断标准是"斜边梯形 vs 直边矩形"。
59. 书脊与木板之间出现缝隙，多是给 `.rack-books` 加了 `padding-bottom`；容器贴底靠 `align-items: flex-end` + `padding: 0 30px`，不要用底部内边距。
60. 竖排书脊 `writing-mode: vertical-rl + text-orientation: upright` 长书名会被硬裁成半个字，必须在前端先截断（14 字 + `…`），完整名放悬停气泡。
61. CDP 后台验收坐标直接用 `getBoundingClientRect()` 的 CSS px 即可，`Input.dispatchMouseEvent` 不收截图像素；按 `innerWidth / screen.width` 换算会点到旁边木板。

## 11. 双存储模式与 EPUB 打开（2026-10-28 v0.6.0 追加）

62. 打开 EPUB 全是乱码，根因是判断格式用了 `/\.epub$/i.test(meta.format)`，而 `meta.format` 存的是 `"epub"`（没有点），正则永不命中 → 掉进 TXT 分支把二进制解码成乱码。格式判断只做字符串比较（`format === 'epub'`），扩展名解析放在唯一的 `formatOf()` 里。
63. `foliate-view` 的 `renderer`（`FOLIATE-PAGINATOR`）用的是 `attachShadow({mode:'closed'})`，CDP 里 `shadowRoot` 恒为 null、`children` 为空 → 不能靠读 iframe 文本判断"书有没有渲染"，只能看 `view.lastLocation`（`section.current` / `cfi`）加截图。
64. EPUB 的 `sections[0]` 常是 `cover.xhtml`、`sections[1]` 是 `nav.xhtml`，`init({showTextStart:true})` 会停在 nav 目录页，用户误以为"没打开" → 初始化后检查 `lastLocation.section.current` 对应 section id，命中 `nav|toc|cover|titlepage` 就 `goTo(book.toc[0].href)` 跳到第一章；这条同时修复了"旧进度 CFI 指向 nav 页"的情况。`view.goTo(href)` 接受 href 字符串，不必先转 CFI。
65. `foliate` 的 `resources.manifest` 项**没有 `size` 字段**（只有 `href/id/mediaType/properties`）→ 彩页过滤不能按 manifest size 做前置过滤，必须 `loadBlob()` 之后按 `byteLength` 与 `naturalWidth/Height` 筛（本次阈值 24KB + 320px），否则一张都出不来。
66. 书架"一行装无限书"：滚动容器隐藏原生滚动条（`scrollbar-width:none`）后必须补鼠标拖拽（PointerEvent + `scrollLeft`）与左右按钮，否则只剩滚轮，用户以为不能滑。
67. CDP 合成 PointerEvent 拖拽验证前要确认 `viewport.scrollWidth > clientWidth`；书少时两者相等，拖了也不动，看起来像拖拽失效（本次 6 本书刚好 1349 vs 1156 才验证成功）。

## 12. 外部站点抓取与英文书脊（2026-10-28 v0.6.1 追加）

68. WordPress Madara 主题的章节目录是 JS 渲染的：页面源码里只有空的 `#manga-chapters-holder`，`admin-ajax.php`（`manga_get_chapters`）与 `/wp-json/` 都不返回章节列表 → 只能 headless CDP 等 `.wp-manga-chapter` 渲染后再读，别在 ajax 接口上反复试。
69. 同一站点的章节页往往服务端直出：`div.reading-content > div.text-left` 用 `requests` 就能拿全，不必逐章开浏览器；但要用 CDP 渲染一页对照首/末段确认没有 JS 补内容。
70. Python `zipfile` 写 EPUB 时，`writestr(ZipInfo(...))` 若不显式设 `compress_type = ZIP_STORED` 会按默认 DEFLATED 写，且默认带 extra → mimetype 两项都不合规；必须 `ZipInfo` + `ZIP_STORED` + `external_attr` 手动设，先写 mimetype 再写其余。
71. 打包时把所有条目统一加 `OEBPS/` 前缀会把 `META-INF/container.xml` 写成 `OEBPS/META-INF/...`，第三方阅读器直接打不开 → 路径要按 META-INF 与 OEBPS 分开拼；自检脚本第一件事就是验 `container.xml` 与它指向的 OPF 都存在。
72. 英文书脊"整行旋转但要能折列"：只给 `.spine-label` 设 `max-height` 时，`writing-mode: vertical-rl` 会把超长文本单列往下排、被父级 `overflow:hidden` 裁掉，永远不换行 → 必须再加 `height: calc(100% - 16px)`（定高才按行折列）、`max-height: none`、`white-space: normal`。
73. 前端算书脊容量不能按"字号×1.15"估英文字符：旋转 90° 后每字符平均前进约 0.62em，按 1.15em 算会把 40 多字符的书名误判为放不下而提前截断（本次 `looking-for-the-villainesss-contract-husband` 被截成 27 字）。

## 17. E1 EPUB 编辑器后端 API 适配（2026-10-30 追加）

107. **Rust 工具链损坏（rustup.exe 丢失）**：`rustup default stable` 更新超时被移走后，后台进程可能还在锁文件，表现为 `rustup.exe 拒绝访问`。最稳的修复是 `StopCommand` 停后台进程 → `Remove-Item -Recurse -Force` 删整个 `D:\dev\rust` → 重新 `Invoke-WebRequest win.rustup.rs/x86_64 -o rustup-init.exe` → 无交互安装。不要在坏掉的 toolchain 上跑 `rustup toolchain remove`，update-hashes 目录锁文件阻止它执行。
108. **zip crate 2.x `CompressionMethod::Deflated` 是 unit variant，不是 tuple**：`CompressionMethod::Deflated(6)` 编译报 E0618，改成 `CompressionMethod::Deflated` 即可（压缩级别由底层 flate2 默认处理，通常是 level 6）。这和 1.x 完全不同。
109. **zip crate 2.x 没有 `SimpleFileOptions`**：全部改成 `zip::write::FileOptions::<()>::default()`——因为 `FileOptions` 是泛型结构体 `FileOptions<'k, T: FileOptionExtension>`，编译器推断不出 T 时显式指定 `::<()>` 是最简洁的写法。
110. **quick-xml 0.31 `LocalName` 不是 `&[u8]`**：旧版直接 `local == b"manifest"`，0.31 里 `LocalName` 是零拷贝包装器，要用 `.as_ref()` 拿到底层字节切片再比较：`local.as_ref() == b"manifest"`。同样适用于 attribute key 的 `k.as_ref() == b"id"`。
111. **Windows 专用 `Command::creation_flags` 需要导入 trait**：加 `use std::os::windows::process::CommandExt;`，否则编译器报 "no method named creation_flags found"。CREATE_NO_WINDOW = 0x08000000。
112. **container.xml 别用 quick-xml serde::from_str**：`#[serde(rename = "rootfile@full-path")]` 这种嵌套属性标记在 quick-xml 0.31 的 serde 集成上不稳定——用手写正则提取 `full-path="xxx"` 更可控（10 行代码 vs 半小时调试）。OPF 有 40+ 行需要解析，container.xml 只有一行，正则是最优解。
113. **zip 2.x `file.crc32()` 直接返回 u32**：旧版返回 `Option<u32>` 要 `.unwrap_or(0)`，2.x 直接是 `u32`——`crc: file.crc32()` 就行。
114. **`std::time::UNIX_EPOCH` 不在 prelude**：必须显式 `use std::time::UNIX_EPOCH;`，否则 `duration_since(UNIX_EPOCH)` 报 "cannot find value UNIX_EPOCH in this scope"。

## 18. 构建链路与产物验证（2026-10-30 E1 开发中反复撞墙追加）

## 19. 书库存储模型重构（2026-10-30 用户明确要求）

120. **旧模型 `<id>/source.epub + meta.json + cover.jpg` 不适合用户**：数字 id 文件夹对人工不可读。新模型必须是**扁平目录 + 原名保留**：`local book repository/<书名原名.epub>` + `local book repository/covers/<slug>.jpg`。meta.json 改为放根目录聚合（一个文件管理所有书）或每本书旁边放 `<原名>.meta.json`。

## 20. 扁平书库模型的完整调用链（2026-10-30 反复撞墙，必须记录完整链路）

125. **扁平模型 vs 子文件夹模型的完整函数依赖链**：
   ```
   所有 invoke 命令（read_book / read_cover / edit_open_epub / open_book ...）
     → 先 find_book(app, id)
        → find_library_book(app, id)  ← 这里之前只走 book_dir(id)/meta.json
        → find_history_entry → entry.to_book()
     → book_source_path(app, book)   ← 这里之前只走 book_dir(id)/source.epub
     → cover_dir(app, id)            ← 这里之前也只走 book_dir(id)
   ```
   **扁平模型下 `list_library_books` 能扫出来书，但后续每个函数都找不到！** 必须让 find_library_book / book_source_path / cover_dir 全都优先 `list_library_books` 扫描结果，或直接用 `book.path`（扁平模型已存完整路径）。
126. **EPUB OPF 3.0 的 `meta name="cover" content="XXX"` 里 XXX 是 manifest item ID，不是文件名！** 正确两步解析：① `content` 拿到 item ID → ② 去 manifest 找 `id="XXX"` → 拿 `href="cover.jpg"` → ③ 拼 OPF 目录前缀（如 `EPUB/`）→ 才是 zip entry 完整路径。OPF 2.x 才是直接写文件名。**之前的代码拿 `content="cover-img"` 直接当 zip 路径找 → 永远找不到**。
127. **release 模式闪退排查**：双击 exe 闪退 = 看不到 stderr 日志。先用 `tauri dev` 或 release 版加 RUST_BACKTRACE=1 在 cmd 里跑看崩溃堆栈。常见闪退原因：① unwrap() 调用 panic ② zip 2.x `by_index()` 需 `mut` ③ PathBuf::from 非法路径 ④ 线程 spawn 里的 unwrap。
128. **🚨 黄金规则：每次改完必须自己跑一遍 dev 模式、自己截图验证后再交付。** 不能让用户做 QA。如果 dev 模式能跑但 release 闪退，优先检查 `tauri.conf.json` 的 resources 路径 + CSP + `panic=abort` 的 unwrap。
129. **Reader.tsx 里编辑面板路径硬编码**：`libraryDir/id/source.epub` 是子文件夹模型假设。扁平模型下要优先用 `source.meta.path`（已存完整路径），再 fallback 旧模型。类似地，App.tsx 里的 openLibraryBook / deleteBook / checkBook 也要统一走 `book.path`。
130. **🚨 严禁对 UTF-8 字符串做任意字节切片！** `s[100..400]` 这种硬编码范围如果恰好落在多字节字符（韩文 3 字节、中文 3 字节、emoji 4 字节）中间 → 立即 panic。安全做法：① 用 `match_indices` 返回的 idx（保证落在 ASCII pattern 起点）② 只切 `s[..idx]`（前缀完整安全）或 `s[idx..]`（后缀完整安全）③ 不要用 `idx - 300` 这种 arbitrary offset。
131. **前端 cover.ts 的 `if (!book.cover) return null` 是封面显示的死亡陷阱！** 扁平模型/历史模型下 book.cover 通常是 null，但后端 read_cover 里有 fallback（实时从 epub zip 解封面）。前端不能因为 cover 字段为空就放弃调用 invoke！否则后端所有 fallback 逻辑都是摆设。封面提取逻辑应该：① 永远调 read_cover ② 后端负责判断"磁盘有→读磁盘，没有→从源文件实时解"。
132. **调试封面显示问题的正确顺序**：① 先 `cargo test extract_epub_cover` 验证后端提取函数能返回真实图片字节 → ② 看前端 coverUrl() 是否真的调了 invoke（加 console.log 或断点）→ ③ 确认 Shelf 组件用了 coverUrl() 的返回值 → ④ 如果都对但还是不显示，检查 CSS 层叠/opacity/父容器 display:none。
133. **🚨 打包发布必须用 `tauri build`，绝对不能用 `cargo build --release`！** 前者会自动跑 vite build → 把 dist/ 前端资源内嵌到 exe → WebView2 用 asset protocol 加载本地资源。后者只编译 Rust，跳过前端打包 → WebView2 还在尝试 localhost:1420 → 打不开页面。这是 2026-10-30 反复撞墙的大坑。
134. **valid_id 函数只该用于校验书 ID（flat_xxx / hxxx 这种 ASCII-only），不该用于校验封面文件名！** 封面文件名已经过 sanitize_filename（过滤了路径穿越字符），且可能含中文/全角括号（如 `（韩）天下第一的爸爸.jpg`），valid_id 的 ASCII-only 规则会误杀。

139. **验证 GUI 的可靠手段：WebView2 开 CDP 端口。** 在 `tauri.conf.json` 的窗口配置里加 `"additionalBrowserArgs": "--remote-debugging-port=9222"`，之后用 `Scrollforge\.agent\cdp.js` 直接驱动页面：`shot` 截图 / `eval` 读 DOM 与计算样式 / `click`+`clickText` 用 CDP `Input.dispatchMouseEvent` 真实点击（React 需要真实事件，`el.click()` 无效）。**比 PostMessage 点窗口可靠得多**——PostMessage 在 WebView2 子窗口层级上经常打不中，且拿不到 DOM 证据。

141. **改前端的排查顺序**（本次省了大量往返）：① 在 exe 字节里查前端标记字符串（`[System.IO.File]::ReadAllBytes` + `Contains`）确认新前端真的进了产物 → ② 页面里插临时 DOM 探针读 `getBoundingClientRect` / `getComputedStyle` / `elementFromPoint` 判断元素是否存在、是否被裁切、是否被遮挡 → ③ 确认后立刻删探针。**不要靠猜截图**。
142. **设置面板从"模式切换"改为"切面并列"后，语义要一并调整：** 阅读历史与本地书库并存（各用各的文件夹），模式切换字段 `storageMode` 仅保留兼容，实际行为由 `keepOriginal`（无痕链接模式）决定；新增 `readingHistoryDir` / `finalExportDir` 两个字段，默认值由 Rust `default_dirs` 命令下发，前端保留兜底常量。三个文件夹在保存设置时都要 `create_dir_all`。
143. **悬浮说明（`[data-tip]::after`）被下层遮挡的两类根因：** ① 祖先容器 `overflow: hidden`（`.shelf-subbar`）会把向下浮出的说明裁掉 → 改 `overflow: visible` + `position: relative; z-index: 12`；② 靠右按钮的说明横向超出窗口右缘被裁 → 对 `.subbar-tools` / `.rack-head` 里的 `[data-tip]::after` 改成 `left:auto; right:0; transform: translateY(...)`。验证方式不是看截图猜，而是 `getComputedStyle(el,'::after')` 读 `opacity/top/zIndex` + 截图确认文字完整。
144. **🚨 3D 书架不要用 CSS `perspective` 做"整排透视"。** `perspective` 挂在超宽行容器上会产生鱼眼（本次实测同一排书脊投影宽度从 3px 到 108px）；挂到每本书的 `.book-slot` 上虽能救，但"书脊平面 + 90° 折进去的封面"两片拼起来仍然像硬贴的封面。**wenku8 的做法是轴测（斜二测）投影 + 仿射矩阵**：每本书 = 书脊面（`matrix(1, skew, 0, 1, 0, 0)`）+ 书页顶面（`matrix(1, skew, dx, dy, 0, 0)`）+ 斜退封面面（`matrix(dx, dy, 0, 1, 0, 0)`，`left=书脊宽`、`top=书脊宽*skew`），三面共享顶点 → 是实心书块。参考 `_reference_src/wenku8-flutter/lib/archive_wave.dart` 的 `ArchiveBoxDepthRender`（`_base` / `_coverTransform` / `_topPath`）与 `archive_shelf_geometry.dart` 的 `depthX=.66, depthY=-.30, spineFor, pitchFor, railY`。
145. **轴测书架的行距 = 书脊宽 + 小缝，封面靠后面的书遮挡**；这也是"只看到一排书脊、从缝里漏出封面"的关键。行距给到封面宽时才是"看封面"档（本次用 `margin-right: calc(var(--cover) * 0.34)`）。顶面 `dy` 别取太大：-0.22 时书页顶面会连成一片"奶油屋顶"，改到 -0.12 才像一条薄书页边。
146. **🚨 `.rack-viewport` 上 `setPointerCapture` 会把按钮的 click 一起吞掉。** 指针捕获后 click 的 target 变成捕获元素，React 收不到 `onClick` → 表现是"3D 书架点书没反应、抽书弹窗不出来"。正确做法：pointerdown 只记录起点不捕获，`pointermove` 超过 8px 判定为拖动后才 `setPointerCapture` 并平移 `scrollLeft`，拖动结束用时间戳抑制后续 click。
147. **书架要跟随窗口：别给 `.rack` 固定 `min(1240px,100%)` 或固定书高。** 用 `ResizeObserver` 量 `.rack-viewport`，`bookH = max(160, 视口高 * 0.8)`，书高/书宽/封面宽全部由它派生；`justify-content: flex-start` 让书从左侧起排（不满时右边留空更像真书架，居中会像"小窗口"）。
148. **CDP 验证新增两条命令**（`Scrollforge\.agent\cdp.js`）：`hover <选择器>` 只发 `mouseMoved`（验证 tooltip / `:hover`），`size <宽>x<高>` / `size-reset` 用 `Emulation.setDeviceMetricsOverride` 模拟窗口缩放（验证自适应，不动真实窗口）。PS 5 不支持 `&&`，多条命令用 `;` 分隔。

## 19. E2 元数据表单（2026-10-30 追加）

149. **Rust 结构体给前端用时必须逐个标 `#[serde(rename_all = "camelCase")]`。** `EditWorkspace` 标了、`OpfMetadata` 漏标 → 前端读 `metadata.coverImage` 恒为 `undefined`，元数据页明明书有封面却显示「暂无封面」，而 `cover_image` 在 JSON 里是 snake_case。字段名对不上时不会报错，只会静默为空——截图最容易看出这种"数据在但没显示"的问题。
150. **替换封面时不要改 manifest 的 href，直接覆盖原封面文件字节。** `cover.xhtml` 里通常写着 `<img src="cover.jpg">`，一旦把 href 改成 `cover.png`（换了格式时）就会：① 书内封面页引用失效；② 旧文件变成包里没人引用的孤儿。实测把 600×800 PNG 写进 `cover.jpg`（media-type 仍是 image/jpeg）后 epubcheck 依然 0 error，阅读器按内容识别正常显示。
151. **书架封面是内存 blob 缓存（`lib/cover.ts` 的 `cache`/`Map<book.id, url>`）。** 编辑并重打包后必须 `forgetCover(id)`，否则回到书架仍是旧封面——此时磁盘 `covers/<书名>.jpg` 已经是新图，容易误判成"封面抽取失败"。本次在 `Reader` 的 `onCommitted` 里调 `forgetCover(source.meta.id)` 后，回书架立刻刷新（实机截图 `shots/cdp-e2-after-cover.png`）。
152. **元数据写回与打包是两步，UI 必须讲清楚。** `edit_update_metadata` 只改工作副本里的 OPF 与封面文件；不点顶部「保存并重打包」（`edit_save`）就不会进 EPUB。表单下方保留这句提示文案，验收时也要分别核对"工作副本 OPF"与"zip 内 OPF"两份。
153. **CDP 改 React 受控 input 必须用原生 setter。** `el.value = x` 不会触发 `onChange`，要用 `Object.getOwnPropertyDescriptor(HTMLInputElement.prototype,'value').set.call(el,v)` + `el.dispatchEvent(new Event('input',{bubbles:true}))`。
154. **`toast` 只显示 2.8 秒**（`App.tsx` 的 `notify`）。验收 epubcheck 这类耗时操作要 400ms 高频轮询 `.toast`，2s 轮一次很容易"看起来没有任何提示"。
155. **本机构建必须显式给 Rust 环境变量**：`cargo` 不在默认 PATH。固定写法：
    ```powershell
    $env:PATH = "D:\dev\rust\cargo\bin;$env:PATH"
    $env:CARGO_HOME = "D:\dev\rust\cargo"
    $env:RUSTUP_HOME = "D:\dev\rust"   # 里面有 settings.toml / toolchains
    npx.cmd tauri build
    ```
    `RUSTUP_HOME` 指到 `D:\dev\rust\rustup` 会报 "could not choose a version of cargo / no default is configured"。
156. **实测会真改书库原文件，必须先备份。** `edit_save` 写回 `workspace.originPath`（书库里那本 EPUB），验收"改元数据 / 换封面"会直接覆盖用户的书。固定流程：先 `Copy-Item` 到 `.agent\tmp\` → 验收 → 字节还原 → 用 SHA256 核对与备份一致（本次 `cdp-e2-restored.png` 与改前截图哈希完全相同）。
157. **`edit-projects` 工作副本落在 `%LOCALAPPDATA%\scrollforge\edit-projects\<时间戳>\edit`**（书库外的书走这条），读磁盘 OPF 验证时要取最新时间戳目录，别拿上一轮的目录核对。




158. **nav 解析要把 `<a>` 搜索限制在嵌套 `<ol>` 之前**：`<li><span>分组</span><ol><li><a …` 里，直接 `find("<a")` 会抓到子项的链接，分组 label/href 全错。先定位嵌套 `<ol>` 起点，只在 head 区间找 `<a>/<span>`。
159. **ncx 的分组 navPoint 必须有 `<content src>`**：nav 侧分组是无 href 的 `<span>`，ncx 侧没有 content 就是非法结构。用「首个有 href 的后代」兜底，保证 nav / ncx 条目数一致。
160. **不要给 ncx 写 `playOrder`**：分组 navPoint 的 `content src` 与首个子项同目标，递增 playOrder 会让 epubcheck 报 12 条 `RSC-005: different playOrder values for navPoint that refer to same target`。原书就不写该属性（NCX 里它是可选的），去掉后报错归零。
161. **nav / ncx 结构自检不能死比 href**：nav 分组 href 为空、ncx 分组必有 src，硬比会永远报「结构不一致」。规则改为「两边都非空才比 href」。
162. **NAV-011 的成因常是「同一文件在目录里出现两次」**：spine 已按目录顺序重排后，重复目标的后一次出现必然「倒退」。验收目录插入功能时用**唯一目标**（本次用 `titlepage.xhtml`），否则 NAV-011 天然消不掉。
163. **`.toc-row` 的 `element.click()` 比坐标点击可靠**：目录行很长，第 40 行以后的 y 坐标早已超出视口（视口只有 820 CSS px），CDP 坐标点击会落空；React 的 onClick 认合成 click。
164. **受控 input / select 赋值必须先走原生 setter**：`Object.getOwnPropertyDescriptor(HTMLInputElement.prototype,'value').set.call(el,v)` 再 `dispatchEvent(new Event('input',{bubbles:true}))`，只改 `el.value` React 收不到。
165. **点工具栏按钮后要等一帧再取 DOM**：`+ 条目` 是 React 状态更新，紧跟其后 `querySelectorAll('.toc-row')` 拿到的还是旧列表（会把标题写到上一行）。加 `await sleep(250)` 并核对行数 = 旧数 + 1。
166. **书库外的书每次打开都会新建时间戳工作副本**（`edit-projects\<ts>\edit`），想拿干净样本就关掉编辑器重开，不必手工清目录；但 `edit_save` 仍会写回 `originPath`，改书前先备份。
167. **CDP 直接带参数启动会用 `openExternal` 把样本登记进书库**（library 模式会复制成 `library\<id>\`）。用缺陷样本做扫描验收后，记得删掉该书库目录并重启应用，否则书架会多一本 `scanfix`。

## 21. E3-UX 编辑器形态与目录交互（2026-10-30 追加）

168. **侧栏改全屏后仍会滚下层，问题不在 CSS 遮挡而在事件**：Reader 的 `window.addEventListener('wheel')` 用 `closest()` 排除浮层，漏了 `.edit-panel` 时滚轮会一路冒泡去翻页。任何「盖在阅读器上的层」都要加进这张排除表（`.edit-panel, .typo-panel, .toc-panel, .footnote-pop, .forge-panel`），面板内部滚动容器再加 `overscroll-behavior: contain`。
169. **全局类名撞车会让新组件莫名其妙错位**：编辑器目录列表复用了阅读器抽屉的 `.toc-list`，而后者的 `.toc-list button { display:block; width:100% }` 把 26px 的抓取/折叠按钮拉成 1150px，`.toc-main` 被压到 `width:0` 并推到 x=2343（视口外）。排查手法：量 `getBoundingClientRect().x/width` + `getComputedStyle().display`，一眼看出样式没命中或被他处覆盖；命名上按模块前缀隔离（`.toc-tree`）。
170. **「节点路径」与「父路径」是两个语义，别用一个 helper 兼**：`withSiblings(nodes,[0])` 想改第 0 个节点的兄弟表（= 根表），`withChildren(nodes,[0])` 想改第 0 个节点的子表。混用会让「第二层的上移/拖拽」静默作用到根层（数据看着没变）。拆成两个函数并让调用点各自显式。
171. **目录标题要「自动换行撑高」只能用 textarea + `field-sizing: content`**：`<input>` 永远单行；换成 `<textarea rows={1}>` 后加 `field-sizing:content; resize:none; overflow:hidden; min-height:calc(1.55em+6px)`，并拦 Enter 直接 blur，才能在字号放大或字数变多时自行长高（WebView2 是 Chromium 151，支持该属性）。注意它同时会让 `max-content` 宽度变大，必须配合 `flex:1 1 180px; min-width:0`，否则会把同行元素挤出容器。
172. **CDP 拖拽要发「连续多步 mouseMoved + buttons:1」**：一步从 A 跳到 B 时 `pointermove` 可能只触发一次且 `elementFromPoint` 命中错误行。`cdp.js drag` 已改为 10 步 50ms 间隔，并支持 `before/after`（按目标行上/下半区）。跨层级拖拽要断言 toast 文案，不要只看顺序没变。
173. **批量移动的「整块」判定在父级分组内做**：`batchShift` 先按 `parentKey` 把选中项分组，再在每组内按方向（上移升序 / 下移降序）逐项交换并维护 `flags`，否则选中的连续项会被拆散。实测 `1,2,3,4,5` 选 3、4 上移 → `1,3,4,2,5`。
174. **Ctrl+滚轮缩放要 `{passive:false}` + `preventDefault` + `stopPropagation`**：否则浏览器会同时缩放整页、事件还会冒泡去翻页。源码框 `wrap="off"` + `white-space:pre` 保证只横向滚；目录框用 CSS 变量 `--toc-font` 统一驱动整行字号，行高用 `em` 计算才会跟着长。
175. **每个标签页独立字号状态要在 effect 里重新挂**：`useEffect` 依赖 `[tab, currentFile?.relPath]`，切标签/换文件后 ref 指向新节点，旧监听会绑在已卸载的 DOM 上（表现为「刚进页面滚轮没反应」）。

## 22. E4 / E4-UX 阅读编辑定位与并排源码（2026-10-31 追加）

176. **foliate 的 `relocate` detail 里没有 `index`**！`view.js` 的 `#onRelocate` 产出的是 `{ ...progress, tocItem, pageItem, cfi, range }`，`progress` 只有 `fraction/size`。想拿当前章节索引必须 `view.renderer.getContents()`（分页模式返回 `[{ index, doc, overlayer }]`），取 `contents[0].index`。
177. **`book.sections[i]` 的字段是 `id` 不是 `href`**：`epub.js` 里 `return { id: item.href, load, size, cfi, linear, ... }`。写 `sections[i].href` 永远 undefined，表现为「自动定位没反应但面板正常打开」。另外 sections 经过 `.filter(s => s)`，索引可能与原始 spine 错位——始终用渲染器给的 index 去查同一个数组。
178. **阅读器 href 与编辑器 zip 路径要做「后缀匹配」**：阅读器给的是相对 OPF 的 `text/ch1.xhtml`，编辑器 `entry.path` 是 zip 内全路径 `EPUB/text/ch1.xhtml`。规则：先 `decodeURIComponent`，再 `path === href || path.endsWith('/' + href)`，最后用小写兜底。
179. **`body.children` 下标是阅读器与编辑器唯一稳定的段落锚点**：`range.startContainer` 上溯到 `parentNode === doc.body` 的那层，再 `Array.prototype.indexOf.call(doc.body.children, node)`。编辑器里同样用 `Array.from(body.children)` 拆块，两边索引才对得上。
180. **滚动定位不要用 `scrollIntoView`**：它会连带滚动外层容器/页面。在自有滚动容器里用 `el.getBoundingClientRect().top - container.getBoundingClientRect().top + container.scrollTop` 算偏移再赋值 `scrollTop`。
181. **并排源码的双向同步必须限定触发条件**：预览→源码走显式「应用到源码」；源码→预览用 700ms 防抖。若段落里有未应用改动（`blockDirty`）就跳过自动重建，否则 `setBlockVersion` 会把 `blockEdits` 清空、用户的段落改动凭空消失。手动重建入口单独留「刷新预览」并在有改动时 `confirm`。
182. **Ctrl+滚轮的字号要分容器独立**：段落预览 `blockFont`(11–34) 用 CSS 变量 `--blk-font` 驱动 `.blk-body`；并排源码框沿用 `srcFont`(9–28)；目录 `tocFont`(9–26)。三个 effect 的依赖都含 `[tab, currentFile?.relPath]`，否则切文件后监听失效。

## 23. E5 从零做书（2026-10-31 追加）

183. **`toc.ncx` 不要写 DOCTYPE**：`<!DOCTYPE ncx PUBLIC "-//NISO//DTD ncx 2005-1//EN" ...>` 在 EPUB 3.2 校验下会报 `OPF-073`（external DTD 不允许）。NCX 按规范不需要 DOCTYPE，删掉后 `book-zh/en/min` 三本全部 `0 errors`；历史 ConvertWizard 产物同样受益。
184. **原生「另存为」对话框 CDP 点不到**：必须 `WScript.Shell.AppActivate('另存为 EPUB')` 后 `System.Windows.Forms.SendKeys::SendWait`。中文文件名在 SendKeys 里不可靠，验收用 ASCII 名（如 `saved-as-test.epub`）；「文件名」框可直接输入完整路径实现另存到任意目录。
185. **手动派发 `input` 后 React 状态不是同步可见**：`new InputEvent('input',{bubbles:true})` 能触发 `contenteditable` 的 `onInput`，但 `块脏标记 / 按钮 disabled` 要等一帧再断言（实测 300ms 后 `应用到源码` 才由 disabled 变可用）。
186. **`buildEpub` 每章只有一个 `<section>` 块**：章节正文全部包在 `<section epub:type="chapter">` 里，编辑器段落视图只拆出 1 个块。要按段落定位就得改成不包 section（或让 `epub:type` 放在 `<body>`）；当前 E5 验收不要求段落粒度，但 E4 的「滚到当前段落块」在新书里恒为第 0 块。
187. **前端 store 与 Rust deflate 会导致同书两种体积**：`buildEpub` 用 `zip-store`（不压缩），`edit_save` 重打包走 deflate，所以「生成 6,485 B → 另存 4,160 B」是正常现象。验收只比结构（章节数、OPF、epubcheck），不要比字节数。

## 26. R3 新建书向导树形结构（2026-10-31 追加）

203. **Tauri 的原生打开/保存对话框不会出现在 UIA 顶层窗口列表。** 它是主窗口内的子窗口（`ClassName = '#32770'`）；必须用 UIA 在主窗口 `Descendants` 里找 `ControlType.Window` 且 `ClassName -eq '#32770'` 的元素，再在对话框内部找控件。`Get-Process | MainWindowTitle` 和 `RootElement.Children` 都看不到它。
204. **原生对话框文件名控件与按钮的 UIA 事实**：打开对话框文件名 `AutomationId=1148`，保存对话框是 `1001`；两者 `ControlType` 都是 `Pane`、`ClassName=Edit`。按钮也是 `ControlType.Pane`（不是 Button）、`ClassName=Button`，Name 为「打开(O)」「保存(S)」「取消(S 或空)」。`ValuePattern` / `SetFocus` 常报 "cannot receive focus"，`InvokePattern` 也常不可用。
205. **自动化原生对话框的稳定写法**：文件名用 `SendMessage(hwnd, WM_SETTEXT 0x000C, 0, 完整路径)`；按钮先按 Name 前缀匹配（`-like '保存(*'`，避免命中「保存类型:」标签），再对按钮 `NativeWindowHandle` 发 `BM_CLICK (0x00F5)`。保存对话框默认目录是 `final export`、默认文件名是书名，直接写完整路径即可落盘到任意位置。
206. **NCX 里同一 target 出现不同 playOrder 会报 `RSC-005`。** 分组节点没有自有页面，若直接指向首个子页就与子项 target 重复；解法是给分组 `content src` 加唯一 fragment（`首子页#sf-gN`），并在该页正文里写 `<span id="sf-gN">`。fragment 必须真实存在，否则报 `RSC-012`。
207. **分组锚点要在构造 nav 之前预分配。** 前置/后置页是在 link 树之后才渲染的，锚点若在渲染阶段才登记就会丢；`epub-writer.ts` 用 `extraPageAnchors: Map<string,string[]>` 先收集再统一写入每页。
208. **向导里用 CDP 坐标点击按钮会误触外层遮罩。** `.wizard-mask` 覆盖全屏，`scrollIntoView` 后按钮落到 y≈54，点击命中遮罩直接 `onClose`，整份草稿丢失。改用页面内 `el.click()` 驱动 React（click 事件有效），输入框用原生 `value` setter + `input` 事件；拖拽仍用 CDP，但必须先确认源/目标都在可视区。
209. **拆分按钮的 tooltip 是「从中间拆成两章」**，用 `includes('拆分')` 找不到；自动化按 `includes('拆成')` 定位。合并只允许两个无子项、非分卷的章节；降级最多到第三层（`depth >= 2` 拒绝）。
210. **epubcheck 用内置 JRE 直接跑**：`resources\runtime\bin\java.exe -jar resources\epubcheck\epubcheck.jar <epub>`。GUI 生成件 20,517 B 实测 `0 fatals / 0 errors / 0 warnings`；目录跳转验收要在阅读器里重新打开目录面板（点击条目后面板自动关闭）。

## 30. R7 翻译（2026-11-02 追加）

231. **专名占位符的编号必须与还原用的数据结构对齐。** `maskProperNouns` 若只把「命中术语」push 进数组，而 token 编号是全部专名的排序序号，`masks[tokens-1]` 会越界，表现为「专名 0/5」。正确做法是每个掩码记 `{ token, no, target, source }`，还原时 `new Map(masks.map(m => [m.no, m]))` 按编号取；不要把数组下标当编号。
232. **同一专名在段落里出现多次时，还原次数会大于占位符数**（出现「专名 6/5」这类假象）。统计成功数用 `Set<number>` 去重，或直接按「已还原的唯一 token 数 / 掩码总数」展示。
233. **`.feature-text` 已是功能卡容器类名，不能再给 `<input>` 用。** R6 的功能注册表把卡片叫 `.feature-text`，R7 文本设置输入框若同名，会被卡片布局的 `display/flex` 规则接管，输入框错位；文本输入统一用 `.feature-input`。
234. **history 模式的书没有 `source.txt`，`commit_forge` 会拒绝写回。** 译文/注释保存走的是书库副本路径；测试或临时书要先登记成本地书库书（`source.txt` + `meta.json`，`storage:"library"`），否则报「找不到这本书的源文件」。
235. **PowerShell `Set-Content -Encoding UTF8` 写出的 JSON 带 BOM，Rust `serde_json` 直接解析失败。** 表现是书库扫描不到刚登记的书（`meta.json` 存在但列表为空）。手写 JSON 用 `[System.IO.File]::WriteAllText(..., UTF8Encoding($false))`，或改用无 BOM 的编辑器写入；`history.json` 复位也要检查首字节不是 `EF-BB-BF`。
236. **OpenCC 在前端只引 `opencc-js/t2cn` 的 `Converter({ from:'tw', to:'cn' })`。** 繁→简必须在模型输出之后、占位符还原之前执行，才能保证「normalize 优先级高于模型输出」；不要把转换放在掩码之前，否则会改动术语表源文匹配。
237. **`Start-Process` 启动的 GUI 仍会随命令结束被回收，`dangerouslyDisableSandbox` 也不保证存活。** 需要验证窗口/截图时，把启动命令放在 `run_in_background` 的壳里并 `Start-Sleep` 持有（父命令存活期间子进程才在）；验证完再主动停掉后台壳。不要用「命令结束后再查进程」判断程序崩溃。
238. **在线失败回落的验收要真的关端口。** 把在线 baseUrl 指向未监听端口（如 18081），本地指向 mock（18082），结果徽标应出现「已回落本地」；只改设置不断端口无法证明回落路径。

## 31. E6 编辑深水区（2026-11-02 追加）

239. **epubcheck CLI 的 `--json` 必须后接「报告文件路径」再后接 EPUB**，不能直接 `--json book.epub`。后者会把 EPUB 当成 JSON 报告文件，epubcheck 直接报 "No file specified in the arguments."，stdout 空、`parse_epubcheck_json` 返回空、应用层 `edit_check` 就一直静默"假通过"——这条 bug 在 E1 上线以来一直潜伏，靠 E6 引入真实书端到端单测才暴露（修完后 epubcheck 单测耗时从 1.35s 变 8.85s 证明真跑了）。
240. **`sanitizeInline` 做 XML 合法性校验时不能用 `innerHTML` 序列化节点树**：`innerHTML` 输出 `<br>`（非自闭合）、保留 `&nbsp;`（XML 里不是预定义实体，XHTML 里虽然合法但 DOMParser 严格模式下会报错），任何含 `<br>` 的输入（包括纯文本粘贴换行自动插入的 `<br>`）都会让 `DOMParser.parseFromString(..., 'application/xhtml+xml')` 抛 "Unexpected closing tag … div != br"。正确做法：节点树处理完后用 `new XMLSerializer().serializeToString(node)` 序列化成合法 XML 再校验，空元素自闭合、`&nbsp;` 直接输出成字符本身。
241. **块级回写只改标签时（改 h2/h3 等标题级别），前端 payload 绝对不能带 `inner` 字段。** `EpubEditPanel.changeBlockTag` 旧实现 `setBlocks` 后还把 `host.innerHTML` 存进 `blockEdits.current[index]`，导致 payload 同时带 `{index, tag:'h2', inner:<原 innerHTML>}`——Rust `apply_block_edits` 看到有 `inner` 就会用它重写块内内容，即使 inner 与原字节相同，也会丢失块内原始的缩进 / 换行风格 / XML 实体写法等字节级细节。修复：只设 `setBlockDirty(true)`，不存 inner。验收时用 Playwright 断言"改标题级别时 payload 里只有 `tag`、没有 `inner`"来防止回退。

## 32. R6-UX 设置面板拖动缩放（2026-11-02 追加）

242. **CSS 里先写 `position: fixed` 又写 `position: relative` 会后者覆盖前者**，导致整个 float 元素从 fixed 视口定位变成 flow 内 relative 定位，位置完全错乱。**修复**：删掉多余的 relative——`position: fixed` 本身就是 positioned 上下文，子元素 `position: absolute` 也会相对它定位，不需要额外加 relative。
243. **拖动/缩放的 pointermove / pointerup 事件必须挂在 window 上**而不是元素上。因为拖动/缩放操作中鼠标可能跑出元素边界（尤其是 resize-handle 只有 16×16，拖角时鼠标经常跑出），如果只监听元素上的事件就会丢失 move/up，导致拖动卡死、缩放停不下来。**正确做法**：pointerdown 只在元素上（用 setPointerCapture 让元素即使被移除也能收到后续事件），move/up 统一挂 window。




## 33. 使用痛点修复：锻造 EPUB 与书架自检（2026-11-05 追加）

244. **quick-xml 的自闭合标签走 `Event::Empty`，只匹配 `Event::Start` 会漏。** 外部 EPUB 的 `<item …/>`、`<itemref …/>` 都是 Empty，导致 manifest/spine 解析为空、锻造按钮常年灰化；两个解析器必须写成 `Start(e) | Empty(e)`。另外 OPF 在 ZIP 中可能排在 `META-INF/container.xml` 之前，顺序匹配会漏，解包结束后必须按 `opf_path` 从磁盘再解析一次。
245. **封面不能靠字符串位置猜。** 旧实现 `match_indices("cover-image")` + `rfind("href=\"")` 会把前一个 item 的 `href`（常见是 `text/cover.xhtml`）当成封面；必须解析 manifest 的 id/href/properties，XHTML 封面再下钻 `<img src>`，最后用魔数（FFD8FF/89504E47/…）确认返回的真是图片。
246. **Rust 遍历 UTF-8 文本时 `bytes[i] as char` 会把中文拆成 latin-1 乱码**（`轮回` → `è½®å›ž`），且长度膨胀 3 倍。必须 `raw[i..].chars().next()` + `ch.len_utf8()` 推进；这类 bug 在只读长度、不读内容时完全看不出来，回归测试要断言中文标点或汉字存在。
247. **扁平书库（书直接放根目录）没有 `meta.json`，`write_cover_meta` 必然失败**，旧 `save_cover` 会先写 `cover.jpg` 再报错，留下孤儿文件。封面命名必须由书名推导（`sanitize(title).<真实扩展名>`），并用同一规则做复用/校验；`shelf_health` 负责按「引用集合 + 魔数」清理 `covers/`，且启动与刷新按钮共用这一个命令。
248. **截图工具的输入注入对 WebView2 无效。** `click.exe`（PostMessage）与 `mouse_event`（真实光标）在 Tauri 窗口上都点不动，滚动也无反应；GUI 交互验证必须用 CDP（临时 `additionalBrowserArgs="--remote-debugging-port=9222"`，交付前删除并重新构建）。`Start-Process` 启动的子进程会随命令结束被回收，**启动 + CDP 调用 + 截图必须写在同一条命令里**。

## 34. 主题与 CSS（2026-11-07 W28 追加）

249. **React effect 的执行顺序是「子先父后」**：Reader 里的主题 effect 先于 App 根节点的 `applyTheme` 跑，此时读 `getComputedStyle(root)` 拿到的还是上一档的 CSS 变量 → 正文注入成旧色（切护眼显示白页、切日间显示深页）。**正确做法**：注入前先 `applyTheme(mode)` 把 `data-theme` 挂到根元素，再读令牌；不要依赖父组件 effect 的时序。
250. **foliate 分页器的页面四周铺底色只在章节载入时写一次**，且 `renderer.shadowRoot` 是 `mode:'closed'`，外部无法改 `#background` → 切档后正文换了色、页边仍是上一档（常是黑边）。**正确做法**：给 vendor `paginator.js` 加最小补丁 `refreshBackground()`（只把 `getBackground(doc)` 重新赋给 `#background`，不触发重排），主题切换时调用；不做整体重载，避免丢阅读位置。
251. **`img { filter }` 选不中 `background-image` 实现的封面**：书架 `.cover` 是背景图，夜间降亮对它无效，封面在全暗界面里依然刺眼。**正确做法**：补 `.cover.has-art { filter: brightness(...) }`，并保留字号/裁切；凡是背景图渲染的图块都要单独列规则。
252. **WebView2 后台窗口截图可能返回旧合成帧**，表现为「截图与 DOM 状态/日志不一致」「主题像自己变了」。**正确做法**：截图前先用 CDP 断言 `document.documentElement.dataset.theme` 与 `body` 计算背景色符合预期，并显式逐档设置（`setTheme` 循环 + 断言）再截，不要依赖窗口激活或定时器。
253. **主题改造的漏网集中在三类**：① 用 `background-image` 画的元素（书封、纹理）；② 伪元素（`::before`/`::after` 的渐变、阴影、分隔线）；③ 第三方渲染区（iframe 内文档、PDF/CBZ canvas、代码高亮）。验收必须对这三类单独扫「白底/亮块」，只盯常规 DOM 的 `background-color` 会漏。

## 35. 自定义标题栏（2026-11-08 W29 追加）

254. **`decorations: false` 只是去掉原生标题栏，不会自动给窗口控制权限**：`core:default` 不包含 `minimize / toggle-maximize / close`，必须显式补 `core:window:allow-minimize`、`allow-toggle-maximize`、`allow-close`、`allow-is-maximized`、`allow-start-dragging`，否则点击按钮静默无效（CDP 侧表现为「点了但窗口没动」）。
255. **`data-tauri-drag-region` 只对事件直接命中的元素生效**：标题栏的空白占位（`.grow`）与品牌区必须各自挂属性，按钮/下拉/输入框**不能**挂，否则点击会变成拖窗口。双击最大化也要自己实现（`onDoubleClick` 里用 `closest('button, select, input, label, a')` 排除交互元素），不要指望原生行为。
256. **窗口按钮要贴窗口右边缘，必须把 header 的 `padding-right` 置 0**，按钮用 `height:100%` 撑满标题栏；最右侧按钮的 `data-tip` 气泡要改成 `left:auto; right:6px` 向左展开，否则提示被窗口边缘裁掉。
257. **阅读页按钮本来就多，加窗口按钮后窄窗会溢出**：在 `<1100px` 隐藏书名（`.bar .bookname { display:none }`）保住窗口按钮；验收时读 `header.scrollWidth <= header.clientWidth`，不要只看截图判断「没挤坏」。
258. **书架排序做成「模式 + 方向」双开关时，方向的默认值要按模式走**：最近阅读/导入时间默认降序，书名默认 A-Z 升序；切换模式时重置方向，方向本身单独持久化（`shelfSortOrder`），不要用一个布尔值套所有模式，否则「A-Z」会变成 Z-A。

## 37. 第二轮反馈 / C-D-E 实施（2026-11-08 W30 追加）

263. **`cargo test`（debug）在这个 Tauri 工程会链接失败**：报 MSVC 运行时 `LNK2005` 一类冲突（debug 配置与 Tauri 的 CRT 设置不一致），但 `npm run tauri build`（release）正常。**正确做法**：跑 Rust 单测用 `cargo test --release`；不要因为 debug 链接失败就判定测试代码有问题。
264. **contentEditable 的 React 受控 `innerHTML` 会导致每次按键光标跳回开头**：只要 `dangerouslySetInnerHTML` 的值随输入变化，React 就会重设 `innerHTML`。**正确做法**：输入内容写进 `useRef`（如 `insertHtmlRef`），渲染值只在「创建 / 撤销 / 写回」时更新，`onInput` 不再 setState 内容；普通段落继续沿用已有的 `blockEdits` ref 模式。
265. **Tauri 命令新增参数必须用 `Option<Vec<T>>`**，否则旧调用方（或前端漏传）会直接参数反序列化失败；前端统一传空数组（`inserts: []`）比依赖 `undefined` 更稳。
266. **往 XHTML 里插入块不能只拼 `<tag>inner</tag>`**：必须沿用所在行的缩进与换行风格，否则写回后缩进塌陷、diff 噪音大；插入是零长度区间 `(end,end)`，重叠校验用 `e > last_start`，等于边界不算重叠，不能写成 `>=`，否则「插在最后一段之后」会被误判。
267. **只用测试的包装函数要加 `#[cfg(test)]`**：`apply_block_edits` / `write_blocks` 在生产路径被 `_ex` / `_with_inserts` 取代后，仍在生产编译会产生 dead_code 警告；加 `#[cfg(test)]` 既保留测试可读性又清警告。
268. **内置 NLLB 只能翻译，不能润色**：把它当润色引擎会得到「再翻译一遍」的结果。`polishOne` 必须在 `backend=builtin && mode!=online` 时直接给出中文提示，要求用户切在线/本地 LLM。
269. **撤销栈在写回成功后必须清空**：`edit_write_blocks` 会改变块坐标（删除/新增后索引全变），旧快照恢复会把内容写到错的段上。写回成功回调里 `historyRef.current = { undo: [], redo: [] }`。
270. **`onKeyDown` 拦截 Ctrl+Z 要判断当前标签页**：源码视图的 textarea / 目录输入框有原生撤销，只有在段落视图统一接管（`if (tab !== 'blocks') return`），并 `preventDefault + stopPropagation`，否则会出现「原生撤销 + 快照撤销」双回退。
271. **块上移/下移用「交换内容」实现时，块的 id/class 不跟随移动**：若该块被目录/书内链接锚定，移动后锚点仍指原位置。产品上必须显式说明该取舍；需要锚点跟随时应改为在源码层交换整段区间（含属性）。

## 38. 第三轮反馈：对齐 / 漏缝 / 说明书（2026-11-09 W31 追加）

272. **flex 行里「文字靠左」不能只靠 `justify-content:flex-start` + `span{flex:1}`**：`flex:1` 只是把文字容器拉满，文字本身仍受按钮的 `text-align` / 居中影响，图标与文字的间距还会随文字长度浮动。**正确做法**：菜单项改 Grid `grid-template-columns: 18px minmax(0,1fr) auto`，图标列固定 18px，文字列 `min-width:0 + text-align:left + nowrap + ellipsis`，尾列（快捷键/语言）`justify-self:end`；弹层宽度要够（本轮 260px），否则长条目仍被省略号截断。
273. **sticky 栏「漏缝」的根因是宽度与 padding 不匹配，不是 z-index 不够**：sticky 搜索栏 / 底部操作条只有内容盒宽度时，父级左右 padding 会露出滚动内容；容器 `padding-top` 存在时内容还会从吸附栏上方透出。**正确做法**：滚动容器顶部 padding 归零（呼吸位交给第一个 `h2` 的 margin-top），吸附栏 `margin: 0 -<padding> 0` 负边距铺满整宽 + 实底 + 去圆角，底部栏再 `bottom:0` 贴住窗口底。
274. **整页覆盖层（说明书 / 设置）的 Esc 必须在 App 层用捕获阶段拦截**：只在覆盖层内监听会被阅读页的 Esc 退出书抢走语义。`window.addEventListener('keydown', handler, true)` 里判 `helpOpen || settingsOpen` → `preventDefault + stopPropagation`，并定好优先级（help 先于 settings）；关闭后回到打开它之前的页面，文案不要写成「返回主页」。
275. **非 DPI 感知进程的 `PrintWindow` 只截到窗口左上角**：2560×1440 @125% 缩放下，先 `SetWindowPos` 成 1000×690（虚拟坐标）再抓图，真实窗口是 1250×863，底栏整条被切掉，容易误判成「底栏没渲染」。**正确做法**：验收优先 CDP `Page.captureScreenshot`；必须系统级抓窗口时，先 `SetProcessDpiAwareness(2)` 再取 `GetWindowRect` 尺寸。
276. **验收需要 CDP 时临时加 `additionalBrowserArgs`，交付前必须移除并重建**：`--remote-debugging-port=9222` 留在 release 配置里等于给正式包开后门。流程固定为「加参数 → 构建 → CDP 验收 → 删参数 → 再构建 → 复制 exe → 确认 9222 无监听」。

## 39. 第四轮反馈：编辑器布局止血（2026-11-09 W32 追加）

277. **同一选择器在 CSS 文件后段重复声明会整体覆盖前段，浏览器不报任何警告**：本轮 `.edit-panel` 在 2430 行是 `position:absolute;inset:0`，5102 行的 D 阶段补丁又写 `position:relative`，后者生效，`inset:0` 静默失效，`flex:1;min-height:0` 整条高度链断掉，最终表现为「编辑面板只占上半、文件树没有滚动条、目录树滚轮无效、折叠分组面板跟着缩」四个看似无关的 bug。**正确做法**：改绝对定位浮层前先 `Grep` 同名选择器全部声明；排查「面板高度不对」时第一件事是 CDP 读 `getComputedStyle(el).position` 与 `el.getBoundingClientRect().height` 对照父容器，而不是先怀疑 flex 或滚动样式。
278. **`overflow:auto` 不滚动时先量 `clientHeight / scrollHeight`，不要先加滚动条样式**：本轮树看起来「没有滚动条」，实际是 `clientHeight = scrollHeight = 486`，父级高度由内容决定，压根没有可滚区间。父子都设 `min-height:0` 只是前提，父级必须有一个**确定高度**（`absolute;inset:0` 或 flex 分配），否则 `flex:1` 退化为内容高度。
279. **浮层底栏要按档位渲染，不要靠 `disabled` 复用**：`.read-bottom` 是 `main.stage` 的兄弟节点，编辑面板绝对定位只能盖住舞台，盖不住底栏；把阅读按钮改成 `disabled` 后仍然占位并露出「第 1 页 1/1」，用户会读成「阅读面板还残留在下面」。正确做法是同一条底栏按 `mode` 换内容，保持高度稳定，避免切档时舞台跳动。
280. **构建还没结束就复制 `target/release/scrollforge.exe`，会拿到上一轮带调试参数的旧包**：本轮 `npm run tauri build` 的后台任务尚未完成时就复制，产物时间戳恰好是上一次构建的时间，烟测出现「正式包仍监听 9222」的假警报。**正确做法**：等构建任务返回 `Finished` 再复制；交付前用二进制串校验（`[IO.File]::ReadAllBytes` + 查 `remote-debugging-port`），不要只看文件时间戳。

## 40. S2 文件树浮层抽屉（2026-11-09 W33 追加）

281. **同一节点上的多个 `window` keydown 监听互相 `stopPropagation` 无效**：本轮 `EpubEditPanel` 想用后注册的 Esc 监听拦截「回阅读档」，但 `Reader` 的监听更早注册在同一个 `window` 节点上，同节点的捕获/冒泡顺序按注册顺序执行，`stopPropagation` 只能阻止向其它节点传播，拦不住同节点后续监听。**正确做法**：把「先收浮层、再退档」的优先级收进唯一监听者（`Reader` 的 Esc 分支里判 `treeOpen → toggleTree(); return`），不要让子组件另起一个同事件监听来抢语义。
282. **`overflow-y:auto` 会隐含把 `overflow-x` 计算为 `auto`**：抽屉只写纵向滚动时，底部出现横向滚动条（内容哪怕只宽 1px）。**正确做法**：单轴滚动容器显式写 `overflow-x: hidden`；排查时量 `scrollWidth > clientWidth`。
283. **`absolute` 浮层要挂最近的 `position:relative` 祖先**：文件树抽屉改成 `absolute; inset-block` 后，若 `.edit-panel__body` 没设 `position:relative`，抽屉会以 `.edit-panel` 为包含块，向上盖住顶栏。新增浮层前先确认父级是否已有定位上下文。

## 41. 布局契约与 CDP 尺寸验证（2026-11-09 W35 追加）

284. **`stage` 不做 `overflow:hidden` 时，absolute 浮层可能压到底栏**：浮层写 `top:0;bottom:0` 看似贴舞台，但一旦尺寸/内容超出（例如内部 min-height 撑开），会画到舞台外。**规则**：三档舞台 `.stage` 必须 `position:relative + overflow:hidden`，浮层只用贴边定位；验证时量浮层 `getBoundingClientRect()` 与 stage 四边是否相等。
285. **单轴滚动容器要显式补 `scrollbar-gutter:stable`**：否则内容从「不满一屏」到「满一屏」时，滚动条出现会挤窄内容 12px，长目录/文件树会横向抖一下。契约：`flex:1; min-height:0; overflow-y:auto; overflow-x:hidden; overscroll-behavior:contain; scrollbar-gutter:stable`。
286. **CDP `Emulation.setDeviceMetricsOverride` 的 `size-reset` 不一定立即恢复真实窗口**：本轮 `size 836x700` 后执行 `size-reset`，`innerWidth/innerHeight` 仍是 836×700，后续量到编辑面板 600 而非 720。**规则**：尺寸实验结束后显式 `size 1200x820` 再截图/验收，或重启验证实例。

## 42. S8 编辑三态视图与分屏同步（2026-11-11 W36 追加）

287. **`edit_scan_blocks` 的 `start/innerStart/innerEnd/end` 是 UTF-8 字节偏移，不是 JS 字符串下标。** 直接 `text.slice(innerStart, innerEnd)` 在中文/韩文正文上会切到半个字符。前端必须用 `toCharSpans()` 一次性把一批字节偏移映射成字符下标（按 `codePointAt` 累计 1/2/3/4 字节），再做合成与光标换算。偏移都落在标签边界（ASCII）上，映射是精确的。
288. **富文本 → 源码镜像不要在每个 `onInput` 里 setState。** contentEditable 的 DOM 改动不经过 React，最稳的触发是 `MutationObserver` 监听 `.block-page`（`subtree + childList + characterData + attributes`），停顿 180ms 合成一次；打字、加粗、粘贴、翻译、删除、改标签全部自动覆盖，也不会每敲一个字重排整章。
289. **镜像文本与原文长度不同时，光标必须做偏移换算。** 合成时同时产出 `toDraft/toBase`（按编辑 op 的 `insert.length - (to - from)` 累加 delta），富文本段起点 → 源码光标用 `toDraft(innerStart)`，源码光标 → 原文偏移用 `toBase(selectionStart)`；只按原文区间找块会在插入点之后整体错位（实测 8 字）。
290. **textarea 的普通点击不一定触发 React 的 `onSelect`。** Chromium 里落光标不等于触发 `select` 事件，只挂 `onSelect` 会出现「点了源码但富文本不高亮」。同时挂 `onClick / onKeyUp`，并给「落在段间空白」的情况加兜底（归到前一个块）；验收要用真实 CDP 点击，不要只 `dispatchEvent('selectionchange')`。
291. **编辑工具条控件变多后要用 `flex-wrap` 而不是靠缩小。** 第二行新增三态按钮后，836 宽下「应用改动」会被裁到窗外（右沿 886 > 836）；`.block-bar` 改 `flex-wrap: wrap; gap: 6px 10px` 后自动换行（76px 两行），1200 宽仍是一行 46px。
292. **分屏双向滚动要用短锁。** 两个 `scroll` 监听互相赋值会打架；按 `scrollTop / (scrollHeight - clientHeight)` 设比例，并在每次程序化滚动后 `scrollLockRef = Date.now() + 60` 跳过对向的即时回声。光标定位触发的平滑滚动锁 150ms。

## 43. S5 书库命名迁移与索引（2026-11-11 W37 追加）

293. **`cargo build --release` 不等于发布包。** 没有 `tauri build` 传入的 production 配置时，二进制会按 `devUrl` 打开 `http://localhost:1420`，窗口显示「localhost 拒绝连接」，而不是内嵌的 `dist`。**规则**：所有要交付/验收的 exe 一律用 `npm run tauri build` 产出；`cargo build --release` 只用于快速确认后端能编过。
294. **旧扁平书库的 id 是按文件名算的，改文件名就换 id。** 根目录散装书每次 `list` 都按当前文件名重算 `flat_<hash>`，而 `flat_<hash>` 工作目录保留旧 id；迁移必须按「文件名的 hash」还原 id 再建目录，才能让修订/草稿重新对上。遗留工作目录里往往还有一份旧 `meta.json`（封面写入时生成），合并时目标已有 meta 会跳过它，导致源目录删不掉——需要先删源 meta 再合并（迁移步骤③）。
295. **目录改名要可重复执行。** `unique_book_dir` 必须做到「同 id 目录直接复用、同名冲突加 -2/-3」，否则第二次启动会把已经改好的目录再套一层；Windows 下 `fs::rename` 目标已存在会失败，不能用「先删再改」的粗暴路径。
296. **索引重建必须跳过没有正文的目录。** 否则一个只剩 `meta.json` 的遗留目录会被算成第 18 本书，出现「书架 17 / 索引 18」。规则：`source_in_dir(dir, format)` 为 `None` 的目录不进索引；`library_check` 单独把这类目录报成 `missingDirs`。
297. **指纹不必上 sha256。** 流式 FNV-1a 64 + 字节数足以发现正文被外部替换，且不增加依赖；把「导入时指纹」放 `meta.json`、「上次检查指纹」放索引，检查时对比索引值即可，避免每次启动哈希 300MB+ 的大书。

## 44. 书库改名后的路径契约（2026-11-11 W38 追加）

298. **书库路径只有一个来源：后端 `book_paths`。** 前端禁止用「书库根 + 书 id + source.epub」拼路径。目录命名规则（`<书名>__<短编号>`）属于数据层，UI 一旦自己拼，改名当天就会全部失效。规则：凡是需要书目录/正文绝对路径的地方，一律 `await invoke('book_paths', { id })`。
299. **改名类改动必须同时提供读写两侧的自愈。** 只修读路径不够：`save_epub` 这类写命令若按旧习惯写入 `<书库根>/<id>/working.epub`，会在书库里重新长出 `flat_<id>` 目录。读侧 `resolve_existing_source`、写侧 `resolve_library_write_path` 都要「父目录名当 id → 解析真实目录」。
300. **迁移要能收养「无 meta 的旧式目录」。** 旧版前端可能在任何时候写出 `<id>/source.<ext>`，且没有 `meta.json`。启动迁移步骤 ②b 负责收养并补 meta/指纹；若该 id 已有正规目录，直接并入，不要另建 `-2` 副本。`library_check` 的 `legacyDirs` 要长期暴露这类目录，归零才算干净。
301. **验收改名类改动，必须同时检查「界面能开」和「磁盘没长新垃圾」。** 本轮除了 CDP 打开编辑/锻造，还数了书库根 `flat_*` 目录为 0、`forge_edit` 落在真实书目录内，并用合成目录验证迁移收养。只看界面不报错，会漏掉静默重建旧目录的问题。





## 45. 阅读壳 sidecar 与锚点标注（2026-11-11 W39 追加）

302. **壳文件名必须固定，不能带书名。** 一旦用 `<书名>.标注.json`，书名或目录命名规则一改，读取端就找不到文件（与 W38 同一类坑）。规则：`阅读壳/` 下只认白名单固定名（`annotations.json` / `translate-drafts.json` / `reading.json` + `manifest.json`），书名只存进 `manifest.json` 做展示。
303. **壳文件读写一律走后端命令，且路径只看 `book_dir`。** `read_sidecar/write_sidecar/sidecar_info` 接收 `(id, name)`，不接收绝对路径；`name` 必须过白名单，既防路径穿越也防命名漂移。
304. **壳文件写盘必须原子写 + 盖章。** 先写 `.json.tmp` 再 `rename`；写前补 `schemaVersion/bookId/sourceFingerprint/updatedAt`，这样单个文件被单独拷走也能说明来路与对应母本版本。
305. **manifest 指纹要能省算。** 每次写标注都全量哈希母本会拖慢，规则：`sourceSize + sourceMtimeMs` 与旧 manifest 一致就复用 `sourceFingerprint`，只有母本真的变了才重算。
306. **读壳要容忍 BOM。** PowerShell `Set-Content -Encoding utf8`（Windows PowerShell 5.1）会写 UTF-8 BOM，`JSON.parse` 直接抛错，结果是「标注文件明明有内容但界面不显示」。规则：前端读取后先 `raw.replace(/^\uFEFF/, '')`；写测试文件用 `[IO.File]::WriteAllText(..., UTF8Encoding($false))`。
307. **异步读外壳数据后必须重新取 `renderer.getContents()`。** 组件挂载时捕获的 `contents` 在 `await invoke` 返回后可能已变化/为空，用它做锚点校验会静默漏校验（partial 不触发）。规则：`applyLoaded` 内部重新取 contents 再 `attachDocument`。
308. **单例 toast 会被后到的消息覆盖。** App 的 toast 是单例（约 2.8s），启动时「已回到上次位置」会盖掉同时发出的标注复核提示。规则：复核类提示延迟 1400ms 再发。
309. **旧壳文件要「读时收养 + 迁移收养 + 自检暴露」三层兜底。** 只做启动迁移不够：用户可能从旧版直接打开书。规则：`read_sidecar` 新路径缺失时把书根旧文件迁入并删旧；`library_check` 报 `legacySidecars`（书根遗留）与 `unknownSidecars`（`阅读壳/` 白名单外文件），两者归零才算干净。




## 46. 阅读撤销栈与标注面板（2026-11-11 W40 追加）

310. **撤销栈存快照，不存 diff。** 标注列表与译文草稿表体积小，`before/after` 各存整份快照，删除、改写、重做都能原样还原，省掉逐字段逆运算。代价必须用深度控制：内存 40 步、落盘 20 步。
311. **撤销必须同时还原数据与渲染。** 只把列表写回壳，页面覆盖层不会自己回来。规则：撤销标注时对比当前与目标列表，缺的 `addAnnotation`、多的 `deleteAnnotation`；撤销译文用 `replaceDrafts` 整表替换并触发 `scheduleAll`。
312. **键盘监听要覆盖 iframe。** 阅读正文在 closed shadow root 的 iframe 内，keydown 不冒泡到父窗口；只在 `window` 上挂 `Ctrl+Z` 会「有时灵有时不灵」。规则：`attachDocument` 里对每个 iframe doc 再挂一份，并用 ref 取最新处理器；`INPUT/TEXTAREA/SELECT/contentEditable` 直接 return，让给原生撤销。
313. **历史文件复用壳文件通道。** `history.json` 只需加入 `sidecar_file_names()` 白名单，manifest、旧壳收养、`library_check` 全部自动覆盖。不要为历史新开一条「任意文件名」的命令，否则白名单与路径防护形同虚设。
314. **分页 iframe 的 rect 不等于可见。** iframe 宽度可能远大于可视窗口（本次 7920px），`getClientRects()` 给出的是文档坐标，不能直接拿来判断「这句话在屏幕上」。规则：用父窗口 `innerWidth/innerHeight` 加 `frameElement.getBoundingClientRect()` 偏移做可见性判断；离屏选区的贴边译文不渲染（这也是本次「翻译成功但浮条不出现」的假象根因）。
315. **面板章标题依赖 TOC 异步加载。** `book.toc` 在书打开后才就绪，`useMemo` 不重算就会一直显示回退名「第 N 节」。规则：memo 依赖加入 `panelOpen`，并在章节 `load` 事件里 bump 一个刷新计数。
316. **撤销历史与当前数据可能分叉。** 编辑器保存导致 `clearDraftsForFile` 后，旧快照再撤销会把已入库的草稿恢复回来。当前接受这一行为（历史只保证「最近 N 步可回退」），后续若做跨档历史，需要在应用快照前做一次合并校验。




## 47. 编辑档渲染阅读标注（2026-11-11 W41 追加）

317. **contentEditable 里的只读标注不要插 DOM。** 向块内插高亮 span 会让 `innerHTML` 带着标记走保存通道，把高亮写进章节 XHTML。规则：用 CSS Custom Highlight API（`CSS.highlights` + `::highlight()`），Range 只指向文本节点，编辑时 Range 自动收缩、删除文字后高亮自然消失，且不会进入任何序列化结果。
318. **Highlight API 的 Range 必须跟着 DOM 重建。** 块用 `dangerouslySetInnerHTML` 渲染，翻译 / 应用改动 / 撤销导致 `blocks` 变化时文本节点被替换，旧 Range 失效。规则：渲染 effect 依赖 `blocks`，并在 `requestAnimationFrame` 里重新构建；颜色不同按色值分组注册（`sf-ann-<hex>`），笔记单独用 `sf-ann-note` 画下划线。
319. **编辑器块里的图片是占位 span。** `［图片］` / `［图形］` 以 `.blk-img` 文本节点存在，直接按 `textContent` 算字符位置会让图片之后的标注整体偏移。规则：`TreeWalker` 收集字符时跳过 `.blk-img` 子节点。
320. **源码视图的改动不进「应用改动」。** 源码 textarea 的编辑走 dirty 通道（保存时提交），而「应用改动」只提交富文本的 `blockEdits`，源码有改动时按钮不可用。规则：验收「删字后标注消失」看内存预览即可；要落盘必须点「保存」，不能把「未写盘」误判为失败。
321. **测试清理优先「还原内容」，不要递归删目录。** 递归删除工作副本会被安全策略拒绝（且可能误删用户未保存的编辑成果）。规则：壳数据写回空壳、删除本轮生成的 `history.json`、更新 manifest；工作副本若未真正写盘（只改内存），无需动它。删除单个测试文件也不要和应用目录混在同一条命令里。




## 48. 编辑层文件级操作（2026-11-11 W42 追加）

322. **`tauri build --debug` 本机链接失败，验证用 release 开调试端口。** MSVC 同时拉入 `msvcprt.lib` 与 `libcpmt.lib`，报 `LNK2038/LNK2005`。规则：CDP 验证统一用 `npm run tauri build`（release）+ `tauri.conf.json → app.windows[0].additionalBrowserArgs: "--remote-debugging-port=9222"`；交付前删掉该字段重建，并用字节搜索确认二进制不含 `remote-debugging-port`。
323. **移动文件要改两类链接。** `rename_file` 原本只改写「指向被移动文件的链接」，跨目录后文件**自身**的 CSS/图片相对链接会失效（`../style/main.css` 从 `EPUB/text/` 搬到 `EPUB/` 仍是 `../style/main.css`，解析到根级）。规则：目录变化时先 `rebase_links(raw, old_dir, new_dir)` 重算自身 `href/src`，再执行引用改写。
324. **`opf_items` 返回的 href 已经解析成包内路径。** 新建章节模板取 CSS 时若再调 `resolve_href(opf_dir, href)` 会得到 `EPUB/EPUB/style/main.css`。规则：直接用返回的 href 做 `rel_from_dir`，不要再拼一次 opf 目录。
325. **删除文件的顺序不能反。** 先删目录项并 `write_toc` 时 manifest 还必须完整（`read_toc` 靠它找 nav/ncx）；之后才能删 manifest `<item>` 与按 id 删 spine `<itemref>`；最后删磁盘文件并清理其他文本里的 `href/src`。规则：目录 → manifest/spine → 文件 → 其余链接。
326. **文件级操作只改工作副本，revision 来自随后的保存。** 新建/删除/移动不会自动生成快照；验收「每次操作有 revision」要按「操作 + 保存」看 `edit_list_revisions` 递增，不要把「点击后无 revision」判为失败。
327. **测试书清理要连工作副本一起还原。** 只删测试文件会留下改过的 OPF/nav/ncx。规则：测试前整书备份 → 测试后还原 → 删除 `edit/` 与 `revisions/`，让下次打开从母本重新解包。
328. **后台保活的进程必须带 `-Wait`。** `Start-Process <exe>` 不带 `-Wait` 时进程会随 PowerShell 会话结束被终止，表现为「启动即退出」，容易误判为应用崩溃。规则：`Start-Process <exe> -Wait` 放 `run_in_background` 后台。




## 49. 锻造译文工程与导出（2026-11-11 W43 追加）

329. **锻造保存不能再复用 `commit_forge`。** 它会把文本写回母本，EPUB 又没有 `source.txt`。规则：译文保存只走 `translation_save` → `译文/<语言>/`；注释单独走 `write_forge_state` 写 `forge.json`；母本只读。
330. **解包临时目录不要放在会被扫描的父级。** `epub_edit::unpack_epub` 会在解包目录的**父级**建 `revisions/`；直接解到 `译文/.tmp-<lang>` 会留下 `译文/revisions`。规则：解到 `译文/.build-<lang>/pkg`，清理 `.build-<lang>` 整棵树。
331. **导出复用母本包，不要重建资源。** 译文工程每章是从母本 XHTML 替换块生成的完整文件，导出时只要解包母本、按 `sourceHref` 覆盖同名章节再 `pack_epub`，图片/字体/CSS 全部天然保留。
332. **翻译块必须 XML 转义。** `BlockEdit.inner` 是直接写进 XHTML 的片段，纯文本里的 `& < >` 不转义会破坏文档。规则：写入前 `& → &amp;`、`< → &lt;`、`> → &gt;`；如需保留译文内联样式，后续再引入白名单解析。
333. **长书未译清单必须限量渲染。** 74,327 段的清单全量渲染会让面板卡死。规则：只渲染前 100 章、每章前 20 段，其余显示 `+N`；计数仍用全量数据。
334. **Windows 删文件不区分大小写。** 同目录下 `scrollforge.exe` 与 `Scrollforge.exe` 被视作同一个文件；删除测试用的小写名会把正式包 `Scrollforge.exe` 一起删掉。规则：构建目录只保留一个正式名；先复制覆盖，再删临时名要确认没有大小写孪生。
335. **整书 payload 会很大。** 保存把整本章节段落传给 Rust 才能统计未译；本次 74k 段、`mapping.json` 约 1 MB 仍可接受。规则：维持 <2 MB 监控，超过就改成「只传有译文的块 + 后端按源章节统计未译」。




## 50. 锻造整章分屏与漂移标记（2026-11-12 W44 追加）

336. **双栏联动按段对齐，不能按滚动比例。** 原文与译文块高度不同（译文框更高），比例联动在长章节会持续累积偏差，「误差 ≤1 段」根本达不到。规则：给每段加 `data-block-index`，用「当前贴顶段序号 → 另一栏同序号块的偏移」定位；只在 `syncingRef + requestAnimationFrame` 窗口内忽略回声。
337. **触顶/触底要直接对齐端点。** 只按段对齐时，两栏内容总高不同，滚到底部会出现「一侧最后一段贴顶、另一侧贴不了」的多段差。规则：`scrollTop<=1` 时另一栏回 0；`scrollTop+clientHeight>=scrollHeight-2` 时另一栏滚到底；中间才按段对齐。
338. **短章节源栏不溢出时「顶段恒为 0」是正常现象。** 5 段的章节源文不足一屏，`scrollHeight===clientHeight`，无论怎么设置 `scrollTop` 都回 0，容易被误判为联动失效。规则：验收必须挑长章节（本次选 128 段落），并在报告里写清章节长度；短章节只验「高亮段一致」。
339. **定位 effect 不要依赖 `paragraphIndex`。** 点进 textarea 时若顺手 `setParagraphIndex`，effect 会把两栏重新滚到该段顶部，形成输入时的跳动。规则：effect 依赖 `[chapterView, chapterIndex, locateToken]`，段落列表/未译清单/「下一处未译」都显式 `locateToken+1`；`paragraphIndex` 只用于高亮与状态。
340. **漂移检测复用草稿里的 `source` 镜像，不另存快照。** `forge-draft.json` 每个 block 本来就有 `source`/`target`；把 `source` 与当前母本段落逐段比对即可判断母本是否被编辑过。规则：按当前章建 `Map<index, source>` 再比，避免 O(n²)；用户删掉草稿后首次进入会按当前母本重建，漂移归零属预期。
341. **CDP 里量「贴顶段」要用 rect 换算，不能用 `offsetTop`。** 滚动容器有 padding，块的 `offsetParent` 也不一定是滚动容器。规则：`el.getBoundingClientRect().top - pane.getBoundingClientRect().top + pane.scrollTop` 得到块相对滚动原点的偏移，再与 `pane.scrollTop - 4` 比较取第一个贴顶块。




## 51. 漂移段重新对齐（2026-11-12 W45 追加）

342. **重新对齐不能只改 `forge-draft.json`。** 译文实际存在两处：草稿块的 `target` 与 `forge.json` 的 `edits`（译文工程再由保存生成）。只改草稿会让重启后 `forge.json` 按旧下标读回，译文错位甚至重新漂移。规则：应用对齐时先写草稿镜像，再走与普通保存完全相同的 `saveDraft`（`translation_save` + `write_forge_state` + `setEdits`），母本仍然不参与。
343. **对齐要复用旧 `source` 镜像，不要重新解析母本。** `forge-draft.json` 的每个块已有建草稿时的原文，直接与当前 `analysis.chapters[].paragraphs` 做 Myers 比对，就能区分同段、位移、改写、新增、删除；解析母本反而拿不到「旧结构」。规则：Myers 只在完全相等的段上对齐，差异块再按位置顺序配对算相似度。
344. **相似度要按文本长度选算法。** 中文长段用 Levenshtein 是 O(n²)（几百段就会卡）；全用 bigram 对十字以内的短句又不敏感（「他说」→「她说」会被判成完全不同的段）。规则：≤300 字用 Levenshtein，超过用字符二元组 Dice，阈值 0.4；低于阈值宁可拆成「删除 + 新增」，把旧译文放孤儿区，也不要硬套到语义已变的新段。
345. **改写段落的旧译文必须显式标出来。** 对齐后 `source` 已更新，W44 的「漂移」检测会归零；如果不再加标记，用户会误以为译文仍对应当前原文。规则：`modified` 且原有译文的块写 `stale: true`，UI 显示「需校」；`setForgeTarget` 写入新译文时自动清除，重新翻译即视为已对校。
346. **孤儿译文不要写回 `forge.json`。** `forge.json` 的键是「当前章:当前段」，把已删除段落的译文留在里面，下次保存会把它当成现有段落写入译文工程。规则：被删除段落的译文/注释只存 `forge-draft.json → orphans`（用户可选保留/丢弃），`forge.json` 只保留新结构下仍存在的键；面板头用「孤儿译文 N」徽标提示可查。
347. **重新对齐后要重排 `block.index`。** 对齐用的是数组位置，`editKey` 用的是块序号；插入/删除段落时若只改数组不改 `index`，译文会写到错误的键上。规则：`finalizeRealign` 统一按新下标从 0 重建 `blocks[].index`，测试造数时也先重排再写 `forge.json`。
348. **长书对齐入口要按全书算漂移。** 只在当前章算「漂移 N 段」时，其他章的漂移会让按钮不出现。规则：`driftByChapter` 一次遍历全书（`Map<chapterIndex, Set<paragraphIndex>>`），面板头徽标仍显示当前章，入口按钮显示全书合计。

## 52. 锻造层逐段分屏重构（2026-11-14 W46 追加）

349. **左右对齐不要靠滚动联动，靠「同一行」。** 比例换算和「找贴顶段再对齐另一栏」在长章节必然累积误差（W44 滚到底还差 1 段）。规则：原文与译文放进同一个 `grid` 行的两列，`align-items: stretch`，行高取两侧较高者，空行自然参与；滚动只有一套，不需要 `syncingRef` 防回声。
350. **受控 textarea 自动增高要防回流死循环。** 高度写成 `scrollHeight` 会反过来改变容器布局；`ResizeObserver` 若同时响应高度，就会「改高→触发→再改高」。规则：观察容器只比较 `clientWidth`，宽度没变直接 return；输入时只 `autosize` 当前元素，切章/批量翻译后再 `fitRows` 全量重算。
351. **同一 tick 内连续点选会读到旧选区。** 用 `setSelection(new Set(selection))` 时，CDP 一次注入两次点击（或用户极快连点）第二次仍拿到渲染前的 `selection`，结果只剩一个选中。规则：加选/减选一律用函数式更新 `setSelection(prev => …)`；连选（Shift）本来就用 `anchorRef` 不受影响。
352. **章节级进度不要每次输入扫全书。** `analysis.chapters[].paragraphs.filter(...)` 对 435 章 / 74k 段在每次按键都跑一遍，输入会发涩。规则：总段数按 `analysis` 缓存一次，已译数遍历草稿键（`chapter:paragraph`）累加，并对越界键做范围校验（重新对齐后可能有旧键）。
353. **顶栏按钮要复用编辑层的上报模式，不要复制一份顶栏。** 锻造层的章节抽屉按钮与编辑层文件树按钮在同一位置；两个面板各画一条顶栏迟早错位。规则：面板通过 `onToolbar(state)` 把 `{ treeOpen, toggleTree }` 交给 `Reader`，`Reader` 用 ref + tick 渲染同一个 `folder` 按钮，`Esc` 也由 `Reader` 先查 `treeOpen`。
354. **注释挪进段落时保留「按需显示」。** 每段常驻一个注释框会让 186 段的章节视觉过密。规则：有注释或该段是当前段时显示输入框，否则只显示「＋ 注释」按钮；点按钮即把该段设为当前段。

## 53. 查漏补缺与仓库整理（2026-11-14 W48 追加）

355. **翻译记忆键必须带目标语言。** `tmKey` 原来固定拼 `${from}>zh:`、写入时也固定 `to:'zh'`，目标语言切到英/日/韩仍会命中中文旧译文。规则：`tmKey(from, source, to='zh')`，默认参数保证历史中文键格式不变；新增非中文目标一律用带目标语言的键，回灌记忆时传 `prefs.translateTarget`。
356. **批量写回显式传章号，不要闭包读当前章。** `translateMany` / `polishMany` 若直接读渲染闭包里的 `chapterIndex` / `paragraphs`，覆盖确认弹层期间切章就会把译文写到新章。规则：批处理函数第一参数收 `chapterNo`，段落、草稿键、回填全部按该章取；弹层把 `ask.chapterNo` 原样传回。
357. **译文工程章节 href 必须校验绝对路径。** 只挡 `..` 不够：`PathBuf::join("C:/…")` 在 Windows 会直接替换基路径，脱离解包目录。规则：统一 `normalize_href`，拒绝空串、`..` 与盘符冒号后再 join；保存与导出共用同一函数。
358. **超长路径删除要用 `\\?\` 前缀。** 参考安装包里的 Android 构建产物路径超过 260 字符，普通 `Remove-Item -Recurse` 报「未能找到路径 AudioProcessingState.dex 的一部分」。规则：先 `Remove-Item -LiteralPath '\\?\D:\…' -Recurse -Force`；仍失败时用 `robocopy 空目录 目标 /MIR` 清空再删。
359. **PowerShell 不支持 heredoc。** `git commit -m "$(cat <<'EOF' …)"` 在 PowerShell 会解析成多个重定向并报错。规则：多行提交信息先 `Write` 到 `.git-commit-msg.txt`，`git commit -F .git-commit-msg.txt`，提交后删除该文件。
